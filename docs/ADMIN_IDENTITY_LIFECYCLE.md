# 后台身份生命周期契约

版本：1.0 开发草稿；日期：2026-10-19。关联 [API 1.5](API_SPEC.md)、[M00](modules/M00_ADMIN_ACCESS.md)、[M15](modules/M15_SECURITY_DEPLOYMENT.md)及 [OpenAPI](../packages/contracts/openapi.yaml)。本文件补充已有身份需求的工程流程；首店主/MFA/本人会话服务与迁移已部分落地，见 [身份实现说明](R1_IDENTITY_IMPLEMENTATION.md)；员工邀请、找回、通知和离线恢复等仍待实现，R1 未完成。

## 凭据与信任边界

| 凭据 | 获得条件 | 可以执行 |
|---|---|---|
| X-Bootstrap-Token | 运维在目标实例的秘密管理系统预置；仅首次部署开启 | 创建该实例第一个店主，并获得 MFA 登记能力 |
| invitationToken | 当前有 staff.manage 的人员邀请；通过受控通知交付 | 为邀请绑定的员工设密；不能自行选邮箱、角色或跳过 MFA |
| ez_admin_challenge | 密码正确且已有 MFA | 结合匹配 challengeId 验证已登记因子；不能登记新因子或访问后台业务 |
| ez_admin_setup | 首次开通、强制 MFA 登录/邀请、或本人重新认证 | 结合匹配 challengeId 创建并确认待登记因子；不能访问业务 API |
| ez_admin_session | 满足账号状态及 MFA 策略后签发 | 每次请求按实时权限授权；受保护写请求还须 CSRF token |

两种挑战 cookie 均为 HttpOnly、Secure、SameSite=Strict，Path=/api/v1/admin/auth/mfa；正式会话 cookie 为 HttpOnly、Secure、SameSite=Lax，Path=/api/v1/admin。所有 cookie 均为 host-only。登记、登录和邀请入口检查精确 Origin；缺 Origin 的自动化部署调用只经另行认证的受控部署通道进入，不能把“缺 Origin”作为公开绕过分支。各凭据绑定目标实例、员工、用途、浏览器尝试、有效期和消费状态，不互相替代。挑战超时不可续期；重新认证才能重新签发。登记重开不延长原挑战有效期。

挑战与邀请有效期、重试上限及限流默认值已登记在 [identity-v1](IDENTITY_SECURITY_POLICY.md)，必须在响应/投递中明示；账号/IP 和挑战失败计数已持久化；邀请发送与过期清理仍待实现。后台密码/会话既有数值继续以 DEVELOPMENT_SPEC 第 7 节为准。禁止将凭据放 URL 查询串、普通日志、审计差异、错误或统计事件。邀请邮件的凭据交付采用不会进入服务端访问日志的页面片段并由页面 POST；页面 noindex、no-store、不加载第三方脚本，使用 Referrer-Policy:no-referrer，读取后清理地址栏。

## 首个店主与邀请

部署方先确认目标实例并启用短时 setup 窗口，安全注入高熵 bootstrap secret；不提供出厂默认密码或公开领取秘密的接口。bootstrap 同时验证部署凭据、窗口及数据库中“从未建立首个店主”的锁定状态。在同一事务内建立唯一首店主、记录 MFA 必需、消费 bootstrap、关闭 setup 入口并写审计；并发请求只允许一个成功。不能仅检查 active 用户数量，也不能因停用或删错账号重新开放。提交后的请求返回统一关闭/已初始化结果，不重复创建或重发秘密。

首店主此时已有身份但没有正式会话，必须完成 TOTP。登记挑战丢失后以已设密码重新登录，获得新的登记挑战；不能重新使用 bootstrap。部署失败在事务提交前可按受控操作恢复，提交后不能清空开通标记重试。

邀请保存 token 摘要、目标邮箱/员工、邀请者、服务端分配角色、有效期、版本和状态；明文仅交由通知服务短时投递，不作为管理员创建响应返回。接受时原子消费有效邀请并设置 Argon2id 密码摘要，激活身份；角色和 MFA 需求按当前服务端策略计算。已撤销、过期、已使用、目标员工停用的邀请不创建会话；错误不泄露额外账号信息。邀请人停用或失去相关授权后尚未接受的邀请须重新审批/撤销，不能继续授予失效权限。角色变更、重发及撤销须使旧 token 失效，重发不产生并行有效 token。重新投递/撤销操作已在 API 1.6 登记 staff.manage、邀请版本及幂等边界，不能通过修改邀请数据表绕过审计；HTTP/通知实现仍待完成。

## MFA 首次登记与替换

1. 密码正确、员工有效且必须 MFA：已登记则签发 verify_mfa 挑战；未登记则签发 enroll_mfa 挑战。两种路径均无正式会话；新挑战使同一认证尝试的旧能力失效，并清理另一种挑战 cookie。
2. 已有会话的用户主动登记或替换时调用 enrollment-authorizations，重新验证当前密码；已有 MFA 时还必须验证当前 TOTP 或一个未用恢复码。当前因子存在与否来自数据库，不能由客户端省略字段改变。使用恢复码时按原子单次消费规则处理。
3. enrollments 只接受受限 setup cookie 和匹配挑战，生成待确认 TOTP。返回 enrollmentId、到期时间及 provisioning secret/URI，仅在此专用 no-store 响应中展示。服务端加密保存 TOTP secret，以便后续校验；恢复码保存哈希。不能把 TOTP secret 和恢复码都作同一种不可逆存储。
4. 同一挑战再次 start 会替换待登记因子并使旧 enrollmentId 无效；旧的正式因子继续工作。重开次数受限，不因为重开延长授权窗口。确认只接受待登记因子的六位 TOTP，不接受恢复码作为“验证新验证器”的证据。
5. confirm 在事务中检查挑战、待登记因子、用户仍有效、授权依据和版本，消费挑战并激活新因子；替换原因子及全部旧恢复码，撤销旧会话，写审计并创建轮换的新会话。只有成功响应展示一次新恢复码。并发确认只允许一个成功；重放返回冲突，不返回第二份明文恢复码。
6. 成功响应丢失时已生成的恢复码不可再读。用户可用新验证器重新登录，再次完成受控因子替换以获得新的一组恢复码；不通过后台详情或重试 confirm 取回旧明文。待登记过期/放弃时只清理待登记数据，不停用原因子。

只有用户主动确认登记的专用响应允许显示 provisioning secret 或恢复码；员工、会话、审计、导出及通用错误均不允许返回。前端不得持久化至 localStorage 或通过遥测收集。

## 恢复与会话管理

有恢复码时，密码登录获得 verify_mfa 挑战，再用未使用恢复码完成既有 verify；恢复码原子消费且不可重放。登录后重新绑定仍需当前密码及当前 TOTP/另一个未使用恢复码，不能让旧登录挑战变成登记能力。

验证器与恢复码均遗失时，禁止通过邮箱密码重设、staff.manage 或普通客服接口关闭 MFA。需要商家确认身份及目标实例、授权运维执行受审计的离线恢复，撤销该员工会话/邀请/挑战和旧因子，发放只可登记的短时能力，并通知账户持有人。身份核验与执行责任已见 [恢复流程](ADMIN_RECOVERY_RUNBOOK.md)，离线恢复命令尚待实现；没有此工具时不能宣称找回流程完成。

本人会话列表只查当前员工；revoke own 必须校验资源归属，跨员工与不存在 ID 均返回 404。staff.read 可按既有权限读取员工活跃会话，staff.manage 可使用既有接口全部撤销。列表 id 是管理标识，不是 cookie 令牌。撤销当前会话可成功送达响应，随后请求立即无效；对已属于本人且已撤销的会话重复撤销不恢复它。权限变更/员工停用/重设密码/因子替换均不能依赖浏览器主动登出。

## 数据、审计及交付门槛

新增持久对象：AdminBootstrapState、AdminInvitation、AdminAuthChallenge、AdminMfaEnrollment；扩展 AdminSession 的可撤销管理 ID、用途、最后活动、空闲/绝对到期及撤销信息。挑战记录 token 摘要、用途、员工、浏览器绑定、到期、消费、失败次数、因子/权限版本；因子和邀请变更使旧授权失效。正式会话与受限挑战分别存储或强类型区分，不能只靠前端页面限制。

审计覆盖 bootstrap、邀请签发/接受/撤销、登记授权、待因子确认/失效、恢复码使用、因子替换、会话撤销、失败和离线恢复；只存 actor/action/object/result/correlation ID 与脱敏原因，不记录密码、token、secret、URI 或恢复码。本批只补充审计动作，不新增跨模块 outbox 事件；将来引入业务事件必须另补事件 schema 及消费者幂等。

上线前必须实际执行：并发 bootstrap、邀请重放/篡改/撤销、挑战跨浏览器/跨用户/跨用途/超时、MFA code 重放、并发 confirm、因子替换中断、通知失败、会话越权枚举、当前会话撤销、角色变化以及密码重设不能绕过 MFA。静态 JSON Schema 用例只覆盖字段与声明边界，无法证明这些事务和授权行为。

新增端点和联合响应仍为同一 API 主版本的未冻结草稿；前端必须按 nextAction 分支并重新生成类型。身份初始迁移已建立 BootstrapState、AdminChallenge、MfaFactor 等实际模型、首店主和挑战/会话唯一约束；待登记字段合并保存在 AdminChallenge。AdminInvitation、通知和到期清理仍待实现。邀请重发/撤销、市场审核及具体安全默认值已登记；离线恢复工具、数据库/通知/限流实现和 M15 运维契约仍须继续交付。
