# 身份安全参数 identity-v1

日期：2026-10-19。工程默认参数以 [security-policy.ts](../../packages/config/src/security-policy.ts) 为机器来源，调整须记录版本、影响、测试和已有挑战/会话的处置；不能由普通店铺配置覆盖。

| 参数 | 默认值 | 行为 |
|---|---|---|
| 已登记 MFA 的登录挑战 | 5 分钟 | 到期即拒绝；新认证签发新挑战 |
| 登记授权及待登记因子 | 最长 10 分钟 | 因子截止时间不晚于原授权截止；重开不续期 |
| 邀请 | 24 小时 | 到期不可接受；可由有权员工显式重发新版本 |
| 邀请重发 | 最小间隔 60 秒，同一邀请每小时最多发送 5 次 | 首次发送计入额度；重发不重置小时窗口；同时按员工/实例/IP 限流，禁止重建邀请绕过额度 |
| 挑战验证失败 | 同挑战最多 5 次 | 达限使挑战失效；仍受账号/IP 限流约束 |
| 身份写请求 IP 限流 | 同 IP 每 15 分钟最多 60 次 | 使用直连对端地址；代理部署需经审核配置可信代理，不能直接信任转发头 |
| 账号失败及冷却 | 15 分钟内 5 次失败，冷却 15 分钟 | 延续开发执行规格；不能换挑战绕过 |
| bootstrap 窗口 | 明确开启后最长 15 分钟 | 首店主建立后永久关闭；超时只可授权运维重新开启未初始化实例 |
| 后台会话 | 空闲 30 分钟，绝对 12 小时 | 活动只滑动空闲截止，不延长绝对截止 |
| 密码重设 | 30 分钟，一次性 | 成功后撤销旧会话，保留 MFA 要求 |
| 重设申请冷却 | 同一邮箱 60 秒，每小时最多 5 次 | 冷却或超限时仍返回统一接受响应但不发信，避免通过响应判断账号是否存在 |
| 随机凭据 | 32 字节密码学随机数 | base64url 传输；服务端只保留 token 摘要，通知投递短时秘密须加密 |
| 恢复码 | 每组 10 个，每个 20 字符 | 使用密码学随机源、至少 32 字符的无歧义字母表；至少 100 bit 随机性；哈希保存，一次性消费 |
| 过期秘密清理 | 每 15 分钟扫描 | 先按到期时间拒绝请求，清理任务延迟不延长有效期 |

## 实例级开关与凭据形式（2026-11-21）

| 项 | 默认 | 说明 |
|---|---|---|
| 后台强制 MFA | 开启 | 店主与 `admin` 角色无条件要求二次验证，`AdminUser.mfaRequired` 只能加码不能减码 |
| `ADMIN_REQUIRE_MFA` | `true` | 只有实例显式写 `false` 才关闭：关闭后密码通过即发会话（`mfaVerified=false`）。适用于私有部署、店主只要「账号 + 密码」的自用场景 |
| 账号名格式 | 不要求邮箱 | 登录标识沿用 `email` 字段名，但只要求 1–254 字符，可用 `admin`、`zhangsan` 这类自由账号名；直建账号与邮件邀请都接受同一种写法 |
| 建号方式 | 直建优先 | `POST /admin/users` 带 `password` 即直接建为可登录账号（不依赖 SMTP）；省略则沿用邮件邀请，需要实例已配置发信 |
| 一次性初始密码 | 强制改密 | 直建账号置 `AdminUser.mustChangePassword=true`：除会话查询、登出、改密外，所有后台接口返回 403 `PASSWORD_CHANGE_REQUIRED`；改密后清除标记并吊销其他设备上的会话，初始密码随即作废 |
| 设置密码最小长度 | 8 | 创建账号、接受邀请、重设密码、自助改密统一 8 位 |
| 登录密码校验 | 不校验长度 | 登录只比对哈希。若策略调整后登录仍卡长度，历史短口令会永远登不进去（校验发生在比对之前会直接 422） |

关闭 `ADMIN_REQUIRE_MFA` 的后果必须写进交付说明：口令成为唯一屏障；未配置 SMTP 时忘记密码无法自助找回，只能由运维改库。市场合规审核仍要求 owner 角色，但关闭后不再要求已验证的二次因子。


恢复码生成、TOTP/时间步防重放、Argon2id、账号/IP 持久限流和身份数据库已实现并通过真实集成测试。邀请与密码重设的持久生命周期、一次性凭据、加密通知任务和 Worker 已实现；通知仍无真实 SMTP 账户验收，清理 Worker 目前随通知 Worker 每轮执行，市场审核与店铺配置的持久实现和受控配置管理仍未完成。当前代码默认值不能被当作已有生产部署。详见 [身份实现说明](R1_IDENTITY_IMPLEMENTATION.md)。

过期 invitation/challenge 保留无秘密的审计关联；待 TOTP 秘密在过期/撤销时清除；历史审计保留期沿用客户确认策略。会话管理记录与审计可保留，但不继续保留可用凭据。正式环境须用数据库时间/可信 UTC，异常或不可解析时间直接拒绝，不能把清理作为有效性判断。
