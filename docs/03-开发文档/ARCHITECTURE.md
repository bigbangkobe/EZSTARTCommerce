# EZSTARTCommerce 技术架构（AWS 独立部署版）

> 版本：v2.0　日期：2026-11-20　状态：评审稿
> 适用范围：一客户一实例、独立数据库、独立域名、配置化前台的烟草/零售电商交付。
> 关联：[产品与技术总体蓝图](../01-产品文档/PRODUCT_TECHNICAL_BLUEPRINT.md) · [开发执行规格](DEVELOPMENT_SPEC.md) · [私有部署模式](../05-部署运维文档/PRIVATE_DEPLOYMENT.md) · [交付工具链规范](../01-产品文档/DELIVERY_TOOLCHAIN_SPEC.md)

## 0. 结论摘要

| 决策 | 结论 | 理由 |
|---|---|---|
| 应用架构 | **模块化单体 + 独立 Worker**，不拆微服务 | 单客户流量有限，交易一致性优先；拆分会提前引入分布式复杂度 |
| 部署架构 | **一客户一 AWS 实例 + Docker Compose + Caddy** | 与“独立部署、数据隔离、客户拥有系统”的产品定位一致 |
| 数据库 | 首期 **同机 PostgreSQL 18 容器**，生产可升级 RDS | 首期成本最低；有更高 SLA 要求时再换托管数据库 |
| 媒体存储 | 默认本地目录，生产建议 **每实例独立 S3 Bucket** | 媒体与数据库分离；签名 URL；实例间隔离 |
| 前台定制 | **Instance Manifest + ThemeConfig 配置驱动** | A 类客户不写前端代码；B/C 类才进入定制开发 |
| 交付方式 | **标准部署包 + 初始化 CLI + 批量升级** | 把“项目交付”变成“可重复的产品交付” |
| 烟草合规 | **上线阻断项，不是事后补丁** | 牌照、年龄核验、健康警示、广告限制、支付通道必须先确认 |

**一句话：** 用一套可重复部署的模块化单体，承载“配置化前台 + 独立实例 + 交易底座”，首期以 AWS Lightsail/EC2 + Docker Compose 跑通单客户上线，再按规模演进到 ECR/RDS/CloudWatch 的托管形态。

## 1. 架构目标与约束

| 目标 | 约束 | 对架构的影响 |
|---|---|---|
| 一套核心服务多个客户 | 不做共享多租户 SaaS | 每客户独立实例、独立数据库、独立密钥与域名 |
| 交易金额与状态可信 | 浏览器不可信 | 价格、折扣、运费、税费、库存全部服务端重算 |
| 换客户尽量不写前端 | A 类配置级为默认 | 品牌、主题、首页区块、导航、文案由配置驱动 |
| 交付可复制 | 不能每家从零部署 | 实例配置源 + 标准模板 + 初始化/升级 CLI |
| 客户数据隔离 | 不集中客户业务数据 | 无跨店控制面；备份、日志、媒体均按实例隔离 |
| AWS 可运维 | 小团队、低运维成本 | 首期单机 Docker Compose；监控/备份/告警优先于过度架构 |
| 烟草行业可上线 | 当地法规与支付通道限制 | 合规能力作为上线门禁，不能靠技术绕过 |

### 1.1 非目标

- 不做商家自助注册、自动开租户的 SaaS 控制台。
- 不做跨客户订单/顾客/销售数据汇总。
- 不把烟草行业规则写死进交易核心；行业差异放在配置、策略与适配器。
- 首期不做多区域容灾、双活、微服务拆分。

## 2. 总体架构

### 2.1 目标态拓扑

```text
                         Internet
                            |
                    Route 53 (DNS)
                            |
                    Caddy 80/443 (TLS)
                     /             \
                    /               \
        storefront:3002          admin:3000
        (客户前台)               (商家后台)
                    \               /
                     \             /
                      api:3001 (NestJS)
                       /      |      \
                      /       |       \
          PostgreSQL 18    Worker     S3 Bucket
          (实例独立库)    (outbox/job) (实例独立媒体)
                                 |
                        支付/邮件/物流适配器
                                 |
                         第三方服务（客户签约）
```

### 2.2 现状与目标态差异

| 能力 | 现状 | 目标态 | 优先级 |
|---|---|---|---|
| 应用运行 | Docker Compose 单机 | 保持单机，增加标准化发布 | P0 |
| 镜像构建 | 服务器上 `docker compose build` | CI 构建并推送 ECR，服务器只拉取 | P1 |
| 数据库 | 同机 PostgreSQL 容器 | 首期保留；有 SLA 要求时换 RDS | P1 |
| 媒体 | 默认本地目录，支持 S3 驱动 | 生产启用每实例 S3 Bucket | P0 |
| 监控 | 健康检查 + Docker 日志 | CloudWatch Agent + 告警 + 外部 uptime | P0 |
| 备份 | 部署前 `pg_dump` + Lightsail 快照 | 定时备份 + 恢复演练 + 备份年龄告警 | P0 |
| 密钥 | `.env` 本地生成，chmod 600 | 首期可用；后续接 SSM/Secrets Manager | P1 |
| CI/CD | GitHub Actions 校验 | 增加镜像构建/推送/部署流水线 | P1 |

## 3. 应用架构

### 3.1 应用清单

| 应用 | 技术 | 端口 | 职责 | 对外暴露 |
|---|---|---|---|---|
| `apps/api` | NestJS 模块化单体 | 3001 | 交易、商品、订单、支付、库存、权限、内容、报表 | 仅经 Caddy 反代 `/api/*` |
| `apps/admin` | Next.js | 3000 | 商家后台：商品、订单、主题、内容、报表 | `admin.<domain>` |
| `apps/storefront-<merchant>` | Next.js | 3002 | 客户品牌前台：首页、商品、购物车、结账、会员 | `<domain>` |
| `apps/worker` | Node.js | 无 | 通知、定时任务、outbox/job 消费 | 不暴露 |
| `caddy` | Caddy 2 | 80/443 | TLS、反向代理、域名路由 | 唯一公网入口 |
| `postgres` | PostgreSQL 18 | 5432 | 交易与配置主数据 | 仅容器内网 |

### 3.2 代码分层

```text
apps/
  api/                 HTTP/用例编排、鉴权、事务边界
  admin/               后台页面与交互
  storefront-*/        客户前台，只读 API + 加购/结账
  worker/              异步任务进程
packages/
  domain/              纯业务规则：金额、状态机、库存、主题、Manifest
  database/            Prisma schema、迁移、客户端
  contracts/           OpenAPI 契约与生成类型
  config/              环境与实例配置读取
```

**边界纪律：**

- `packages/domain` 不碰数据库、网络、React；只做纯规则与闭集校验。
- API 是唯一能修改交易数据的地方；前台不得自行计算价格、折扣、运费。
- 模块之间通过服务接口/事务协作，不跨域直接改表。
- 契约以 `packages/contracts/openapi.yaml` 为准，前后端类型由契约生成/校验。

### 3.3 模块边界

| 域 | 职责 | 关键不变量 |
|---|---|---|
| Identity & Admin | 管理员、角色、权限、审计 | 敏感操作必须服务端授权并留痕 |
| Store Configuration | 品牌、语言、市场、功能开关 | 配置按实例隔离 |
| Catalog | 商品、规格、分类、品牌、搜索 | 可售状态与价格由服务端裁定 |
| Content / Merchandising | 页面、FAQ、公告、文章、主题区块 | 发布快照不可变，未发布不对外 |
| Commerce | 购物车、结账、订单 | 订单状态机单向流转 |
| Payments & Reconciliation | 支付适配器、回调、退款、对账 | 幂等、验签、未知状态不误判 |
| Fulfillment | 配送区域、运费、履约 | 运费服务端计算 |
| Customer / Membership | 顾客、会员、OTP、隐私请求 | PII 最小化、可导出/删除 |
| Promotions | 优惠券、规则、核销 | 优惠不可叠加超限 |
| Inventory | 库存、预留、变动账目 | 预占—核销—释放，绝不超卖 |
| Communications | 通知模板、任务、发送状态 | 交易通知与营销通知分离 |
| Analytics / Import | 报表、漏斗、批量导入 | 指标口径固定、可追溯 |
| AfterSales | 售后、退款、退货质检 | 退款与案件状态分离，不直接改原始交易 |

## 4. 数据架构

### 4.1 数据库

- PostgreSQL 18，单实例单库；Prisma 7 管理 schema 与迁移。
- 迁移文件版本化，部署时 `prisma migrate deploy`；迁移只前进，不回滚数据。
- 金额使用最小货币单位整数 + ISO 币种；禁止浮点。
- 订单、支付、退款、运费、商品规格保留交易时快照，后续改商品不回写历史。
- 关键资金操作带 `Idempotency-Key`；webhook 验签 + 幂等 + 重放保护。
- 异步任务使用 PostgreSQL outbox/job 表，首期不引入 Redis。

### 4.2 核心数据域

| 数据域 | 代表表 | 说明 |
|---|---|---|
| 店铺配置 | `StoreConfig`、`MarketProfile` | 品牌、语言、市场、功能开关 |
| 主题配置 | `ThemeConfig`、`ThemeVersion` | 草稿 → 发布快照 → 版本历史 |
| 商品 | `Product`、`ProductVariant`、`Category`、`Collection` | 多语言、媒体、可售范围 |
| 交易 | `Order`、`OrderItem`、`Payment`、`Refund` | 状态分离、快照、幂等 |
| 库存 | `Inventory`、`InventoryMovement`、预留 | 预占/核销/释放 |
| 营销 | `Coupon`、`Promotion`、积分流水 | 规则与核销留痕 |
| 内容 | `ContentPage`、`MerchandisingLayout` | 发布快照、SEO/重定向 |
| 售后 | `AfterSalesCase`、`ReturnInspection` | 退款与履约分离 |
| 审计 | `AuditLog`、`AdminSession` | 敏感操作留痕 |

### 4.3 媒体存储

- 开发/单机默认本地目录 `MEDIA_LOCAL_ROOT`。
- 生产建议 `MEDIA_DRIVER=s3`，每实例独立 Bucket：
  - Block Public Access 全开；
  - 仅 API 角色可读写；
  - 上传走预签名 URL，下载走短效签名 URL；
  - 生命周期规则清理临时上传；
  - 跨实例不共享 Bucket、不共享密钥。
- 媒体文件不进数据库；数据库只存对象键与元数据。

## 5. 交易链路设计

### 5.1 下单与支付

```text
浏览商品 → 加购 → 结账报价（服务端算价）
  → 创建订单（幂等键）
  → 预占库存/优惠
  → 发起支付（适配器）
  → 支付回调验签 + 幂等
  → 成功：确认订单、核销库存、记支付台账
  → 失败/取消：释放预占
  → 未知：保持预占 + 告警，等待主动查询/人工处理
```

### 5.2 资金底线

- 服务端定价：价格、折扣、运费、税费、总额全部重算。
- 状态分离：订单、支付、履约、售后各自状态机，不合并猜测。
- 幂等：创建订单、支付、退款、库存调整、批量发券必须可重试。
- 对账：支付渠道结算文件只做匹配与差异分类，不自动改写事实。
- 资损监控：支付 `unknown` 不得当失败；不得释放库存/优惠占位。
- 退款：不得超过可退余额；退款与案件完成分离；退款通道原路优先。

### 5.3 库存

- 下单原子预占 → 支付明确成功核销 / 失败或取消释放。
- 结果未知保持预占并告警，绝不误释放。
- 退货只有在质检通过后才回到可售库存。

## 6. 配置化与多实例交付

### 6.1 配置链路

```text
instance.yaml
  → 结构校验 + 上线阻断检查
  → 生成实例目录（compose/Caddy/.env/部署脚本）
  → 数据库迁移
  → 初始化 StoreConfig / ThemeConfig / 管理员
  → 启动全家桶
  → 冒烟测试
```

### 6.2 前台配置

- `ThemeConfig` 单行：`draftConfig`、`publishedSnapshot`、`version`、`publishedAt`、`publishedBy`。
- `ThemeVersion` 保存历史快照，支持回滚。
- 区块类型是服务端闭集：`hero`、`about`、`product_grid`、`rich_text`、`faq`、`content_card`。
- 前台只读已发布快照；未发布/异常回退默认主题，配置不是单点故障。
- 颜色白名单 `#RRGGBB`，字体预设枚举，禁止任意 CSS/外部字体 URL。

### 6.3 多实例交付

- 一客户一目录：`deploy/merchants/<id>/`。
- 一实例一 `.env`，密钥本地生成，`chmod 600`，不进 Git。
- 升级分组：`pilot → canary → standard`；跨 major、降级、主题迁移未确认时阻断。
- 发布回滚：镜像 `:prev` 回滚；数据库迁移只前进，回滚前必须评估兼容性。

## 7. AWS 部署架构

### 7.1 当前已部署形态

| 项 | 值 |
|---|---|
| 云 | AWS Lightsail 东京 `ap-northeast-1` |
| 规格 | 2 vCPU / 4 GB / 100 GB |
| 系统 | Amazon Linux 2023 |
| 运行 | Docker Compose：Caddy + API + Admin + Storefront + Worker + PostgreSQL |
| 入口 | Caddy 80/443；DB/API/Worker 不暴露公网 |
| 备份 | 部署前 `pg_dump` 到 `/opt/ezstart-backups`，保留 14 份；Lightsail 每日快照 |

### 7.2 AWS 选型对比

| 方案 | 成本 | 运维复杂度 | 可用性 | 适用阶段 | 结论 |
|---|---|---|---|---|---|
| Lightsail + Docker Compose | 低 | 低 | 单机 | 首客户、试点、低流量 | **首期推荐** |
| EC2 + Docker Compose | 中 | 中 | 单机，可升配 | 需要更大规格/VPC 控制 | 备选 |
| ECS Fargate + RDS + ALB | 高 | 高 | 多可用区 | 多实例、高 SLA | 规模化后再上 |
| Elastic Beanstalk | 中 | 中 | 单机/多机 | 传统 Web 应用 | 不推荐：多容器/Next 支持不贴合 |

**推荐路线：**

1. **首期（当前客户）**：Lightsail/EC2 + Docker Compose，保持一客户一实例。
2. **稳定性补强**：镜像改由 CI 构建推 ECR；媒体切 S3；CloudWatch 告警；备份恢复演练。
3. **规模化**：实例数上升后，再评估 ECS/RDS；不改变“一客户一实例”的产品边界。

### 7.3 网络与域名

- Route 53 管理 `A` 记录：`<domain>`、`www.<domain>`、`admin.<domain>`。
- Caddy 自动申请/续期 Let's Encrypt 证书。
- 安全组/防火墙只开放 80/443；SSH 仅限固定管理 IP。
- PostgreSQL、API、Worker 不映射公网端口。
- 如客户要求数据留在香港，再评估 `ap-east-1`；否则东京 `ap-northeast-1` 作为首期区域。

### 7.4 环境划分

| 环境 | 用途 | 数据 | 域名 |
|---|---|---|---|
| dev | 本地开发 | 假数据/本地库 | localhost |
| staging | 上线前验收 | 脱敏/测试数据 | `staging.<domain>` |
| prod | 客户生产 | 真实数据 | `<domain>` |

staging 与 prod 必须是独立实例、独立数据库、独立密钥；不能共用 `.env`。

## 8. 安全架构

### 8.1 身份与权限

- 后台登录：会话 + RBAC + MFA（按现有身份模块能力）。
- 敏感操作：退款、权限变更、密钥配置、发布主题必须服务端授权并记审计。
- 前台会员：OTP 登录；不把后台会话与前台会话混用。
- CSRF、来源校验、CSP/安全头按现有 API/Next 配置执行。

### 8.2 密钥与配置

- `.env` 权限 600，不进 Git；模板只保留键名与空值。
- 生产建议接 AWS SSM Parameter Store / Secrets Manager；容器启动时注入，不落盘明文。
- 支付、SMTP、承运商密钥按实例独立；严禁跨客户复用。
- 轮换 `IDENTITY_ENCRYPTION_KEY` 会作废旧上传链接，需按运维窗口执行。

### 8.3 数据隔离

- 实例间数据库、媒体 Bucket、管理员账号、日志、备份完全隔离。
- 不做跨店查询接口；运维访问需授权、限时、留痕。
- 备份文件加密存储；恢复/迁移前确认实例 ID，防串库。

### 8.4 供应链与发布

- CI 执行契约校验、类型检查、单元/集成测试、后台构建、浏览器测试。
- 依赖锁定 `pnpm-lock.yaml`；安全更新走评审。
- 生产镜像使用固定版本标签；禁止服务器上直接改代码后部署。

## 9. 可观测性

### 9.1 健康检查

- `GET /api/v1/health/live`：进程存活。
- `GET /api/v1/health/ready`：数据库可用、服务就绪；未就绪返回 503。
- Docker healthcheck 已接入 compose；Caddy 只在 API 健康后接流量。

### 9.2 日志与指标

| 类型 | 内容 | 采集 |
|---|---|---|
| 应用日志 | JSON：启动、错误码、请求 ID、支付/退款事件 | Docker logs → CloudWatch Logs |
| 主机指标 | CPU、内存、磁盘、网络 | CloudWatch Agent |
| 容器指标 | 重启次数、健康状态 | CloudWatch Agent / Docker |
| 业务指标 | 订单量、支付成功率、退款失败、库存差异、死信任务 | 报表/定时 SQL + 告警 |
| 外部探测 | 首页、后台、健康接口、证书有效期 | 外部 uptime 服务 |

### 9.3 告警最低集

- API 5xx 比例或健康检查连续失败。
- 磁盘使用率 > 80%，内存持续 > 85%。
- 容器反复重启。
- 支付回调失败/验签失败突增。
- 订单长时间停留在待支付/待确认。
- 备份任务失败或备份文件超过 24h 未更新。
- TLS 证书剩余有效期 < 14 天。

## 10. 备份与恢复

| 项 | 首期方案 | 目标 |
|---|---|---|
| 数据库备份 | 每日 `pg_dump` + Lightsail 快照 | RPO ≤ 24h，RTO ≤ 2h（试点） |
| 媒体备份 | S3 版本化/跨区域复制（启用 S3 后） | 误删可恢复 |
| 配置备份 | `.env` 离线保管 + 实例配置入库（不含密钥） | 可重建实例 |
| 恢复演练 | 上线前至少 1 次全量恢复 | 有记录、有时长 |
| 升级回滚 | 镜像 `:prev` + 数据库迁移前备份 | 应用可回滚，数据不回滚 |

> RPO/RTO 为试点目标值，最终以客户 SLA 与预算确认；烟草客户若要求更高，升级 RDS 多可用区与跨区域备份。

## 11. 烟草商城专项架构

> 本节是**技术控制清单**，不替代当地法律意见。上线前必须由客户提供牌照、销售许可、广告合规与支付通道书面确认。

### 11.1 上线阻断项

| 项 | 要求 | 技术落点 |
|---|---|---|
| 销售资质 | 客户持有当地烟草零售/进口所需牌照 | 上线签字项；后台留存证照编号与有效期 |
| 年龄核验 | 禁止未成年人购买 | 前台年龄门 + 结账强校验 + 配送环节复核 |
| 健康警示 | 商品页/结算页/邮件按当地要求展示 | 主题/内容模板固定位，不可被客户配置关闭 |
| 广告限制 | 不向未成年人投放，不违反当地广告限制 | 营销模块限制 + 内容审核 + 不接违规广告像素 |
| 支付通道 | 收单机构允许烟草类目 | 支付适配器按客户签约通道启用；未获批不接 |
| 配送合规 | 配送环节年龄/签收要求 | 承运商回传 + 人工复核 |
| 数据留存 | 订单/年龄核验记录按法规留存 | 审计表 + 保留策略 |

### 11.2 建议新增的配置字段

以下字段属于**建议新增**，当前 Manifest 尚未实现，需在开发阶段补入并做校验：

```yaml
compliance:
  tobacco:
    enabled: true
    minimumAge: 18
    ageVerification: "checkout"   # checkout | delivery | both
    healthWarning: "香港法定健康警示文案"
    licenseRef: "客户牌照编号"
    salesLimitPerOrder: 0          # 0 表示不额外限制
```

### 11.3 明确不做

- 不做绕过年龄核验的“自声明即可”方案，除非法务书面确认该市场允许。
- 不做向未成年人定向营销、校园场景投放、伪装成非烟草商品的规避设计。
- 不存储支付卡数据；支付交给持牌收单机构。
- 不在未取得烟草类目许可的支付通道上强行上线。

## 12. 环境变量与配置

### 12.1 核心变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `DATABASE_URL` | 是 | PostgreSQL 连接串，仅容器内网 |
| `SITE_DOMAIN` | 是 | 客户主域名 |
| `INSTANCE_ID` | 是 | 实例唯一 ID，用于隔离与审计 |
| `IDENTITY_ENCRYPTION_KEY` | 是 | 32 字节 base64，身份/媒体签名派生 |
| `BOOTSTRAP_TOKEN` | 可选 | 首店初始化令牌，完成后移除 |
| `MEDIA_DRIVER` | 否 | `local` / `s3` |
| `S3_ENDPOINT` / `S3_BUCKET` / `S3_REGION` | S3 时必填 | 每实例独立 Bucket |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | S3 时必填 | 最小权限 IAM |
| `SMTP_*` | 通知时必填 | 交易邮件 |
| `CARRIER_WEBHOOK_SECRETS` | 可选 | 承运商回传签名 |

### 12.2 配置原则

- 实例配置源 `instance.yaml` 是客户配置的单一事实源；`.env` 只放密钥与运行参数。
- 客户配置与代码版本分离；升级不覆盖客户配置。
- 生产环境变量不进 Git、不进镜像、不进日志。

## 13. 风险与待确认

| 风险 | 影响 | 应对 | 状态 |
|---|---|---|---|
| 烟草牌照/广告/支付合规未确认 | 无法合法上线 | 客户提供书面合规意见；列为上线阻断 | **待确认** |
| AWS 账号/区域/域名未确认 | 无法部署 | 确认账号归属、区域、Route 53 权限 | **待确认** |
| 服务器 4 GB 构建 Next 镜像可能 OOM | 发布失败 | CI 构建推 ECR；或加 swap/升配 | 待处理 |
| 本地 Node 22 与项目 Node 24 不一致 | 本地命令失败 | 用 Node 24 或 Docker 开发 | 已知 |
| 数据库与应用的备份只在本机 | 主机故障丢数据 | 每日快照 + 异地备份 + 恢复演练 | 待补强 |
| 无集中监控/告警 | 故障发现慢 | CloudWatch Agent + 外部 uptime | 待补强 |
| S3 媒体未启用 | 媒体与主机耦合 | 生产启用 S3 + IAM + 生命周期 | 待实施 |
| 新实例无 storefront 应用 | 第二客户起实例会失败 | 增加前台应用生成步骤或 manifest 指向既有应用 | 复制前必修 |
| 模板硬编码旧服务器/Caddy 端口 | 新客户带出旧信息、同机演练冲突 | 模板参数化 `HTTP_PORT`/`HTTPS_PORT`，去硬编码 | 复制前必修 |
| HTTP 集成测试依赖 embedded Postgres | CI 偶发超时 | CI 用 `--test-concurrency=4` + 独立 PG | 已知 |
