# EZSTARTCommerce 测试用例矩阵

> 版本：1.0（开发前用例基线）  
> 用例状态：预期结果已定义；测试代码、实际结果、证据、缺陷号和执行日期应在对应迭代/发布记录中填写。  
> 测试规则：[测试策略](TEST_STRATEGY.md)；接口前置：[API 契约](API_SPEC.md)；交易场景：[生产就绪验收](PRODUCTION_READINESS_ACCEPTANCE.md)。

## 1. 执行字段

执行时每条用例增加：`Build/Commit`、环境、执行人、时间、结果（Pass/Fail/Blocked/Not Run）、证据链接、缺陷 ID、备注。下表里的“预期结果”必须可由 UI、API、数据库账本、审计记录或异步任务状态之一复核。P0/P1 用例是发布门禁。所有测试数据均为合成数据，金额使用整数最小单位。

## 2. 单元测试用例（UT）

单元测试面向纯领域规则和应用服务，使用固定时钟与明确输入；数据库并发/事务另见 IT 用例。

| ID | 模块 | 优先级 | 输入/操作 | 预期结果 |
|---|---|---:|---|---|
| UT-001 | M01/M06 | P0 | 用整数金额计算小计、折扣、配送、税费和总额 | 公式与最小货币单位精确一致，无浮点误差、负总额 |
| UT-002 | M11 | P0 | 固定金额优惠分摊到多行，出现不可整除余数 | 按订单行创建顺序分配余数，各行折扣和等于总折扣 |
| UT-003 | M11 | P0 | 百分比优惠在半单位边界计算 | 按 half-up 舍入；不超过合格商品金额 |
| UT-004 | M11 | P1 | 优惠开始前、有效区间内、结束时刻验证 | 区间为 `valid_from <= now < valid_until`，边界结果一致 |
| UT-005 | M11 | P0 | 超订单总额、最低消费、商品范围、顾客限额的券 | 正确接受/拒绝并返回稳定原因码 |
| UT-006 | M12 | P0 | 现货、预留数不同组合计算可售量 | `available = on_hand - reserved`；不允许负预留/负现货 |
| UT-007 | M12/M08 | P0 | 预留过期但支付仍未知 | 不释放库存或优惠；进入待查询/告警状态 |

| UT-009 | M03 | P1 | 同 SKU 大小写/规范化冲突 | 按本实例唯一性规则拒绝重复 SKU |
| UT-010 | M04 | P1 | 手动陈列排序相同或动态排序同值 | 产生规定的稳定次级排序；结果可重复 |
| UT-011 | M07/M08 | P0 | 订单付款、取消、退款、发货状态机尝试合法转换 | 按状态表允许的转换成功并保留 from/to 信息 |
| UT-012 | M07/M08 | P0 | 对订单/支付执行未列出的状态跳转 | 拒绝转换，不写交易副作用 |
| UT-013 | M08/M16 | P0 | 退款金额超过已收减累计退款 | 拒绝，累计退款上限准确包含并发前已完成款项 |
| UT-014 | M09 | P1 | 区域、固定运费、门槛免运边界值 | 按已配置区域和税前优惠后商品金额计算 |
| UT-015 | M09/M07 | P0 | 发货后地址变更，或费用变化未获顾客确认 | 拒绝直接修改；按策略返回待确认/人工处理 |
| UT-016 | M10 | P1 | 积分获取、退款冲回、重复事件 | 按规则计算，重复事件幂等，不出现重复入账 |

## 3. 数据库/模块集成与 API 功能测试（IT/API）

| ID | 模块 / API | 优先级 | 前置与步骤 | 预期结果 |
|---|---|---:|---|---|
| IT-001 | M00 登录 | P0 | 正确密码登录；未启用 MFA 的高权限账号继续操作 | MFA 账号建立待验证 challenge；验证前敏感操作被拒 |
| IT-002 | M00 会话 | P0 | 停用员工后重用原 session cookie 访问后台 | 即时 401/撤销；访问失败有 requestId，不泄露数据 |
| IT-003 | M00 权限 | P0 | 客服角色直接调用退款/支付配置 API | 403 `FORBIDDEN`；没有交易/配置副作用并留下必要审计 |
| IT-004 | M00 审计 | P1 | 创建员工、改角色、停用账号 | 审计含操作者、对象、动作、结果和时间；不含密码/MFA secret |
| IT-005 | M01 店铺配置 | P1 | 启用语言但不提供必填店铺文案后发布 | 配置发布被阻止，指出缺失 locale 和字段 |
| IT-006 | M01 市场 | P0 | 关闭一个市场后请求目录、加购物袋、报价和下单 | 四个服务端入口均拒绝/过滤，不能只隐藏前端入口 |
| IT-007 | M03 商品 | P1 | 建立含多 SKU/三语的商品草稿并更新版本 | 数据关联正确；旧 version 更新返回 409，不覆盖新版本 |
| IT-008 | M03 商品发布 | P0 | 发布合规齐全商品后读取 storefront API；再撤下 | 已发布可见，撤下后不能购买；历史订单快照仍可查 |
| IT-009 | M03 搜索 | P1 | 精确 SKU、名称子串、多语言和不可售项搜索 | SKU 优先；按请求语言匹配；不返回草稿/市场禁售商品 |
| IT-010 | M04 陈列 | P1 | 同一首页配置区块 A/B、置顶商品和动态新品排序 | 只影响对应页面/区块；其他页面和商品原字段不变 |
| IT-011 | M04 原子发布 | P0 | 三语页面中一种语言缺少必填内容后发布 | 所有语言均不发布；线上旧版本保持完整可用 |
| IT-012 | M04 定时任务 | P0 | 建定时发布后编辑并发布更新版本，再触发旧计划 | 旧计划不能覆盖/撤下新版本；任务状态与失败原因可查 |
| IT-013 | M04 回滚 | P1 | 从版本 V2 回滚到 V1 | 新建 V3 发布版本，审计保留；不是篡改历史版本 |
| IT-014 | M05 导入 | P1 | 上传 CSV 后执行 validate | 返回总行数、有效/无效行数和行级错误；产品表未改变 |
| IT-015 | M05 原子导入 | P0 | 原子模式文件含一行无效并执行 | 整批不提交，记录失败原因；无部分商品变更 |
| IT-016 | M05 部分导入 | P1 | 部分有效模式文件混合有效和无效行执行 | 仅有效行提交；失败行可下载；结果计数一致 |
| IT-017 | M05 幂等 | P0 | 同 key 同 payload 重复执行导入；再用同 key 不同 payload | 前者返回同一 job/result 不重复写；后者 409 冲突 |
| IT-018 | M05 导出 | P0 | 普通用户导出 PII，再由获准角色创建短时导出 | 未授权请求被拒；授权导出按字段遮蔽，链接过期失效 |
| IT-019 | M06 购物袋 | P1 | 游客购物袋尝试读取其他 session 的购物袋 | 访问被拒；token 不可枚举，响应不泄露商品/个人资料 |
| IT-020 | M06 报价 | P0 | 报价后改商品价格/库存/券/配送规则再提交旧 quote | 订单创建被阻止并返回 `PRICE_CHANGED`/`QUOTE_EXPIRED` 等稳定码 |
| IT-021 | M06 下单幂等 | P0 | 同一 key 并发提交相同下单请求 | 仅创建一笔订单、一组预留和一次付款意图 |
| IT-022 | M06 下单幂等冲突 | P0 | 同 key 并发提交不同购物车 payload | 一个结果被固定，其余返回 409；没有第二笔订单 |
| IT-023 | M06 价格信任 | P0 | 请求体伪造低价、税、折扣或总金额 | 服务端忽略客户端权威金额，返回重算金额/拒绝差异报价 |
| IT-024 | M07 并发库存 | P0 | 两个请求并发购买最后一件商品 | 只有一个订单获得预留；另一个 `INSUFFICIENT_STOCK`；账本不超卖 |
| IT-025 | M07 订单状态 | P0 | 已取消订单再次发货或重复取消 | 非法跳转 409；库存/通知/付款不重复变化 |
| IT-026 | M07 地址修改 | P0 | 修改未发货订单地址，造成配送费差额，再不确认 | 变更未生效、旧订单金额保留；有待确认或拒绝状态 |
| IT-027 | M09 分包裹 | P0 | 一个订单分两包裹发货，再尝试超量发货 | 累计不超购入数量；逐次写正确库存流水及订单履约状态 |
| IT-028 | M08 webhook | P0 | 签名无效、过期事件和重复事件依次发送 | 无效拒绝；过期按 provider 防重策略拒绝；重复不重复记账 |
| IT-029 | M08 webhook 乱序 | P0 | 先送成功后送延迟 pending/失败回调 | 状态不能倒退；账本最终状态和事件历史一致 |
| IT-030 | M08 unknown | P0 | provider 超时并返回未知支付状态 | 订单不标失败；库存/券不释放；触发查询任务和可见告警 |
| IT-031 | M08 金额校验 | P0 | 回调金额、币种或商户号与本地 payment 不符 | 不置成功；进入差异队列并记录脱敏事件摘要 |
| IT-032 | M08 退款幂等 | P0 | 同退款 key 重试/并发，超过余额再次申请 | 同 key 返回原退款；累计退款不超额；越限拒绝且有审计 |
| IT-033 | M08 结算重复文件 | P1 | 重复导入相同结算文件和行 | 文件/交易行识别重复，不重复入账，保留来源摘要 |
| IT-034 | M08 结算差异 | P1 | 导入金额/币种不符行，授权人员解决差异 | 差异类型和人工理由留存；原始行/原账本金额不被覆盖 |
| IT-035 | M10 OTP | P0 | 请求 OTP、错误码超限、正确验证码验证、重复使用旧码 | 限流/冷却准确；正确码建立会员会话；一次性验证码不能重用 |
| IT-036 | M10 身份关联 | P0 | 未验证访客下单资料与现有会员邮箱相同 | 不自动合并；会员验证后才按批准规则关联 |
| IT-037 | M10 积分 | P1 | 已完成订单产生积分，重复事件后再部分退款 | 入账仅一次；按实退比例冲回；流水不可覆盖 |
| IT-038 | M10 隐私请求 | P0 | 未核验身份尝试导出/删除客户资料 | 操作被阻止；请求保持待核验；不生成下载链接 |
| IT-039 | M11 券并发 | P0 | 多笔订单同时争用最后一张/最后额度券 | 只有限额内成功预占；其余明确无额度；重复请求幂等 |
| IT-040 | M11 释放 | P0 | 取消未付款订单、未知付款订单分别处理 | 明确取消时按规则释放；未知付款不释放；仅一次状态转换 |
| IT-041 | M12 库存调整 | P0 | 两人基于旧库存版本并发提交相反调整 | 锁/版本冲突避免覆盖；每笔成功调整有原因和库存流水 |
| IT-042 | M12 预警 | P1 | SKU 低于阈值并重复触发 worker | 产生一个活动告警或按策略去重，不无穷重复发送 |
| IT-043 | M13 交易通知 | P1 | 订单事件重复投递，通知供应商失败后重试 | 同业务通知不重复发送；失败可重试；订单交易不回滚 |
| IT-044 | M13 营销同意 | P0 | 未同意/已退订顾客进入营销发券任务 | 任务阻止营销发送；交易通知仍按交易用途单独判断 |
| IT-045 | M13 人工重发 | P1 | 管理员重发失败通知 | 只发送消息；不重新执行下单、支付、退款或积分业务 |
| IT-046 | M14 报表口径 | P1 | 同时存在 COD 待收、线上待付、退款和完成订单 | 指标按已定义状态和来源账本计算；展示口径/时区/生成时间 |
| IT-047 | M14 导出 | P0 | 创建报告导出并尝试越权下载及过期后下载 | 未授权/过期拒绝；默认不含 PII；操作可审计 |
| IT-048 | M15 实例隔离 | P0 | 两个测试部署各创建不同商品/订单并交叉请求 | 不可跨实例访问数据库、对象、会话、密钥或备份 |
| IT-049 | M15 迁移 | P0 | 从上一受支持版本迁移并在迁移失败点重试 | 迁移版本可识别；失败安全退出/恢复，不破坏已有数据 |
| IT-050 | M16 退货质检 | P0 | 退款/退货案件收货，分别标记可售、损坏、报废 | 各库存状态产生正确流水；质检前库存不恢复 |
| IT-051 | M16 重复退款 | P0 | 同一售后案件重复执行退款动作 | 仅一次外部退款/账本金额；重复操作返回既有结果或冲突 |
| IT-052 | API 契约 | P0 | 向下单 DTO 注入未定义字段/客户端总额字段 | 422 `VALIDATION_ERROR`；没有订单、库存预留、优惠占位或付款副作用 |
| IT-053 | API 版本 | P1 | 使用过期 `If-Match`/`expectedVersion` 更新商品或页面 | 409 `VERSION_CONFLICT`；响应当前版本，不覆盖服务端新版本 |

## 5. 全功能端到端旅程（E2E）

E2E 每条以独立、可重置测试店铺开始；用 Playwright 桌面与移动视口运行。第三方付款/通知用隔离沙箱或 stub。至少为订单/付款等失败步骤保存脱敏 trace。

| ID | 链路 | 优先级 | 执行步骤摘要 | 端到端验收结果 |
|---|---|---:|---|---|
| E2E-001 | 初始化到可运营店铺 | P0 | 首次部署 → MFA 管理员 → 三语/市场 → 配置支付/配送 → 健康检查 | 店铺配置完整；未批准或未配置渠道未出现在前台；初始化操作可审计 |
| E2E-002 | 商品到前台展示 | P0 | 后台新建三语商品/SKU/图片/库存 → 发布 → 前台分类/搜索/详情查看 | 三语言数据、库存和价格一致；草稿和下架数据不可购买 |

## 6. 安全、可靠性与非功能测试（SEC/NFR）

| ID | 优先级 | 验证步骤 | 预期结果 |
|---|---:|---|---|
| SEC-001 | P0 | 尝试水平/垂直越权：替换用户、订单、退款、导出 ID | 不返回未授权资料；无副作用；requestId 可追踪 |
| SEC-002 | P0 | 对登录、OTP、优惠码、搜索和 webhook 做限速/重放尝试 | 按策略返回 429/拒绝；有限恢复；不泄露账号存在性 |

| SEC-004 | P0 | 扫描日志、错误页、埋点、trace 中的合成 PII/密钥/OTP | 不出现明文敏感信息；必要标识使用脱敏/不可逆摘要 |
| SEC-005 | P0 | 访问不允许索引的后台、购物袋、结账、预览 URL | 有 `noindex`/访问控制；不进入 sitemap/公开缓存 |
| SEC-006 | P1 | 上传超大、伪造 MIME、恶意扩展名文件 | 上传被拒；私有对象不公开；无脚本执行 |

| NFR-002 | P1 | 模拟数据库/对象存储/支付 provider 暂时不可用 | 健康状态明确；写操作不静默成功；可恢复任务有限重试 |
| NFR-003 | P1 | 停止 worker 后累积 outbox 任务，再恢复 worker | 任务可续跑；重复投递不重复扣款/发券/积分/通知业务 |
| NFR-004 | P0 | 备份损坏、恢复失败、升级迁移中断的演练 | 明确失败、报警和恢复路径；不报告虚假成功 |
| NFR-005 | P1 | 检查三语页面窄屏和常用桌面宽度 | 核心购买/运营操作可完成，无关键遮挡和横向溢出 |
