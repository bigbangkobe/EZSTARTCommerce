# 统一设计系统与交互规范

## 1. 产品视觉方向

后台先采用清楚、克制、以信息层级为主的经营工具风格；客户前台不共享一个固定品牌风格，但共享布局基础和可访问组件。

第一轮前台示例用编辑式陈列方向：自然中性色、深绿主色、少量暖铜色点缀、图片主导、较宽留白。它是一个客户设计方向，不作为所有客户的默认主题。另一种快速选购方向减少大幅主视觉，突出分类、筛选和商品密度。

不同客户独立确定品牌标志、主色、字体、影像和首页结构；共用的应是可访问性、表单行为、价格格式、购物车状态和 API 语义。

## 2. 布局规则

### 顾客前台

- 桌面内容区按客户页面设计采用居中容器；关键购买信息优先于装饰区。
- 导航、语言、搜索和购物袋在常见页面保持一致。
- 商品列表使用稳定的卡片比例；图像尺寸和裁切规则由主题定义。
- 商品详情页在移动端固定保留可访问的加购动作，但不覆盖关键信息。
- 购物车和结账优先单列，摘要清楚显示商品金额、折扣、运费和应付金额。

### 商家后台

- 左侧主导航按任务分组；窄屏折叠为图标/抽屉导航。
- 页面顶部保留面包屑、标题、帮助说明和主操作。
- 列表页按“筛选 -> 表格 -> 分页”组织；编辑页按业务分段，优先两列，仅字段相关时并排。
- 销售和库存摘要仅显示能指导运营行动的指标，不用无业务意义的装饰卡片填满页面。
- 订单、支付、库存和操作日志保留直接可读的状态、时间与操作人。

### 断点策略

布局需在宽屏、平板、窄屏和 320px 起的窄视口检查。断点以内容是否需要重排决定，而不是为每个设备复制一套页面。表格优先精简列、隐藏次要列；无法压缩时才提供水平滚动。

## 3. 字体、颜色与主题

### 字体

- 界面默认使用系统无衬线字体；客户品牌页可单独配置品牌字体。
- 品牌标题可使用衬线或客户指定字体，表格、表单和状态使用易读字体。
- 价格、订单号、SKU、日期和报表数字使用等宽数字。
- 不使用极小文字承担关键说明；错误、价格和付款状态必须清晰可读。

### 颜色语义

通过语义变量定义而非在各页面硬编码：

- background：页面背景。
- surface：内容区、表格或浮层表面。
- text-primary、text-secondary：正文与辅助说明。
- border、field：分隔线和输入边界。
- brand、brand-foreground：客户品牌色和其上文字。
- success、warning、danger、info：状态语义。

状态必须同时使用文字，不仅依靠颜色区分。低库存、支付失败、权限不足和危险操作采用明确语义，但不使用满屏红色或过度弹窗。

## 4. 通用组件设计

| 组件 | 适用页面 | 交互要求 |
|---|---|---|
| 全局导航 | 前台、后台 | 当前页明显；可键盘访问；移动端有可关闭菜单 |
| 面包屑 | 后台编辑/详情 | 可回到上级列表；不作为唯一导航 |
| 搜索与筛选 | 商品、订单、顾客、统计 | 条件可见；清除条件可恢复默认；支持 URL/分页状态时保持一致 |
| 数据表格 | 商品、订单、顾客、库存、日志 | 清晰列名、排序指示、选择行行为、分页、窄屏策略 |
| 表单字段 | 设置、商品、优惠、内容 | 可见标签、帮助文字、必填标识、行内校验、保存状态 |
| 状态标签 | 订单、付款、导入、库存、通知 | 显示文字与颜色；状态语义跨页面保持一致 |
| 确认对话框 | 删除、退款、库存调整、权限变更 | 说明影响、对象和是否可撤销；危险按钮使用明确动词 |
| Toast/通知 | 保存、导入、加购、操作结果 | 表达成功或失败，短暂显示；失败仍保留页面输入 |
| 空状态 | 新店、无商品、无订单、无报表 | 解释为什么为空，并给一个与权限匹配的下一步 |
| 骨架/加载态 | 首次加载和筛选 | 保留大致布局，避免闪烁；操作按钮显示进行中状态 |
| 错误面板 | API/支付/导入失败 | 展示可理解原因、重试或联系渠道，技术细节仅进入日志 |

## 5. 文案与多语言

- 界面支持简体中文、繁体中文、英文；后台当前语言与前台可用语言分别配置。
- 每个可翻译实体显示各语言完成状态，明确缺译时的展示策略。
- 日期、货币、数字、地址字段按实例配置的地区与时区格式化。
- 订单和交易文案保留创建订单时的语言快照，不因后台默认语言变化覆盖历史记录。
- 翻译文本长度变化不应引起按钮消失、表格结构错位或价格遮挡。
- 禁止把已翻译文案拼接成一个句子；完整句子按语言分别维护。

## 6. 表单、状态与反馈

所有表单都有四种基本状态：初次打开、修改未保存、保存中、已保存/保存失败。离开未保存页面时提示保留或放弃修改。服务端返回字段错误时定位到字段并保留输入。

破坏性操作需显示对象名、影响范围和结果；不能用“确定吗？”这种无上下文确认。需要重复提交保护的动作包括创建订单、应用支付回调、库存调整、退款和批量导入。

## 7. 权限、审计与隐私呈现

- 没权限的动作隐藏或禁用并解释缺少的权限；后端仍必须再次授权。
- 顾客电话、邮箱和地址仅在订单/客服相关权限内显示；报表默认使用聚合值。
- 导出、退款、支付凭证更改、库存调整、价格/促销变更、角色授权记录操作者与时间。
- 页面日志和错误信息不显示访问令牌、支付密钥、完整支付卡资料或不必要的个人资料。
- 客户前台不暴露后台路由、管理 API 密钥或内部备注。

## 8. 可访问性与响应式验收

- 页面主要操作有可见文字或可读屏标签；图标按钮不能只依赖图形。
- 所有交互可用键盘完成，焦点次序符合视觉阅读顺序，焦点状态清晰。
- 错误通过文本关联到字段；动态结果通过合适的状态播报。
- 颜色对比达到目标标准；颜色不是唯一的状态编码。
- 触控控件有足够间距，表单输入不会被移动端键盘遮挡。
- 图片有替代文本；纯装饰图不读出无意义描述。

## 9. 客户主题与定制分层

每个客户的主题配置只承担品牌资料、颜色、字体、图片、导航和已支持内容块。客户特有页面结构、复杂筛选、专属商品选择器或独有结账交互属于前端定制开发。主题配置不允许注入可执行代码或绕过交易规则。

交付客户页面前需维护：站点地图、页面清单、设计稿链接/版本、响应式状态、页面数据来源、关键交互、异常态和验收标准。
