# M15 私有部署、实例开通、安全与模板升级

**优先级：**P0  
**初步开发估算：**16–24 人日（不含商家自有云资源、域名及第三方服务费用）

## 产品目标

让同一份 EZSTARTCommerce 模板可为不同商家重复开通为独立私有实例。每位商家配置并运营自己的品牌独立站、商品、订单、付款、配送、内容和后台；不同商家之间不共享商店数据或管理权限。

## 首期范围

- 可重复的部署包/部署脚本和环境配置模板。
- 为新商家初始化一套独立站点、后台管理员、数据库、媒体空间和密钥。
- 商家自己的域名绑定及 HTTPS/SSL 设置说明。
- 首次启动配置：店铺名称、标志、语言、货币、时区、目标市场、客服资料和管理员。
- 商家分别配置自己的商品、价格、库存、订单、优惠券、配送和支付服务凭证。
- 默认部署到商家持有的云账号；交付方获授权安装、初始化并交接。可选代托管独立实例，持续运维/SLA 另行签约。
- 开发/测试/生产环境，版本化数据库迁移、健康检查、日志、监控、备份和恢复。
- 版本发行说明、兼容性约束、升级检查、升级前备份和回滚步骤。
- 通用后台和电商核心优先通过配置与稳定扩展点满足共性需求；每位客户的专属前台可独立设计、开发和发布，并通过稳定 API 连接该客户实例，避免把客户专属页面逻辑分叉进共享核心。
- 导出商店配置、商品和订单资料的迁出方案；备份中包含数据库与媒体文件。
- 实例交接或停止服务时提供受权限保护的数据导出/迁出流程，至少覆盖商品/SKU、分类与内容、订单及行项目、客户/会员及同意记录、优惠券、库存流水和媒体索引；导出注明格式、生成时间、币种/时区和校验清单。密钥、支付凭证、OTP 和会话令牌不进入通用业务导出；客户需通过密钥轮换/服务商重新绑定完成交接。
- 客户确认数据导出并完成留存/删除责任后，可按批准期限销毁实例数据；备份副本按备份保留周期到期轮转删除，不能宣称即时从所有备份清除。操作需双重核对目标实例并记录操作者、审批和完成状态。

## 独立实例边界

每个商家实例至少隔离：

- 应用部署/运行环境及管理员账号。
- 数据库中的商品、顾客、订单、库存、优惠券和报表数据。
- 商品图片、内容媒体和导入导出文件空间。
- 支付、邮件、短信、WhatsApp 和物流凭证。
- 域名、TLS 证书、日志访问权限和备份。

模板提供方不得默认跨店读取商家订单或顾客资料。若代运维需访问排障，应使用经授权的临时权限并记录操作。

## 主要数据对象

DeploymentConfig；InstanceProfile（实例编号、商家标识、版本、域名、区域、状态）；SecretReference；ReleaseVersion；MigrationRecord；BackupRecord；HealthCheck；SupportAccessRecord；IncidentLog。敏感密钥不进入代码仓库、普通配置文件或日志。

## 关键业务规则

- 一套部署默认对应一家商家和一个独立站；若同一商家要多个站点，默认创建多个实例，避免一个后台误操作影响多个站。
- 同一套版本化核心支持多实例，但每家商店的运行数据、密钥和配置独立。
- 代码版本与商家配置/商家数据分离；升级不能覆盖商品、订单或主题配置。
- 生产升级前备份并在可用的预发布环境验证；升级失败有恢复/回滚步骤。
- 商家持有云账号、域名和第三方商户凭证；交付方按授权完成初次部署。主机/备份/监控费用由商家承担。
- 持续安全升级、监控值守、事故响应时段、RPO/RTO 承诺和代托管范围写入单独服务协议；没有该协议时不承诺全天候支持。
- 具体市场的数据留存、导出、删除、年龄验证和销售限制由业主审核后配置。
- 默认不建设集中 SaaS 总控台，也不将多个商家的运营数据集中到模板方后台。

## 验收条件

- 能按部署说明从空环境开通两套示例实例。
- 两个实例拥有不同域名/配置/管理员和数据存储；在一方创建商品、订单或顾客资料，不会出现在另一方。
- 每个实例可独立设置品牌、语言、货币、市场、配送和付款凭证。
- 管理员可在自己的后台维护该店商品并处理订单。
- 可完成域名/HTTPS 配置，或明确提供所需 DNS 和证书步骤。
- 可备份及恢复数据库和媒体文件；恢复不会混入另一商家数据。
- 模板升级不覆盖商家数据；升级前备份、健康检查和回滚流程可演练。
- 运维人员只能按约定权限访问实例；支持访问有记录。
- 可生成不含密钥/会话凭证的实例业务数据导出，并能校验文件/媒体清单；停用/迁移时能按客户确认的保留期限执行销毁并记录备份轮转截止时间。
- 部署资料说明资源要求、密钥配置、更新、迁移、备份和故障处理。

## 8. 非功能目标与可验收门槛

以下为建议起始值，需求冻结时需结合客户自托管/代托管责任、机器规格和合同确认；它们不是已签署 SLA。

| 类别 | 建议基线 | 验收方式 |
|---|---|---|
| 性能 | 约定商品/订单数据量、测试设备和网络下，商品目录/详情主要内容 p75 ≤ 2.5 秒；内部关键 API p95 ≤ 800ms；第三方支付、邮件和物流耗时单独计 | 记录测试环境、数据规模、请求和页面时延 |
| 可用性 | 代托管实例建议月度目标 99.5%；商家自托管需明确主机和网络责任边界 | 健康探测和事故记录 |
| 备份与恢复 | 每日自动备份；默认规划 RPO ≤ 24 小时、RTO ≤ 8 小时；保留期限可配置 | 在隔离环境完成恢复演练并记录恢复耗时 |
| 管理员安全 | 最小权限 RBAC；高权限角色 MFA；登录限速；退款、导出、权限变更和生产运维全审计 | 权限矩阵演示及审计日志抽查 |
| 数据安全 | 全站 TLS；备份加密；密钥不写进源码或普通日志；不存卡号/CVV | 配置审查与日志抽查 |
| 交易可靠性 | 建单、支付回调、退款、库存调整和导入定义幂等；外部服务超时可观察并安全重试 | 重复请求和超时场景演练 |
| 可维护性 | 版本化数据库迁移；发布前检查、备份、健康检查和回滚步骤齐备 | 在预发布实例演练升级及恢复 |
| 隐私 | 分析事件不得包含顾客姓名、电话、邮箱、地址或付款资料 | 抽样检查事件结构和日志 |
| 前台质量 | 三语、移动端、键盘操作、表单标签、焦点、错误反馈和图片替代文本纳入验收 | 页面检查清单和代表性设备走查 |

实例开通验收必须包含：新装、支付/通知配置检查、数据隔离、升级、备份、恢复、日志脱敏和支持访问审计。具体 SLA、支持时段、故障响应和安全更新时限需写入客户合同。

## 依赖

实例初始化和部署骨架只依赖商家/运维方提供的云账号、域名、DNS、密钥管理及备份服务，可先于业务模块交付。安全基线、恢复演练、业务数据交接和停用流程须在 R6 与全部已交付模块联合验收。

## 项目实施建议

项目 C 阶段搭建可重复部署和实例初始化，MVP 阶段用两个独立测试实例验证隔离；G 阶段验证全新部署、升级、备份恢复和交接。估算 16–24 人日仅覆盖私有部署与核心版本升级能力，不含任一客户的专属前台设计和开发；自动化控制台、集中账单、跨店统一运营另立项目估算。
