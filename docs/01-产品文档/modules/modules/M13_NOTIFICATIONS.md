# M13 订单通知与客服资料

**优先级：**P0  
**初步开发估算：**6–10 人日（短信/WhatsApp 自动化按服务商另估）

## 产品目标
向顾客/店铺传递订单关键节点信息，并让商家维护前台客服联系方式。

## 首期范围
后台配置客服电话、WhatsApp 链接、邮件地址、营业时间；邮件订单确认/状态通知；可扩展短信或 WhatsApp 商业消息适配器；后台发送记录和失败重试。

## 主要数据对象
NotificationTemplate（多语言）；NotificationChannelConfig（凭证引用）；NotificationJob；DeliveryAttempt；CustomerConsentReference；SupportContact。

## 关键业务规则
仅使用已获批的发送渠道和模板；不把商户密钥存为明文；对发送失败记录可重试；营销通知与交易通知分开管理。通知任务在订单/付款等业务事务成功提交后创建，使用业务事件 + 接收目标 + 模板版本作为幂等键，重复 webhook/队列消费不得重复发送。人工重发单独记录操作者和原因，不重复执行订单或支付操作。模板发布前校验必需变量、链接和目标语言；生产启用语言没有已批准模板时不回退到其他语言、不阻断已提交订单，通知任务标为配置失败并告警；但交易邮件模板和通道配置完成是生产开店门槛。发送日志只保留必要状态和脱敏目标，不保留 OTP 明文或完整消息敏感字段。

## 验收条件
客服资料在前台更新；仅已提交的业务事件触发已配置通知；重复事件/重试不会重复发送或重复执行订单操作；人工重发留审计；通知按订单语言选择已批准模板，缺失模板按已配置策略告警/处理；营销发送受单独同意控制；发送失败原因和脱敏收件目标可查。

## 依赖
M01、M04、M07 业务事件契约及经客户批准的服务商账号/模板。M10 OTP 与 M11 营销通知调用本模块适配接口，不反向成为通知通道基础设施的前置模块。

## 项目实施建议
第 F 阶段；邮件基础 6–10 人日，短信/WhatsApp 自动化按服务商另估。
