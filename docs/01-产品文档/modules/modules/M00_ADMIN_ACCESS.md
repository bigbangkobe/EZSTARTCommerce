**优先级：**P0  
**初步开发估算：**8–12 人日（包含 MFA 与会话撤销后需按认证实现方案复核）

## 产品目标
为商家提供统一、安全的运营后台，并按岗位控制可见数据和可执行操作。

## 首期范围
后台管理员登录/登出；邀请或创建店员；密码重设；角色权限；后台导航；重要操作审计；会话列表与强制撤销。建议预设店主、管理员、商品运营、订单客服、财务、仓库、只读报表和隐私专员角色。隐私请求读取/核验/审批/处理/导出分开授权；通用顾客档案权限不自动授予完整隐私资料或导出权限。所有敏感操作服务端校验。

## 主要数据对象
AdminUser（姓名、邮箱/登录名、状态、凭证摘要、最近登录）；Role；Permission；UserRole；AuditLog（操作者、动作、对象、时间、结果、必要的变更摘要）。密码或支付密钥不得写入日志。

## 关键业务规则
服务端权限码、默认角色权限范围、会话/MFA和高风险动作统一按 [开发执行规格第 7 节](../DEVELOPMENT_SPEC.md#7-后台角色与权限基线) 执行；每个新增后台 API/导出/异步下载都必须有 permission code。
顾客账号与后台账号分离；员工使用唯一账号，不得共用管理员凭证。最低权限原则；离职/异常账号可立即停用并保留审计关联，停用后现有会话立即失效。角色/权限被收紧时，下一次请求立即使用新权限，必要时撤销相关会话。店主和管理员必须启用 MFA，首选验证器 TOTP 并提供一次性恢复码；登录限速、会话空闲/绝对期限和找回流程按实例安全策略执行。退款、支付配置、导出、隐私请求、权限变更等敏感动作做权限检查、二次确认和审计；高风险金额可配置双人审批。审计记录只允许受限角色读取/导出，应用层不提供编辑/删除能力；保留期限由客户上线策略配置，过期处置需留有不包含敏感内容的处置记录。

## 验收条件
不同角色只能访问授权菜单和操作，且 API 直接访问也不能绕过权限；停用账号立即使会话失效；权限收紧后旧会话不能继续使用已撤回权限；店主/管理员未完成 MFA 不能进入后台；关键操作可追溯；登录失败、密码重设和会话撤销流程可用；普通管理员不能修改/删除审计记录；审计不记录密码、OTP、支付密钥或完整支付/银行资料。

## 依赖

身份生命周期的路由、凭据边界、首次店主/邀请、MFA 登记与恢复、会话管理和实施前门槛见 [后台身份生命周期契约](../ADMIN_IDENTITY_LIFECYCLE.md)。当前已有 OpenAPI 草稿与静态回归，不代表认证服务已实现。
M15 实例初始化与平台基础。RBAC 权限点、员工身份和审计接口由各后台模块消费；具体权限矩阵随模块逐项登记，不要求所有业务模块先于本模块交付。
