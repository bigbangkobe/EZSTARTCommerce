# M04 内容管理

**优先级：**P0  
**初步开发估算：**5–8 人日（仅为基础 CMS 估算；加入首页/专题陈列配置和版本预览后需重新估算）

## 产品目标
让商家不改代码即可维护店铺内容、首页陈列和必要的客户说明。

## 首期范围
关于我们、联系我们、FAQ、隐私/退换/配送说明、公告、文章；三语内容；草稿/发布；发布时间和排序；客服资料由统一设置引用。维护主题已提供的首页、分类/专题页陈列区块：选择区块类型、显示状态、区块顺序、商品/分类/内容来源、手工商品顺序或动态排序规则，并可预览后发布。可编辑各语言页面标题、slug、SEO title/description、社交分享图和索引开关；提供预览、站点地图收录和已发布 URL 变更的重定向管理。

## 主要数据对象
ContentPage；ContentTranslation；Article；ArticleTranslation；FAQItem；Announcement；HomepageSection；MerchandisingCollection；ProductPlacement；PublishVersion；PublishStatus；UpdatedBy/UpdatedAt。

## 关键业务规则
跨语言发布原子性、定时计划、版本回滚、公开/索引资格及商品资格复验按 [开发执行规格第 8.1–8.2 节](../DEVELOPMENT_SPEC.md#8-页面发布导入通知和统计的端到端流程) 执行；商品新品/销量/价格动态排序口径见第 5.4 节。
页面内容可按语言分别发布；陈列草稿必须补齐店铺已启用语言的必填内容，发布不能静默回退到另一种语言。每店/语言 URL slug 唯一；已发布 slug 修改时需预览并确认创建旧地址到新地址的 301 重定向，冲突或循环必须阻止保存。未发布草稿、预览链接、后台和非生产环境不得被站点地图收录，预览页返回 noindex 控制且链接短期有效。已发布页面只有在明确允许索引时才加入站点地图；禁用/删除页面从站点地图移除并展示处理提示。SEO title/description 支持长度提示但不截断实际内容，canonical 和多语言 alternate URL 由路由/语言配置生成，不允许手工指向其他店铺域名。免责声明/政策内容由业主提供并审核，系统不生成法律承诺。陈列配置只能使用当前客户主题已注册的安全区块和字段，不提供任意代码/脚本编辑。区块内可选手工指定商品并调整本区块优先级，或按新品、销量、价格等已支持规则动态排序；动态规则需有展示上限和稳定的同值排序，手动优先级只在手动模式启用。排序作用范围为该区块/页面，不改商品全局数据。

商品资格在发布时及前台读取/购买时均校验。手动陈列中的商品若后续下架、归档或当前市场不可售，前台立即隐藏该商品；后台保留配置并标记异常，提示运营替换。动态陈列排除不合格商品并由后续合格商品补足展示数量。缺货商品按店铺配置隐藏或显示售罄，但始终不可加购。发布版本按所有启用语言原子切换，前台不得混用新旧语言版本。定时任务按店铺时区执行；首期每页仅允许一个待执行计划，撤下计划绑定对应发布版本，不能撤下后续更新版本。计划失败时保留线上版本并告警。更改保存为草稿，版本历史不可覆盖；回滚会从历史快照创建新的发布版本。

## 验收条件
管理员可以编辑、预览、发布、取消发布各语言页面；前台按状态显示；未发布草稿不可公开访问。管理员可新增/隐藏/排序主题支持的首页、分类和专题陈列区块，选择商品或动态排序、调整本区块商品优先级、保存草稿并预览桌面/手机三语视图；可即时发布、按店铺时区定时发布或撤下，并撤回/恢复历史版本。SEO 字段、索引开关、三语 canonical/alternate、站点地图和 slug 变更重定向可复核；草稿/预览不得进入索引。动态排序下禁用手动排序控件；选择商品时，禁选项显示具体资格原因。发布后商品资格变化会触发前台重验：下架、归档、市场不可售商品立即隐藏，动态区块补足候选；手动区块保留后台配置并提示运营修复。缺译、定时冲突、过期草稿和计划失败均有明确阻断/修复提示。定时失败时线上版本保持不变且后台显示失败原因。客户主题不支持的区块明确提示需定制开发，不允许配置静默失效。

## 依赖
M00/M01、M02、M03。前台消费已发布的内容与商品陈列契约；主题预览和页面发布流程使用 M02 前台契约。

第 D 阶段，基础页面优先；历史基础 CMS 估算为 5–8 人日，陈列配置需重新估算。

## 第一批实现（2026-11-18）

本批只做「内容页」这一条最常用的链路，把 M04 里最先被需要、也最容易出错的部分落地：后台三语草稿 → 发布版本快照 → 前台按发布版本渲染。

已实现：

- **页面与翻译**：`ContentPage`（page_key/page_type/status/version）+ `ContentPageTranslation`（locale/title/slug/SEO/indexable）。page_key 与 slug 都是小写 ASCII 短横线串，同语言 slug 唯一（草稿唯一 + 发布地址部分唯一两套约束）。
- **草稿与发布分离**：草稿存在 `ContentPage.blocks` 与翻译表；发布时固化成 `ContentPageVersion.snapshot` 不可变 JSON，前台只读快照。因此「保存草稿」永远不会改变公开地址，也不会生成可索引的临时内容。
- **跨语言原子性**：发布要求店铺**已启用语言**全部齐全（不静默回退到另一种语言），三语在同一事务里一起切换；缺语言返回 `CONTENT_LOCALE_INCOMPLETE`，后台给出补齐提示。
- **发布 / 撤下 / 回滚**：撤下清空 `published_slug`（地址立即失效）并把版本标 `withdrawn`；回滚用历史快照建**新版本**并同时把草稿恢复成该内容，避免下一次发布把新草稿盖回旧线上内容。
- **定时发布**：`mode=scheduled` 只登记计划（202），worker 每 15 秒检查到期任务；发布失败保留线上版本，计划回退为草稿并写 `content.page.schedule_failed` 审计。编辑已定时的页面会自动取消计划（避免用编辑后的内容在旧时刻静默上线）。
- **区块注册表**：参考主题注册 `rich_text` / `faq_list` / `contact_card` / `notice` 四种类型，配置按类型逐字段白名单校验，拒绝 HTML/脚本字符、未知字段、重复 id；未注册类型直接 422，不提供任意代码编辑。
- **内容发布标记**：`ContentRelease` 单行计数器，任何发布/撤下 +1，前台 `/storefront/config` 返回 `cr-N`；主题把它作为区块埋点的 `publishVersionId`，区块报表因此能按真实内容版本分组（替换了原来的固定主题标记）。
- **前台**：`/[locale]/pages/[slug]` 渲染已发布内容页，canonical 指向实际渲染语言、alternates 来自同一份快照，`indexable=false` 输出 noindex；页脚列出已发布页面；站点地图只收 indexable 的已发布页（含三语 alternate）。
- **后台**：`/admin/content` 列表、新建草稿、编辑（If-Match 版本）、发布/定时/撤下/回滚、草稿预览（桌面/手机），错误码映射为可执行的修复提示。

本批未做（由第二批补上预览外链与 301；其余进入第三批）：

- 首页/分类/专题的陈列区块配置（`/admin/merchandising/{pageKey}`，含动态排序、手工优先级与商品资格复验）。
- 文章/公告列表页、`/storefront/collections/{slug}` 专题页、社交分享图字段。
- 政策文本仍由业主提供并审核，系统不生成法律承诺；`site.policies` 版本号仍需替换为真实版本。

## 第二批实现（2026-11-19）

本批补齐第一批明确留下的两个运营缺口：**不能把草稿发给别人看**、**改 slug 后旧地址变死链**。陈列区块配置（首页/分类/专题）仍留在第三批。

已实现：

- **预览外链**：`POST /admin/pages/{id}/preview-token`（`content.preview` 权限）签发 60 分钟有效的 token，可指定 5–1440 分钟。token 是 32 字节随机数的 base64url，**库里只存 SHA-256**，链接只在签发响应里出现一次。token 绑定「页面 + 语言 + 视口 + 签发时的草稿版本」：版本不一致返回 409（防止预览到别人还没审阅的稿），改不了语言也改不了视口。
- **预览页**：`/{locale}/preview/{token}` 渲染**草稿**（隐藏区块仍不显示——预览是「发布后会是什么样」，不是编辑器），HTTP 头 `X-Robots-Tag: noindex, nofollow, noarchive` + `Cache-Control: no-store`，且**不加载埋点**：预览访问不进入任何统计。token 不存在、过期、语言与地址不一致都 404，不区分原因。
- **slug 变更 301**：发布时对比每个语言上一次的 `publishedSlug`，不同就登记旧地址 → 新地址（301，`SeoRedirect`），并把原本指向旧地址的记录改为直接指向新地址（少一跳）、移除「从新地址出发」的旧记录（否则会挡住刚上线的页面）。写入后仍解析不出目标（成环/自跳）就删掉这条，保持「旧地址 404」而不是坏跳转。
- **撤下联动**：撤下页面时清理指向它的重定向，避免 301 把访客送到一个已经不存在的地址。
- **重定向管理**：`GET/POST /admin/redirects`、`DELETE /admin/redirects/{id}`（`content.read` / `content.publish`）。只接受站内相对路径（拒协议、域名、`//`、查询串、片段、`%`、反斜杠、空白），自跳、成环、重复登记、遮挡在线页面分别返回 `REDIRECT_SELF` / `REDIRECT_LOOP` / `REDIRECT_EXISTS` / `REDIRECT_SHADOWS_PAGE`。
- **入口层**：参考主题新增 `middleware.ts`，缓存重定向清单 30 秒后本地匹配并回 **301**（不是 308），同时给预览路由补 noindex/no-store 头。清单取不到时直接放行，入口层不能成为单点故障。
- **后台**：内容页每行新增「预览链接」（按当前视口签发，可复制），新增「URL 重定向」面板（清单、自动/手工标记、补登记、删除），错误码映射为可执行的修复提示。

本批未做（第三批）：

- 首页/分类/专题的陈列区块配置（`/admin/merchandising/{pageKey}`，含动态排序、手工优先级与商品资格复验）。
- 文章/公告列表页、`/storefront/collections/{slug}` 专题页、社交分享图字段。
- 重定向的访问量统计与批量导入；目前只记录「从哪到哪」，不统计命中次数。
- 政策文本仍由业主提供并审核，系统不生成法律承诺。

## 第三批实现（2026-11-19）

本批交付首页陈列的配置链路：后台排布区块 → 发布快照 → 前台按快照渲染，并让商品资格在每次读取时重算。分类/专题页的陈列与专题列表页仍留在后续批次。

已实现：

- **版面与草稿分离**：`MerchandisingLayout`（page_key 唯一，本批只开放 `home`）+ `MerchandisingVersion`（发布历史，不可覆盖）。草稿存在 `sections`，线上只读 `publishedSnapshot`，因此保存草稿不会让首页提前变样；撤下只摘掉线上快照，草稿保留可再改再发。
- **区块注册表扩展**：新增 `product_grid`。字段闭集：`section_id`、`visible`、`position`（由数组顺序重排）、`titleByLocale`、`sortMode`、`limit`（1–24）、`productIds`、`categoryIds`。未注册类型、未知字段、含 HTML 标签的标题、未实现的排序方式一律 422，不允许「后台能存、前台不显示」。
- **手工与动态互斥**：`sortMode=manual` 必须给商品清单且数量不少于展示上限，同时不能挂分类筛选；动态模式必须清空手工清单（而不是忽略），否则运营以为手工顺序生效。切换模式时后台自动清空，服务端再兜一层 `MERCHANDISING_MODE_CONFLICT`。
- **发布门槛**：要求每个可见区块在店铺已启用的每种语言下都有标题（`MERCHANDISING_LOCALE_INCOMPLETE`），至少一个可见区块（`MERCHANDISING_NO_VISIBLE_SECTION`），且手工商品在发布这一刻全部可售（`MERCHANDISING_PRODUCT_INELIGIBLE`）。发布同时把快照写入 `MerchandisingVersion` 并推进 `ContentRelease`，区块埋点因此按 `cr-N` 分组。
- **读取时资格复验**：`GET /storefront/merchandising/{pageKey}` 在每次读取时按「已发布 + 当前市场开放 + 市场审核通过 + 可售清单内」重算。动态区块排除不合格商品后由后续候选补足（展示数量维持 limit）；手工区块失效商品直接隐藏，后台 issues 里保留配置并提示替换原因（未上架／未到发布时间／市场不可售／商品已删除）。
- **排序口径（开发规格 5.4）**：新品按首次发布时间倒序；销量取**近 30 天已履约订单件数**并扣减退款退回件数；价格升/降用当前可购买变体最低价，且「无可售变体」永远排最后。所有规则以商品 id 兜底，同值顺序稳定。
- **版本语义**：没有草稿时视作版本 1，首次保存消耗版本 1 并落库为 2；之后保存/发布/撤下都 +1。两人同时首次保存时后到者拿到 409，不会互相覆盖。
- **后台**：`/admin/merchandising`（内容读/写/发布权限分别校验），支持区块增删、上下移、显示/隐藏、三语标题、排序方式与上限、手工商品选择（不可售商品为禁选项并显示原因）、动态候选分类范围、保存/发布/撤下，以及 issues 列表。
- **前台**：首页优先渲染已发布版面（每个区块保留 `data-ez-section`/`data-ez-placement` 埋点字段），没有发布版面或接口不可用时退回主题默认精选——陈列是增强，不能成为首页的单点故障。

本批未做（后续批次）：

- 分类页与专题页的陈列路由（`/admin/merchandising/{category|collection}` 与前台 `/[locale]/categories/{slug}`、`/[locale]/collections/{slug}`）；数据结构已按 `kind` 预留，但本批明确拒绝非 `home` 的 pageKey 与 `collectionId`，不留死配置。
- 文章/公告列表页、社交分享图字段。
- 陈列的定时发布与历史回滚（复用内容页的计划机制前需先定「撤下计划绑定版本」的语义）。
- 重定向命中次数统计与批量导入。

## 第四批实现（2026-11-19）

本批把陈列从首页扩到分类页：分类页有了正式路由，版面按分类绑定，候选商品被限制在该分类内。专题（collection）仍未开放。

已实现：

- **分类页面选择器**：`GET /admin/merchandising/pages` 返回「首页 + 每个启用中的分类」及各自版面状态（`none` 表示还没开始配）。后台 `/admin/merchandising` 的页面下拉直接用这份数据，不再写死只有首页。
- **版面作用域扩到分类**：pageKey 从静态 `home` 扩为 `home | category:<uuid>`（领域 `parseMerchandisingPageKey`）。用分类 **id** 而不是 slug 绑定——分类改名/改 slug 时已发布版面不会失联或指到别的分类。三种失败分开报：`category:not-a-uuid` → 422、`collection:summer` → 422 `MERCHANDISING_PAGE_UNKNOWN`、不存在的分类 → 404。
- **第 32 条迁移**：把 pageKey 的 CHECK 收紧为 `home` 或 `category:<uuid>`，并新增「kind 必须与 pageKey 形状一致」与 kind 闭集约束，杜绝 `kind=category` 但 key 是 home 这类读出来会错位的行。
- **候选池按分类收窄**：分类页读取时把该分类作为页面级范围传进可售查询（`sellableWhere`），动态区块即使不选分类，也只能在这个分类里取商品；区块自己的 `categoryIds` 是在此之上的进一步筛选（与关系，不是或）。
- **手工位必须属于该分类**：保存与发布都会校验，跨分类商品直接 422 `MERCHANDISING_PRODUCT_OUT_OF_SCOPE`。跨分类推荐请用首页版面，不要在分类页混装。后台的商品选择器在分类版面下带 `categoryId` 过滤，选不到范围外的商品。
- **前台分类页**：新增 `GET /storefront/categories/{slug}`，一次返回分类信息、各语言地址、已发布版面区块（含 `contentRelease`）与平铺商品。有可渲染区块就按版面渲染；没发布版面、或发布后所有区块都被隐藏时，退回该分类的平铺商品（最多 60 件）——分类页首先得能逛，版面只是排版方式。
- **分类页路由**：`/[locale]/categories`（索引，只列启用中的分类）与 `/[locale]/categories/{slug}`（详情）。canonical/hreflang 用分类各语言 slug 生成；分类不存在 404、接口不可用时显示「暂时无法加载」且 `noindex`（不让空壳页被收录，也不让已收录页因一次接口抖动消失）。导航、站点地图同步收录分类。
- **埋点**：分类页 `pageKey=category:<slug>`，区块容器带 `data-ez-section`/`data-ez-section-id`，曝光/点击与首页同一套口径。
- **分类 slug 维护（本轮补齐）**：分类页地址来自 `CategoryTranslation.slug`，但后台原来只能建分类、不能编辑。本次在 `/admin/catalog` 的「分类与品牌」里补上分类编辑表单（三语名称 + slug、启用、排序，`If-Match` 带版本）。没有 slug 的分类不会出现在前台分类页、导航与站点地图，列表里直接标「无 slug（前台不可见）」，避免运营以为已经上线。

本批未做（后续批次）：

## 第五批实现（2026-11-20）

本批把「专题」做成独立于分类的策展位：后台挑一组跨分类商品、排好顺序，前台有列表页与详情页，页面可以再套一份陈列版面。专题改 slug 时旧地址 301 到新地址。

已实现：

- **数据模型（第 33 条迁移）**：`Collection` + `CollectionTranslation`（三语名称/slug/简介）+ `CollectionProduct`（有序多对多）。不复用 `ProductCategory`：分类是商品归类的稳定骨架，专题是临时策展，一个商品可以同时出现在多个专题里，专题也可以跨分类。
- **陈列作用域扩到专题**：pageKey 从 `home | category:<uuid>` 扩为 `home | category:<uuid> | collection:<uuid>`；CHECK 约束同批放开，kind 必须与 key 前缀一致。与分类一样用 **id** 绑定，专题改 slug 不会让已发布版面失联。
- **区块级专题筛选**：`collectionId` 从「一律拒绝」改为动态区块的候选筛选（与 `categoryIds` 同层，叠加是「与」关系）。手工区块带专题筛选属于配置冲突（`MERCHANDISING_MODE_CONFLICT`）；在专题 A 的版面里筛专题 B 则直接 `MERCHANDISING_COLLECTION_OUT_OF_SCOPE`——候选交集必然为空，存下来只会变成一个空区块。
- **专题后台**：`/admin/collections`（内容读/写权限）列表、新建、编辑（三语名称/slug/简介、启用、排序、商品清单与顺序）、删除。商品按 id 校验真实存在（`COLLECTION_PRODUCT_NOT_FOUND`），重复商品拒绝而不是静默去重。`If-Match` 版本锁避免双人覆盖。
- **slug 变更 301**：编辑时逐语言比对旧 slug，旧地址 → 新地址登记 301，并把原本指向旧地址的跳转改直。`SeoRedirect` 新增 `collectionId` 归属，停用/删除专题时按归属清理，不会把访客送到一个已经不存在的页面。
- **前台接口**：`GET /storefront/collections`（启用 + 当前语言有 slug + 至少一件当前市场可售商品）与 `GET /storefront/collections/{slug}`（专题信息 + 各语言地址 + 已发布版面或按编排顺序平铺的商品）。没有版面时按运营编排的 `position` 平铺，而不是按创建时间——专题的意义就是「我挑的先后」。
- **前台页面**：`/[locale]/collections`（索引）与 `/[locale]/collections/{slug}`（详情）。canonical/hreflang 用专题各语言 slug；详情 404 时先查已登记的 301（旧地址不猜目标）；导航与站点地图收录专题；埋点 `pageKey=collection:<slug>`，区块容器带 `data-ez-section`。
- **后台交接**：`/admin/merchandising` 的页面下拉自动包含启用中的专题（标为「专题 · 名称」），专题版面下商品选择器按专题收窄，动态区块在专题版面里不再显示范围选择器（候选已锁定）。

本批未做（后续批次）：

- 分类 slug 变更 301：分类编辑入口已有，但还没有像专题那样在改 slug 时登记跳转。
- 陈列与内容页的定时发布、历史回滚。
- 文章/公告列表页与社交分享图字段。
- 专题的手工排序拖拽与批量导入商品。
