# EZSTARTCommerce 完整产品总规格

> 版本：产品基线 1.2  
> 状态：产品及工程共用规则已形成开发基线；目标市场法律规则、第三方服务商和客户专属前台仍需逐客户确认。详见 [开发执行规格](../03-开发文档/DEVELOPMENT_SPEC.md)。  
> 产品模式：可复用的通用电商核心 + 商家管理后台 + 每客户独立私有部署 + 每客户独立定制前台。不是共享 SaaS。

## 1. 产品定义与目标

EZSTARTCommerce 是一套可重复交付的通用电商产品。每家商家得到独立站点、后台、数据库、媒体空间、密钥和备份；商家员工在本店后台管理商品、内容、订单、顾客资料、优惠、库存、交易和报表。顾客通过客户专属前台访客下单。烟草只是首个行业客户案例，核心模型保持通用。

产品目标：

1. 商家无需开发人员日常介入即可维护商品、内容、价格、库存、优惠券和常用店铺设置。
2. 顾客能在品牌化前台完成商品发现、购物车、访客结账和订单结果查看。
3. 交易数据由服务端计算并可审计，订单、付款、履约、退款状态分离。
4. 同一版本核心可重复部署，同时允许客户前台拥有独立页面结构和品牌体验。
5. 运营负责人能查看定义明确的经营报表与网站访问漏斗。
6. 运维人员能升级、备份、恢复和支持各个独立实例，不读取无授权的客户数据。

## 2. 已确认基线与约束

- 不建设共享多租户 SaaS 商户控制台、跨店经营总览或平台订阅账单。
- 默认一商家、一站点、一独立实例；同一商家多站点另行配置为多实例。
- 访客购物和结账始终可用，不强制注册或登录。
- 会员能力纳入首期：后台档案、订单关联、等级、积分流水/规则、权益与优惠券关联、同意记录及自愿验证码会员中心；不使用密码。
- 简体中文、繁体中文、英文是首期前后台语言需求；具体商品翻译由商家提供。
- 商品和内容由后台维护；客户前台的页面结构、视觉和独有互动按客户独立开发。
- 后台支持货到付款，并通过适配器配置经商家及服务商批准的线上支付方式。
- 支持商品批量导入、优惠券创建/发放/核销、库存预警、报表与网站分析。
- 参考网站仅作为业务和视觉参考，不假定能访问其管理后台、源代码或数据库。
- 目标市场、产品准入、年龄/资格限制、广告、支付、税务及物流规则由商家负责确认，系统提供配置和执行机制。

## 3. 用户、角色与需求

| 用户 | 主要目标 | 常用能力 |
|---|---|---|
| 商家负责人 | 开店、看经营表现、控制风险 | 初始化、员工权限、付款/配送设置、报表、审计 |
| 店铺管理员 | 日常运营 | 商品、内容、订单、促销、库存和通知 |
| 商品运营 | 快速准确上架 | 商品编辑、多语言、规格、图片、批量导入 |
| 订单/客服人员 | 正确处理订单及售后 | 订单详情、联系资料、状态、发货、售后案件 |
| 财务人员 | 核对收款和退款 | 付款交易、退款、对账导出、相关审计 |
| 分析人员 | 了解经营表现 | 聚合报表、访问漏斗、受限导出 |
| 授权运维 | 交付和维护独立实例 | 部署、升级、备份恢复、健康检查、支持访问审计 |
| 顾客/会员 | 访客下单，会员自愿查看权益 | 浏览/搜索、购物袋、优惠、访客结账、OTP 会员中心 |

员工角色按最小权限原则配置。查看/导出个人资料、退款、改价、库存调整、权限管理和生产运维是分开的授权动作。

## 4. 产品范围

### 4.1 首期 P0 核心能力

- 独立实例开通、配置、数据隔离、备份、恢复和版本升级。
- 后台登录、员工、角色、权限、审计。
- 店铺品牌、语言、地区、货币、时区、市场和功能配置。
- 商品、变体/SKU、分类、品牌、属性、图片、翻译、上下架。
- 商品 CSV/XLSX 导入预览、字段映射、校验、执行和错误报告。
- 内容页、FAQ、公告、导航和主题支持的首页/专题商品陈列配置；商家可选择商品、排序区块和商品优先级，预览并发布到前台。
- 客户专属前台：按单独页面清单实现首页、分类、搜索、商品详情、购物袋、访客结账、会员入口/中心、结果页和政策内容。
- 商品检索、访客购物会话、服务端价格/库存/优惠/运费复核和幂等下单。
- 货到付款；至少一类获批线上支付方式的适配能力，接入范围取决于服务商账户及审批。
- 订单、付款、履约状态拆分；订单确认、处理、取消、发货和完成。
- 配送区域、费率、免邮门槛的基础配置；未接物流时允许人工录入单包裹/分批包裹运单信息。
- 顾客/会员档案、OTP 会员中心、等级/积分流水与规则、权益配置和营销同意记录。
- 优惠券创建、启停、发放/导入、限制条件、核销记录。
- SKU 库存、流水、预留、低库存阈值和预警。
- 订单及交易通知模板、发送日志、失败重试。
- 经营报表、匿名网站事件和转化漏斗、CSV/XLSX 导出。
- 基础售后记录：取消、全额/部分退款、退货/换货案件人工跟踪；退款 API 能力以已批准的服务商接口为准。
- 交易对账：导入支付服务商结算文件、匹配内部支付/退款台账、展示差异并留审计记录；具体 API 自动对账按服务商能力另行确认。
- 多语言、响应式、无数据/错误/权限不足、会员验证码和付款状态等页面验收。

### 4.2 P1 条件能力

- 顾客无需账号的安全订单查询，以及前台提交售后申请入口；需确定邮箱/短信验证方式和服务费用。
- 物流商 API、运单打印、物流轨迹自动回传；手工录入的分批发货仍属于 P0。
- 跨店积分、高级营销自动化、自定义会员权益脚本及会员 App；首期会员中心不支持跨商家账户。
- 多仓、采购单、批次/效期、自动补货。
- 高级营销自动化、复杂归因、外部 BI。
- 多币种结算、税务引擎、电子发票和会计/ERP 集成。
- 客户自助拖拽建站器、客户差异后台代码插件。
- 统一运维控制台和跨客户集中数据管理。

### 4.3 明确不包含

SaaS 多租户控制面、跨商户数据池、客户原站数据迁移、强制注册或密码式顾客账号、未经审批的支付/行业销售规则、移动 App、复杂 ERP、自动法律合规判断，以及未在具体客户清单中的定制页面和专有集成。

## 7. 核心领域规则

### 7.1 商品与多语言

产品、变体和商品文案分离；每个商品/变体具有稳定内部 ID 与 SKU。商品发布按语言完整度策略校验；缺译如何回退由实例配置。订单行快照在商品后续改名或改价后仍可还原。

### 7.2 访客 CRM 与会员

访客可完成全流程购物/结账；会员可用已验证邮箱的一次性验证码登录会员中心，不设密码。后台管理会员等级、积分流水、规则和权益。手机号验证码需配置获批的短信服务。订单与会员仅按已验证联系方式关联，不按姓名自动合并；营销同意与交易联系分开记录。

### 7.3 价格、促销和库存

服务端重算价格、优惠、税费/配送费；以事务或原子方式预留库存；重复下单/回调使用幂等键。库存变化以不可改写流水追踪。价格币种、税费、优惠叠加、库存预留时点须实例配置和需求冻结。

### 7.4 订单、付款和履约

订单、付款、发货、售后分别有状态机。支付成功必须由已验签的服务端回调或渠道主动查询确认。浏览器回跳不构成到账证明。COD 的签收和收款分别记录。

### 7.5 售后与退款

售后案件关联原订单行和支付流水。先记录申请与审核，再按实际收款情况执行退款。退款金额不得超过可退实收金额；每笔退款记录操作者、原因、渠道号和结果。退回商品只有在收货检查后才能选择入可售、损坏、冻结或报废库存。

### 7.6 数据统计

经营收入以订单、实收付款和退款流水为依据；网站分析以匿名事件为依据。两者不能混用。每个指标标明时区、币种、退款处理、有效订单范围和最后更新时间。

P1 增强：按前台页面/区块统计曝光、点击、加购、已提交订单与净实收金额。所有客户定制前台接入统一事件契约，以稳定区块标识和发布版本查看表现；预览、员工、沙箱和测试数据排除。区块交互通过匿名 placement/interaction 标识与购物袋及订单行关联，不采集顾客个人资料；订单归因按订单行计数。净实收仅按商品行优惠分摊后的已收款减关联成功退款计算，COD 收款后计入；财务现金流仍以支付、COD 收款和退款账本按实际发生日期统计。采集缺失需显示状态，不得将未知数据显示为零。该报表用于比较陈列效果，不替代经营总览；详细埋点、归因、时间及导出口径见 M14。

## 8. 关键用户流程

### 开店与上线
独立部署 → 初始化店铺 → 安全配置和品牌资料 → 配置市场/付款/配送/通知 → 商品导入和校验 → 前台预览 → 测试订单/退款 → 备份恢复及升级检查 → 上线。

### 上架商品
建草稿 → 填 SKU/规格/价格/库存 → 维护三语和媒体 → 预览 → 校验 → 发布 → 前台验证。

### 访客下单
浏览/搜索 → 选择 SKU → 购物袋 → 服务端报价与优惠检查 → 联系/配送资料 → 付款选择 → 服务端建单/库存预留 → 订单结果 → 商家履约。

### 订单履约
新订单队列 → 审核付款与地址 → 备货拣货 → 发货/录入物流 → 签收或异常 → 完成/跟进。

### 售后
顾客联系或经验证入口提出 → 客服核实订单/付款/履约 → 审核与记录原因 → 退货收件（若需要）→ 质量检查 → 执行/确认退款或补发 → 更新库存/指标 → 通知顾客并关闭案件。

## 9. 页面、交互与视觉基线

- 以“交易信息清楚、主操作明确、异常可恢复”为原则；前台可按客户视觉主题独立实现。
- 后台采用稳定导航、列表/表单/详情一致模式；危险操作确认、结果可追溯。
- 每页都要给加载、空结果、校验错误、服务失败、权限不足和保存成功状态。
- 简体/繁体/英文需要分别验证长标题、金额、地址和按钮溢出；日期和货币按实例配置。
- 键盘操作、焦点顺序、表单标签、颜色对比、替代文本和触控尺寸纳入验收。
- 商品、图片、政策和金额为业务数据；前台布局、专属互动和品牌叙事为客户项目设计资产。
- 示例品牌、产品、金额和图像仅作原型占位，不得作为生产默认内容。

页面和模块完整产品设计文件见 docs/design/README.md；视觉方向样稿见 docs/design/prototype/。

## 10. 技术和数据架构

推荐首期使用模块化单体、独立后台 UI、独立客户前台应用、版本化 REST/OpenAPI、关系型主库、后台 worker、对象存储及可重复部署包。每商家一套应用/数据库/媒体/密钥/备份。按实际瓶颈演进，不在首期提前拆分微服务。

技术选型候选见 PRODUCT_TECHNICAL_BLUEPRINT.md 与 ARCHITECTURE.md。必须遵守：

- Storefront API 与 Admin API 分域鉴权、限流、审计。
- 订单保存商品/地址/金额/付款/配送快照；货币金额用最小单位整数。
- 支付 webhook、建单、退款、库存变更、批量导入均定义幂等。
- 顾客敏感资料最小化访问、日志脱敏、实例备份加密。
- 迁移脚本有版本、可预演；前台 API 有兼容策略。
- 商家配置和业务数据不被核心升级覆盖；客户前台独立版本发布。

## 11. 安全、隐私与非功能要求

所有目标需按托管/自托管形态和合同确定。建议在需求冻结时采用以下起始验收目标：

| 类别 | 规划基线 | 验收证据 |
|---|---|---|
| 性能 | 约定设备/网络/数据规模下，目录/商品页移动端主要内容 2.5 秒内呈现；内部关键 API p95 不高于 800ms，第三方付款/短信耗时单独计 | 记录环境、样本和关键接口时延 |
| 可用性 | 托管实例目标月可用性 99.5%；客户自托管受客户资源及网络影响，单独界定 | 健康检查和故障记录 |
| 备份 | 每日自动备份，保留期限可配置；起始目标 RPO 24 小时、RTO 8 小时 | 隔离环境恢复记录 |
| 账户安全 | 管理员 RBAC；高权限角色 MFA；登录限速；退款/导出等敏感动作审计 | 权限矩阵和操作日志演示 |
| 数据保护 | TLS；加密备份；密钥不进代码仓库/普通日志；不存卡号/CVV | 配置检查与日志抽查 |
| 可靠性 | 订单、支付、退款、导入、通知支持幂等或安全重试；外部服务失败不丢订单 | 重复/超时场景验收记录 |
| 隐私 | 事件不含姓名、邮箱、电话、地址；联系履约与营销同意分开 | 事件字段检查 |
| 可维护性 | 版本化迁移、升级预检、健康检查、恢复和回滚手册 | 版本升级演练 |
| 可访问性 | 键盘可操作、字段有标签、错误与控件关联、非颜色单独表达状态 | 页面检查清单 |

这些数值是规划目标，不是已经签署的 SLA；需与托管责任、容量、预算和目标市场确认后冻结。

## 12. 验收门槛与交付物

### 产品验收门槛

1. 新实例可按手册独立部署两份，业务数据、管理员、媒体和密钥相互隔离。
2. 商家可自助创建/导入商品，维护三语内容并预览前台。
3. 顾客可以访客完成从商品浏览到货到付款或获批线上支付订单；会员 OTP 登录为自愿流程。
4. 后台能查看订单、付款、履约和审计历史；状态合法且订单快照准确。
5. 优惠和库存服务端校验，重复建单/支付回调不造成重复订单或扣款。
6. 优惠券可创建、发放、限制使用并查核销记录。
7. 库存流水、低库存预警和处理状态可追踪。
8. 顾客可访客结账；会员可自愿验证码登录，等级/积分/优惠和订单摘要准确；同意、验证和积分流水可审计。
9. 售后案件可关联原订单，支持取消、退款记录、退货/换货跟踪和库存处置。
10. 报表明确口径并与交易数据核对；访问漏斗不包含个人资料。
11. 失败通知、导入失败、支付延迟和备份恢复均有可诊断状态。
12. 三语、移动端、权限、空态、异常态、备份和上线清单通过评审。
13. 支付结算文件导入可幂等匹配；差异有分类、处理原因和审计，不自动改写交易事实。
14. 订单可按商品数量分包发货；库存只扣已发数量；支付状态未知时保留库存并进入待处理。
15. 后台主题陈列配置发布后同步手机/桌面前台，排序/置顶正确且未发布/不可售商品不能绕过服务端规则。
16. 交易、权限、隐私、运维、商品陈列、访客/会员、优惠/通知及数据交接场景通过 [生产就绪清单](../04-测试文档/PRODUCTION_READINESS_ACCEPTANCE.md)。
17. 可选会员认证、优惠额度预占/返还、通知幂等、客户数据导出/停用按对应模块与客户上线参数验收。
18. SEO 元数据、语言 URL、索引控制与 slug 重定向通过验收；个人资料请求经身份核验、授权处理、记录保留例外并按客户批准时限闭环。
