# EZSTARTCommerce 客户前台定制方案

## 1. 已确认的交付模式

EZSTARTCommerce 不作为共享 SaaS 平台运营。交付给不同客户时，为每个客户单独部署一套站点和后台，并按该客户业务单独设计、开发前台页面与交互。

产品拆为两部分：

1. **可复用电商核心与管理后台：**商品、分类、规格、订单、付款、配送、优惠券、会员客户资料、库存、通知、报表、内容管理和配置能力。
2. **客户专属前台：**该客户的品牌视觉、页面结构、商品展示方式、促销落地页、购物流程和专属交互。

客户之间不共享前台部署、商品/订单数据、管理员账号、第三方服务凭证或分析数据。

## 2. 客户前台定制层级

### A. 内容配置
适用于页面结构与标准组件相同，只需要客户维护标志、图片、文字、颜色、导航和商品资料的情况。

### B. 视觉定制
适用于页面结构大致相同，但需要不同设计系统、首页布局、商品卡片、详情页样式和移动端视觉。

### C. 页面/流程定制开发
适用于客户有不同的信息架构、产品筛选/选购流程、商品详情组件、落地页、促销规则展示或业务交互。需要独立原型、前端实现、接口联调和验收。

**烟草示例站按 C 类客户项目评估**：它可作为该客户的品牌前台案例，但不能假设其他客户也使用相同页面。模板仍提供通用后台和交易核心。

## 3. 推荐技术边界

- 建立稳定、版本化的电商 API 契约，前台通过 API 调用商品、价格、库存、购物车、优惠、配送和订单功能。
- 管理后台尽量使用共享的通用版本；前台按客户分别构建和部署。
- 共用商品、购物车、结账和订单规则，避免客户前端自行计算交易金额。
- 每个客户前端可有独立源码包/代码目录和发布版本；共享核心按明确版本依赖。
- 客户专属页面放在前端扩展层，通用能力回收到核心或可复用组件库。
- 每家私有部署仍有独立应用环境、数据库、媒体空间、密钥、域名和备份。
- 不建设 SaaS 商户总控台、共享租户数据库或跨店运营后台。

具体采用同一代码仓库内多个 storefront 包，还是每客户独立仓库，须根据源码访问权限、客户是否需要自维护和升级策略决定。

## 4. 每个客户项目的交付流程

1. **业务发现：**了解客户商品类型、顾客群、市场、语言、付款、配送和售后流程。
2. **页面盘点：**建立站点地图、页面清单、组件清单及访客购买流程。
3. **原型与视觉确认：**交付首页、分类、商品详情、购物车、结账和关键专题页原型。
4. **定制开发：**在客户前端实现视觉、页面、交互和内容结构。
5. **核心接口联调：**连接该客户独立后台的商品、库存、优惠券、配送、付款及订单 API。
6. **验收：**按客户批准的设计稿和验收流程检查桌面/移动端、三语、订单金额及边界状态。
7. **独立部署：**配置该客户域名、HTTPS、数据库/媒体、第三方凭证、备份和监控。
8. **交接与维护：**交付客户版本号、定制清单、运维说明及升级兼容性。


### 客户页面清单基线

每个客户至少评审以下页面是否适用：主页、分类列表、搜索结果、商品详情、购物袋、结账、订单结果、政策/内容、会员验证码入口与会员中心、订单查询、售后申请、资格提示、404/维护。页面增删不默认为同一价；逐页注明桌面/移动端布局、简繁英内容、数据接口和审核人。

每页的状态至少列出：加载、正常、空数据、字段错误、接口失败、库存/价格变化、不可售/不可配送。支付还要有待处理、成功、失败和回调延迟；会员 OTP 还要有发送中、成功、错误、过期和限流。

客户确认物应包含：站点地图、低/高保真稿、品牌素材清单、商品图片授权、三语文案责任、接口清单、状态矩阵、响应式验收视口、浏览器范围、页面验收签字和变更流程。
## 5. 客户定制工作量评估因素

每个客户的前端需单独估算，不能简单套用模板核心的固定人日。评估至少包括：

- 页面数量与每页独特程度。
- 是否有线框/视觉设计，是否由我方提供。
- 商品类型、规格复杂度、筛选/搜索需求。
- 顾客结账流程和促销展示差异。
- 语言数量和翻译资料完整度。
- 移动端适配、动画、可访问性和 SEO 需求。
- 外部支付、物流、客服、营销或数据分析接口。
- 内容迁移/录入和图片处理。
- 客户审稿轮次、验收设备/浏览器和上线支持。

报价应拆成：通用核心/后台模板成本、每客户前台设计与开发成本、独立部署与迁移成本、持续维护/升级费用。

## 6. 变更与版本治理

- 客户已确认的页面清单、原型和验收条件作为项目范围基线。
- 超出基线的页面、交互、语言、接口或规则通过变更单重新估算。
- 核心后台和 API 使用语义版本或兼容版本；客户前端锁定已验收的 API 版本。
- 核心升级先在客户测试环境验证前台兼容，再发布到该客户生产环境。
- 客户专属实现不随核心模板自动复制给其他客户。
- 维护通用产品时，优先用配置、公共组件或稳定扩展接口，避免核心代码逐客户分叉。
- 合同需明确源码/IP归属、可否由客户自行修改、升级支持期限和定制代码维护责任。

## 7. 验收条件

- 客户前台按其已批准的站点地图、设计稿和页面清单实现。
- 每个页面与交互可以调用该客户独立后台数据。
- 客户之间的域名、前台内容、商品、订单、顾客、后台账号、密钥和分析数据完全独立。
- 核心交易校验在服务端完成，定制前端不能绕过价格、库存、优惠、付款或目标市场的规则。
- 客户专属修改不会意外更改其他客户的前台。
- 记录前端版本、核心/API版本及兼容关系，升级前可验证和回滚。

## 8. 本项目不包含

- SaaS 自助建站控制台和多商户统一后台。
- 将一个客户的定制页面自动发布给其他客户。
- 未确认页面清单之前的客户专属前端定制报价。
- 自动复制或抓取参考网站的代码、图片和商品数据库。
