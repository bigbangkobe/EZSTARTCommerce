# EZSTARTCommerce 客户前台定制方案（配置驱动）

> 重做基线：前台定制方式已从「每客户独立开发」改为「配置驱动、A 类为默认」。
> 完整方案与代码改造清单见 [配置化前台与交付体系重做方案](../06-产品设计逻辑/03-配置化前台与交付体系重做方案.md)。

## 1. 已确认的交付模式

EZSTARTCommerce 不作为共享 SaaS 平台运营。交付给不同客户时，为每个客户单独部署一套站点和后台，前台由**实例配置生成**——品牌、配色、字体、首页区块编排、文案和模块开关全部可配置，换客户无需前端开发。

产品拆为两部分：

1. **可复用电商核心与管理后台：**商品、分类、规格、订单、付款、配送、优惠券、会员客户资料、库存、通知、报表、内容管理和配置能力。
2. **配置驱动前台：**由一份实例配置渲染出该客户的品牌视觉、首页结构、商品展示与购买文案；配置覆盖不了的独特页面与交互，按例外定制。

客户之间不共享前台部署、商品/订单数据、管理员账号、第三方服务凭证或分析数据。

## 2. 客户前台定制层级（A 类为默认）

### A. 配置级（默认路径，无需前端开发）
适用于绝大多数客户。可配置项：

- **品牌**：Logo、品牌名、品牌别名、标语、favicon
- **视觉**：主色/文字色/背景色、字体组合、圆角等 design tokens
- **结构**：首页区块类型、顺序、显隐与参数（由声明式区块注册表驱动）
- **内容**：三语文案、政策页、客服信息、WhatsApp
- **商品陈列**：首页/分类/专题的版面与商品排序（已有 `MerchandisingLayout`）
- **开关**：语言、货币、市场、功能模块

交付动作：**填实例配置 → 标准部署 → 上线**。标准报价，目标上线周期由团队确认。

### B. 视觉级（例外，单独报价）
适用于需要全新设计系统、定制组件样式或独特动效，但页面结构与流程仍沿用的客户。交付动作：配置 + 主题包开发。

### C. 工程级（例外，单独报价）
适用于客户有不同信息架构、专属选购流程、定制商品详情组件、复杂促销展示或业务交互。需要独立原型、前端实现、接口联调和验收。

**判定原则：先尝试用 A 类配置表达；表达不了再评估 B；涉及新页面/流程才是 C。** 首个烟草客户应按此原则重新评估——优先配置化，只有确有独特需求的部分才走例外。

## 3. 配置引擎技术边界

- 建立并冻结稳定、版本化的电商 API 契约；前台通过 API 调用商品、价格、库存、购物车、优惠、配送和订单功能。
- **主题配置独立持久化**（ThemeConfig，草稿 → 发布快照 → 版本），前台读取已发布快照；未发布/接口不可用回退默认主题，配置不是单点故障。
- **声明式区块注册表**：每个区块声明 `{type, 字段 schema, 默认参数}`；后台表单由注册表驱动，新增区块类型后台自动适配。首期区块：`hero`、`about`、`product_grid`、`rich_text`、`faq`、`content_card`。
- 共用商品、购物车、结账和订单规则，避免客户前端自行计算交易金额（资金底线不变）。
- **实例配置与代码分离**：配置不写进源码，升级不覆盖客户配置。
- 每家私有部署仍有独立应用环境、数据库、媒体空间、密钥、域名和备份。
- 不建设 SaaS 商户总控台、共享租户数据库或跨店运营后台。

## 4. 每个客户项目的交付流程

### A 类标准交付（默认）
1. **填写实例配置**：品牌素材、配色、字体、首页区块、三语文案、市场/支付/配送参数（一份机器可读配置源，见 [实例配置规范](../01-产品文档/INSTANCE_CONFIG_SPEC.md)）。
2. **配置校验**：schema 校验 + 上线阻断项检查（市场/支付/隐私责任人等）。
3. **标准部署**：一键拉起独立实例，初始化 StoreConfig/ThemeConfig，导入配置。
4. **冒烟验收**：核对品牌/区块/文案展示、桌面/移动端、三语、交易金额与边界状态。
5. **交接与维护**：交付配置版本、实例版本与升级说明。

### B/C 类例外交付（单独报价）
在 A 类基础上增加：业务发现 → 页面盘点 → 原型与视觉确认 → 定制开发/主题包 → 接口联调 → 扩展验收。

### 客户页面清单基线
每个客户至少评审以下页面是否适用：主页、分类列表、搜索结果、商品详情、购物袋、结账、订单结果、政策/内容、会员验证码入口与会员中心、订单查询、售后申请、资格提示、404/维护。每页状态至少列出：加载、正常、空数据、字段错误、接口失败、库存/价格变化、不可售/不可配送；支付另列待处理/成功/失败/回调延迟；会员 OTP 另列发送中/成功/错误/过期/限流。

## 5. 客户定制工作量评估因素

A 类按标准配置报价；B/C 类单独估算，评估因素包括：

- 页面数量与每页独特程度，是否超出区块注册表能力。
- 是否提供视觉设计，是否需我方设计。
- 商品类型、规格复杂度、筛选/搜索需求。
- 顾客结账流程和促销展示差异。
- 语言数量与翻译资料完整度。
- 移动端适配、动画、可访问性和 SEO 需求。
- 外部支付、物流、客服、营销或数据分析接口。
- 内容迁移/录入和图片处理。
- 客户审稿轮次、验收设备/浏览器和上线支持。

报价结构见 [商业分层与报价模型](COMMERCIAL_MODEL.md)。

## 6. 变更与版本治理

- 实例配置版本化，每次变更可追溯、可回滚；配置与代码版本分别记录。
- 主题配置沿用草稿 → 发布 → 撤下三段式，发布生成不可变快照与版本号；升级前在测试环境验证，生产可一键回滚。
- 核心后台和 API 使用语义版本；前台锁定已验收的 API 与区块注册表版本。
- 超出 A 类配置能力的页面、交互、语言、接口或规则通过变更单按 B/C 类重新估算。
- 客户专属实现不随核心模板自动复制给其他客户；维护通用产品时，优先把能力沉淀进配置或公共区块，避免核心代码逐客户分叉。
- 合同明确源码/IP 归属、配置资产归属、可否由客户自行修改、升级支持期限和定制代码维护责任。

## 7. 验收条件

- 客户前台按已批准的实例配置生成，品牌/区块/文案/开关与配置一致。
- 换品牌/配色/首页布局**无需改代码、无需重新构建**；主题发布可回滚。
- 每个页面与交互可调用该客户独立后台数据。
- 客户之间的域名、前台内容、商品、订单、顾客、后台账号、密钥和分析数据完全独立。
- 核心交易校验在服务端完成，配置化前端不能绕过价格、库存、优惠、付款或目标市场规则。
- 记录前端版本、主题/API 版本及兼容关系，升级前可验证和回滚。

## 8. 本项目不包含

- SaaS 自助建站控制台和多商户统一后台。
- 将一个客户的定制页面或配置自动复制给其他客户。
- 万能拖拽式页面构建器（首期为声明式区块注册表）。
- 未确认配置与页面清单之前的客户专属报价。
- 自动复制或抓取参考网站的代码、图片和商品数据库。

> 本方案为产品设计参考，具体实施请结合公司合规与法务要求确认。
