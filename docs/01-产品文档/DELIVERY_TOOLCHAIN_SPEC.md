# 交付工具链规范

> 状态：设计基线 v1.0（已定稿，P4 已落地）
> 定位：用标准部署包 + 一键起实例 + 批量升级，把交付从"人工 8 步"变成"配置 + 一键"，且不需要 SaaS 中控。
> 关联：[私有部署模式](../05-部署运维文档/PRIVATE_DEPLOYMENT.md) · [重做方案](../06-产品设计逻辑/03-配置化前台与交付体系重做方案.md)

## 1. 设计原则

- **不集中任何客户数据**：工具链在交付方本地或客户实例内执行，不做跨店数据中台。
- **配置与代码分离**：版本化镜像不包含客户配置；客户配置由实例配置源注入。
- **可重复、可回滚**：起实例、升级、恢复都是脚本化、可演练、可回滚的。

## 2. 标准部署包

一个版本化的交付制品，包含：

| 组成 | 内容 |
|---|---|
| 应用镜像 | api / admin / worker / storefront 四个版本化容器镜像 |
| Compose 模板 | 编排与网络/卷定义，参数由环境变量注入 |
| Migration runner | 按版本执行数据库迁移，支持幂等与回滚检查 |
| 初始化脚本 | 读实例配置，初始化 StoreConfig/ThemeConfig/管理员 |
| 健康检查 | 存活/就绪探针，数据库未就绪不对外服务 |

## 3. 一键起实例

命令形态（示意）：`ezstart init --config instance.yaml`

流程：
1. 校验实例配置（schema + 上线阻断项），不通过则拒绝。
2. 生成 `.env`（密钥不写进配置文件，安全注入）。
3. 拉取对应版本镜像，启动全家桶。
4. 执行 migration + 初始化（StoreConfig/ThemeConfig + 首管理员）。
5. 导入品牌/主题配置，前台按配置渲染。
6. 跑冒烟测试（首页、商品、访客下单、后台登录）。
7. 输出交付清单：版本、配置哈希、备份点、访问地址。

## 4. 批量升级

- **版本清单**：记录每个实例当前 `core / theme-schema / 配置` 版本。
- **兼容性检查**：升级前核对 API 契约版本与主题 schema 版本兼容。
- **逐实例执行**：备份 → 拉取新镜像 → migration → 验证 → 切换 → 冒烟；任一失败自动回滚。
- **分组发布**：先测试实例、再小批、再全量；不强制同时升级所有客户。
- **无中控**：升级脚本在交付方侧逐实例执行，或用客户侧运维代理执行，客户数据不回传。

## 5. 轻量运维代理（可选）

装在客户实例内，职责限于：

- 监控与健康状态上报（不含业务数据）。
- 备份调度与恢复演练记录。
- 日志采集（脱敏）与告警转发。
- 接受升级指令并执行（客户授权范围内）。

客户数据不出内网；上报内容与授权范围写入服务协议。

## 6. 回滚与恢复

- 每次升级/发布前自动备份数据库与媒体。
- 主题配置回滚走 ThemeConfig 版本快照（见前台配置引擎规格）。
- 版本回滚：切回上一版本镜像 + 对应 migration 回滚脚本。
- 定期做空环境恢复演练，作为交付验收项。

## 7. 与现有资产的关系

- 复用现有 `IMPLEMENTATION_PROGRESS` 的部署/升级/回滚要求与 `PRIVATE_DEPLOYMENT` 的隔离规则。
- 工具链是"把已有规范脚本化"，不改变独立部署与数据隔离边界。

## 8. 落地状态（P4 已实现）

以下为已落地的可运行最小闭环，规则层在 `packages/domain`，IO 在 `scripts`，模板由 mrinhk 生产资产参数化而来。

| 能力 | 入口 | 产物 |
|---|---|---|
| 标准部署包 | `pnpm instance:bundle <instance.yaml> [--out <dir>] [--require-launch-ready]` | 7 件制品（compose / Caddyfile / env 模板 / deploy.sh / DEPLOY.md / 归一化配置 / 包清单） |
| 一键起实例 | `pnpm instance:init <instance.yaml> [--execute] [--scaffold]` | 生成包 + 注入 `.env`（chmod 600）；默认 dry-run，生产交付强制校验 10 项上线签字 |
| 批量升级 | `pnpm fleet:upgrade <inventory.yaml> <version> [--execute]` | 按 pilot→canary→standard 输出计划；跨 major / 降级 / schema 未确认一律阻断 |

关联文件：

- 规则层：`packages/domain/src/deployment.ts`（闭集、版本兼容、分组计划、包完整性）
- 模板：`deploy/templates/instance/*.tpl`（参数化自 mrinhk 已验证资产，LF 行尾）
- 版本清单示例：`deploy/instances.yaml`
- 测试：`tests/deployment.test.ts`（10 项，含 major 阻断、降级阻断、主题迁移确认、分组顺序）

### 安全与边界

- `.env` 密钥由 CLI 本地生成（密码 / UUID / 32 字节加密密钥），只登记键名不写值；已存在则拒绝覆盖。
- 目标目录非空时默认拒绝生成，保护现有生产实例；仅显式 `--force` 才重建包（`.env` 仍受独立保护）。
- `--execute` 才调用 docker；批量升级失败即停并提示 `deploy.sh --rollback`，数据库迁移只前进。
- 所有判断在 domain 规则层，脚本只做 IO，避免"脚本说能升、运行时拒绝"的规则漂移。
