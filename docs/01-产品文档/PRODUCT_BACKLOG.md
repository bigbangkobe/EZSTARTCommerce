# EZSTARTCommerce 研发待办与发布切分

> 作用：把完整产品总规格拆为可按模块推进的交付批次。它不是最终 Jira 工单；产品/工程共用基线已见 [开发执行规格](../03-开发文档/DEVELOPMENT_SPEC.md)，开发团队仍需拆解为团队实际任务；逐店经营参数由客户上线表冻结。

2026-10-19 实施状态：[R1 工程说明](../03-开发文档/R1_ENGINEERING_PROGRESS.md) 与 [身份实现说明](../03-开发文档/R1_IDENTITY_IMPLEMENTATION.md) 已登记数据库迁移、首店主/MFA/本人会话 API 及真实数据库校验证据；员工邀请/找回/通知、后台页面及实例交付仍未完成，R1 门槛保持未通过。

## 1. 发布策略

| 批次 | 目标 | 包含范围 | 通过门槛 |
|---|---|---|---|
| R0 范围冻结 | 降低返工 | 市场/合规责任、会员规则/OTP 服务商、支付与结算输入、税务/配送/分批发货参数、售后政策、隐私请求与留存期限、SEO/URL 策略、运维责任、首店主题区块目录和专属前台页面清单 | 每项客户参数有负责人、选项、验收口径和阻断条件；缺少的外部凭证/审核不阻断独立的模板基础开发，但对应交易功能保持关闭 |
| R1 独立实例与后台框架 | 使产品可安装和管理 | M00、M01、M15 基础；配置、审计、RBAC/MFA、备份骨架 | 从空环境重复开两套隔离实例，管理员权限/MFA可验收 |
| R2 商品运营 | 商家能配置前台数据 | M03、M04、M05、M02 Storefront API/预览 | 商品/翻译/媒体可维护并导入；后台陈列配置可预览发布并同步桌面/手机前台 |
| R3 交易闭环 | 顾客可完成订单 | M06、M07、M08 COD及获批线上渠道、M09人工配送/分批发货、M12限时库存预留、M13交易通知 | 顾客访客下单；后台可处理；金额/库存/付款/履约状态可追踪；支付状态未知不错误释放库存 |
| R4 商家运营 | 支持日常增长与客服 | M08结算对账、M10会员运营、M11优惠券、M12预警、M13模板/重试、M14报表、M16售后基础 | 核心运营动作及审计可完成；对账差异可解释；指标与业务台账核对 |
| R5 首个客户前台 | 用真实品牌/交互上线 | 客户专属页面、内容/商品导入、API 联调、市场/服务审批、上线验收 | 通过该客户单独签署的页面清单和流程验收 |
| R6 复制交付 | 证明模板可复用 | 第二实例开通、配置迁移、升级、备份/恢复和交接 | 新客户不依赖首客户生产数据或手工改代码 |

R1–R4 属于模板核心；R5 是客户项目，应单独估算视觉、页面、内容和差异集成。

R0 的客户经营参数不齐时，仍可并行开展 M15 实例骨架、M00 后台身份和 M01 基础店铺配置等不依赖该参数的工作；涉及交易规则、敏感个人资料处理和客户专属页面的模块，须先冻结其输入与验收口径。

## 2. Epic 清单与依赖

> 依赖列表示模块间需要冻结的数据/API/事件契约，不等同于严格的先后排期。R3 的结账、订单、付款、配送、库存与通知必须先冻结共同契约，再按端到端交易流程集成验收；优惠券引擎可并行开发，按契约接入。M15 的实例初始化/部署骨架先于业务开发，完整升级、恢复与退出交接在 R6 跨模块验收。

| Epic | 主要交付 | 可验收结果 | 依赖 |
|---|---|---|---|
| M00 管理身份 | 登录、员工、角色、最小权限、MFA、会话撤销、受限审计日志 | 不同角色只能执行获准操作；权限收紧/停用后立即生效；店主/管理员强制 MFA；审计不可由普通后台编辑/删除；高风险动作可追溯 | M15 基础环境 |
| M01 店铺配置 | 品牌、语言、地区/市场、币种、时区和开店向导 | 后台保存后前台按实例设置展示；未审核市场可阻止交易 | M00 |
| M02 前台接入 | 独立前台基线、预览、Storefront API、可索引输出/域名路由 | 前台不直连数据库；客户可独立发布并消费版本化 API；canonical/多语言 alternate/sitemap/robots 与草稿 noindex 可验收 | M01、M03 |
| M03 商品目录 | 商品、SKU/变体、分类、品牌、属性、媒体、简/繁/英资料 | 必需语言文案完整才可按规则发布；订单保留当时商品/语言/价格快照 | M00、M01、媒体存储 |
| M04 内容管理 | 页面、导航、FAQ、公告、三语 SEO、slug 重定向、主题区块陈列和商品优先级 | 内容/陈列可草稿、桌面/手机预览、发布/撤回；slug 更新有安全重定向；草稿/预览不入索引；商品与区块排序按配置同步前台 | M01、M00、M02、M03 |
| M05 导入导出 | 模板、字段映射、预览、行级校验、部分有效/整批原子执行、错误报告、受控导出 | 执行策略明确；重复/冲突 SKU 不误改；中断可幂等续跑；库存变化走库存账目；远程图片受安全限制；导出有权限/过期控制 | M03、M00、M12、M15 |
| M06 购物与结账 | 访客会话、购物袋、价格重算、优惠/运费报价、可选会员权益和幂等下单 | 不登录也可完整结账；会员 OTP 故障不阻断访客；访客资料不自动并入会员；重复提交不重复建单；服务端给出最终金额 | M03、M07、M08、M09、M11、M12 |
| M07 订单 | 快照、状态、搜索、详情、备注、取消和履约 | 合法状态转换有历史；付款与履约分开；访客订单可在会员身份验证后按规则关联 | M00、M08、M09；M10 会员关联为可选扩展 |
| M08 付款 | COD、渠道设置、适配器、线上支付回调、交易台账、结算对账和退款接入点 | 回调验签与幂等；结算文件不重复导入；差异分类、人工处理有原因和审计 | M06、M07、M15 |
| M09 配送 | 区域、费率、免运门槛、人工单包/分批发货及追踪字段 | 结账服务端报价；订单保存配送快照；分批发货数量不超订购量 | M01、M07；M06 调用运费报价契约 |
| M10 顾客/会员 | CRM 档案、会员验证码登录、等级/积分、权益、优惠券、同意与隐私请求队列 | 访客结账始终可用；会员登录自愿、无密码；积分退款/过期有流水；隐私请求先核验身份并按保留例外受控处理 | M00、M07、M08、M13、M15；M11 会员专属券按契约联调 |

| M12 库存 | 现货、限时预留、流水、阈值和告警 | 并发不超卖；支付状态不明时不释放预留；取消、超时、分批发货和退货质检产生正确流水 | M03、M07、M08、M09；与 M06/M07 的预留和订单事件按契约联调，M16 质检入库在售后阶段接入 |

| M14 数据统计 | P0：经营账本报表、匿名访问事件、漏斗和导出；P1：统一主题埋点契约、采集覆盖监控、按发布版本对比陈列区块曝光/点击/加购/订单行归因及净实收 | 财务收入来源可追溯；分析事件不含个人资料；预览/员工/测试流量排除；按稳定区块标识和版本复核；金额、退款、COD、时间归属与导出上下文口径明确 | M02、M03、M06、M07、M08、M11、M12 |

## 3. 逐店参数与首店前台冻结项

跨模块默认规则和技术约定已在 `DEVELOPMENT_SPEC.md` 冻结；以下只补充首店的市场、服务商、合同参数和专属前台。缺失值只阻断对应的生产功能/客户页面，不阻断无关模板模块开发。每项记录负责人、最终值、批准依据和验收方式：

1. 首发国家/地区、可售商品、年龄/资格验证及市场审查责任人；未批准市场默认保持关闭。
2. 邮箱/短信 OTP 服务商（默认邮箱）、会员等级/积分/退款扣回/权益参数和通知账户。
3. 支付服务商及行业/地区审批、商户账户、服务商结算账户绑定、文件/API 能力、COD 区域/上限和退款限额。
4. 单店基础币种；税费/发票需求（默认关闭）；配送区域、费率、时效及运费差额/退货政策。
5. 是否有书面需求偏离默认 30 分钟线上支付预留、未知状态保留占位和 COD 人工确认规则。
6. 售后资格/时限、退货运费承担、审批、COD 退款、优惠券返还和积分扣回策略。
7. 安全访客订单查询是否纳入客户前台；如需要，确认一次性链接/验证渠道和费用。
8. 三语翻译/审校责任人、政策文本、商品资料/图片提供和审核人。
9. 数据/分析同意、各类资料保留、隐私请求处理时限/责任人和交易记录保留例外。
10. 确认客户云账号部署、备份目标/保留期、合同 RPO/RTO、值守 SLA、代托管、源码/IP 和升级责任。
11. 首店主题的注册区块/字段目录，以及桌面/手机预览要求。
12. SEO/URL：生产域名、语言路径、索引范围、旧 URL 映射清单及 SEO 文案责任人。
13. 客户隐私联系人、身份核验方式、请求到期时间、资料保留期限及角色授权。
14. 首店专属前台：页面/状态清单、桌面/手机设计稿、三语内容责任、专项接口和验收负责人；独立估算并纳入 R5。
15. 工程实施清单：按 `DEVELOPMENT_SPEC.md`、`API_SPEC.md`、`TEST_STRATEGY.md` 和 `TEST_CASES.md` 建立仓库/环境、完整 OpenAPI 初稿、数据库迁移、权限码、事件 schema、测试框架/fixture/临时数据库、CI、日志/监控、部署流水线和代码评审规则；这是 R1 技术任务，不再是待定产品决策。

## 4. 迭代拆分建议

每个发布批次先完成流程与数据设计，再交付页面/API/后台任务/权限/异常状态。按小批量演示，不把“页面已画出”视为业务闭环完成。

每个 Epic 内建议拆为：
- 用户流程与状态变更。
- 页面与多语言内容。
- API/数据对象和迁移。
- 权限、审计、幂等和异常处理。
- 接口/部署配置与操作说明。
- 业务验收条件和责任人。
- 端到端生产就绪场景见 [PRODUCTION_READINESS_ACCEPTANCE.md](../04-测试文档/PRODUCTION_READINESS_ACCEPTANCE.md)；新增对账、分批发货和陈列范围后，各模块原人日估算须重新估算。
- API 变更须同步 OpenAPI、权限和测试用例；每个 Epic 按 [测试策略](../04-测试文档/TEST_STRATEGY.md) 实现并执行分层测试，发布用例结果记录到构建证据中。

## 5. Definition of Ready

- 业务目标、用户、范围和不做项明确。
- 前后台页面与状态流转有设计链接。
- 字段、权限、数据来源、错误/空态明确。
- 外部服务凭证、沙箱和责任方可用或有替代路径。
- 验收结果可由业务人员观察，不依赖开发解释内部实现。
- 开放决策未影响当前批次关键交易或数据安全。

## 6. Definition of Done

- 页面、API、后台任务和数据库行为符合对应模块规格。
- 简体中文、繁体中文和英文覆盖实际交付页面；会员 OTP、访客结账和付款异常状态均验收。
- 权限、审计、空态、错误、重复请求和外部服务失败行为有演示证据。
- 对应的 unit、integration/API 功能测试及关键 E2E 已运行并记录结果；不能用文档定义用例替代执行结果。
- 商品、订单、支付、退款、库存和指标数据可追溯。
- 部署配置、密钥、迁移、备份/恢复和操作手册更新。
- 业主按已冻结验收标准签收；客户专属前台按该客户范围独立签收。

## 7. 变更管理

增加会员认证通道、第二支付/物流服务商、市场、多仓、税务、数据迁移或特殊行业能力时，记录对产品范围、数据、接口、安全、工期和客户升级的影响，再批准进入本批次或新版本。
