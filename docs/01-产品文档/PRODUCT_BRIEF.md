# EZSTARTCommerce 产品方案

## 1. 产品定义

EZSTARTCommerce 是一套可复用的**通用电商核心与管理后台模板**，并为每位客户单独部署站点、通过配置生成其专属前台。商品、订单、付款、配送、库存、促销和后台能力尽量复用；品牌视觉、首页区块、模块开关和购买文案由实例配置驱动，无需为客户单独开发前端。真正需要独特页面结构或流程的客户，按例外走工程级定制并单独报价（见 [定制模型](CUSTOMIZATION_MODEL.md)）。

产品本身是通用电商模板。烟草是首个落地行业/配置包，不应把商品类型、市场、语言、付款或配送规则硬编码进核心系统。

## 2. 产品交付模型

### 已确认的首期交付模式

同一份版本化电商核心/后台可提供给多个商家分别私有部署。每个商家拥有自己的品牌站点和后台，独立管理自己的商品、订单、顾客、库存、优惠券、付款/配送设置和报表；客户前台由一份实例配置驱动生成（品牌、配色、首页区块、文案、模块开关），不同商家不共享业务数据、账号或密钥。交付一个客户的默认动作是「填配置 → 标准部署 → 上线」，不是前端开发项目。

本项目不建设多租户 SaaS 总控台；一位商家默认对应一个独立站实例。商家可自托管，或由模板方代为托管独立实例；这不改变实例间的数据隔离和前台定制要求。

### 可配置维度

- 商店品牌、域名、标志、主题颜色和首页内容。
- 启用语言、默认语言、货币、时区和市场资料。
- 商品分类、属性、规格和库存。
- 付款方式、配送区域、费用和免运规则。
- 优惠券、通知渠道、客服资料和政策页面。
- 地区合规资料及需要的销售限制配置。

## 3. 目标用户与角色

### 主要使用者

- **商家负责人：**建立店铺、管理产品和业务设置，查看销售表现。
- **商品运营人员：**维护商品、分类、图片、规格、语言版本和库存。
- **订单/客服人员：**处理访客订单、联系顾客、安排配送及更新状态。
- **顾客：**浏览、选购、使用优惠码并以访客身份下单。
- **模板维护团队：**版本化维护核心产品、部署流程和可复用配置。

### 顾客身份边界

顾客可访客下单；会员可自愿使用已验证邮箱的一次性验证码登录会员中心，不设置密码且不强制注册。会员首期包含后台档案、等级、积分流水/规则、权益配置、优惠券关联和同意记录；手机号验证码须在短信服务商确定后启用。

## 4. 顾客核心旅程

1. 顾客访问商店，切换简体中文、繁体中文或英文。
2. 按分类浏览或搜索商品，查看商品图片、规格、价格和库存状态。
3. 选择规格和数量，加入购物车。
4. 在购物车输入优惠码，查看商品金额、折扣、运费和应付金额。
5. 以访客身份填写必要的联系和配送资料，选择已启用的付款方式。
6. 提交订单，看到订单确认信息；按配置收到订单通知。
7. 商家在后台处理订单、更新状态并安排配送。

## 5. 商家核心旅程

1. 获取一份新部署的模板，设置商店品牌、域名、语言和市场。
2. 配置管理员和店员权限、客服资料、配送规则和获准的付款方式。
3. 手工维护商品，或按模板导入商品表格。
4. 启用优惠券、库存预警及所需通知。
5. 管理员/店员查看订单并处理；负责人查看销售、商品和库存报表。
6. 通过版本升级流程获取模板修复和新功能。

## 6. 产品能力地图

| 能力域 | 首期能力 |
|---|---|
| 店铺与平台设置 | 可重复私有部署的单店实例、品牌设置、语言/货币/时区、地区配置、功能开关 |
| 前台体验 | 配置驱动前台：品牌、配色、字体、首页区块编排、模块开关、三语文案均可配置，无需前端开发；可配置 SEO 元数据、可索引输出和 URL 重定向；确有独特流程需求的客户走 B/C 类例外定制并单独报价 |
| 商品目录 | 商品、分类、品牌、规格、图片、价格、促销价、库存 |
| 订单履约 | 订单管理、状态流转、付款状态、配送规则和履约信息 |
| 运营增长 | 会员档案、等级/积分规则、权益、优惠券、基础促销 |
| 运营效率 | 商品导入导出、库存预警、通知配置、经营报表、网站访问与转化分析 |
| 内容管理 | 页面、FAQ、公告、文章及三语内容；SEO、索引、Sitemap 和已发布 URL 变更管理 |
| 管理与安全 | 后台身份验证、角色权限、操作日志、经身份核验的个人资料请求、备份和部署 |

## 7. 产品原则

1. **通用核心、行业配置：**通用电商流程与烟草行业规则分离。
2. **地区可配置、上线需审核：**不默认任何市场均可销售或使用任意支付/配送服务。
3. **访客结账优先：**会员登录自愿且不设密码；浏览、加购、结账都不要求注册。
4. **运营可自助：**商品、内容、折扣、库存、通知资料和常用业务规则由后台维护。
5. **可替换的外部服务：**支付、邮件、短信、物流通过适配层接入，避免绑定单一供应商。
6. **可升级交付：**模板版本、商家配置和商家数据分开管理，升级前有备份和回滚计划。
7. **隐私最小化：**仅收集订单和运营必要的顾客资料，保留期限由目标市场审核确定。

## 8. MVP范围

### 必须包含

- 商家独立站及后台。
- 三语框架及后台多语言内容维护。
- 商品、分类、规格、价格、图片和库存管理。
- 商品导入/导出。
- 商品搜索、购物车、优惠券和访客结账。
- 订单后台及状态管理。
- 货到付款；至少预留线上支付适配接口，并接入一个经业主和服务商批准的线上支付方式。
- 配送区域、费用及免运门槛配置。
- 后台会员资料、等级/积分规则和自愿验证码会员中心；访客结账不受影响。
- 库存预警、经营报表、网站访问与转化漏斗分析。
- 页面/FAQ/公告管理、客服资料配置和基础订单通知。
- 多语言 SEO 元数据、索引开关、Sitemap/robots 基线和已发布 slug 重定向；前台需提供搜索引擎可读取的元数据。
- 后台个人资料请求队列，含身份核验、营销退订、访问/更正/删除或匿名化处理、交易保留例外及限时导出审计。
- 基础售后案件：后台取消/退款记录、退货/换货跟踪、退款状态与库存处置；支付商退款 API 单独确认。
- 多商家可重复私有部署；实例初始化、域名/HTTPS、数据/密钥/备份隔离、版本升级与回滚文档。
- 前台配置引擎：一份实例配置即可生成客户专属前台（品牌/配色/首页区块/文案/模块开关），换客户无需前端开发；配置能力边界与例外定制见 [重做方案](../06-产品设计逻辑/03-配置化前台与交付体系重做方案.md)。
- A 类（配置级）为默认交付路径；仅有独特页面结构或流程的客户走 B/C 类例外，单独估算和验收。

### 本项目明确不包含（新增需求需另立项目评估）

- SaaS 账户与账单总控台、跨商家统一运营后台和跨店数据汇总。
- 原参考站数据库迁移或恢复。
- 强制顾客注册、密码式登录、跨店会员账户/积分；复杂营销自动化另行评估。
- 移动 App、复杂推荐、实时个性化。
- 多仓、多供应商采购、复杂会计/ERP。
- 多物流商自动比价/轨迹聚合。
- 高级营销自动化和复杂 BI。
- 未经审批的支付服务、跨境物流或自动绕过市场限制的能力。

## 9. 成功指标

上线后建议观察：

- 新商店从部署到首批商品上架的时间。
- 管理员完成商品新增/批量导入的成功率和耗时。
- 顾客从商品详情到成功下单的转化率。
- 结账中断率及订单提交失败率。
- 订单处理时长、取消率和库存异常率。
- 三语页面完整度。
- 支付回调/通知失败率。
- 模板升级成功率及升级回滚次数。
- 后台关键操作错误率和权限事故数。

具体目标值在基准数据和商家运营方式确认后设定。

## 10. 关键假设和边界

- 多个商家可以分别私有部署同一电商核心；每家有独立站点、后台、数据库、媒体和第三方凭证，前台由各自实例配置生成，彼此相互隔离，不是共享数据库 SaaS。
- 一位商家默认一站一实例；同一商家是否可用一套后台管理多个站点，暂不纳入首期。
- 商品由商家自行上传或提供结构化资料导入。
- 顾客不需要注册或登录即可购物结账；可选择一次性验证码登录会员中心。
- 会员系统包含后台档案、等级/积分和自愿验证码会员中心；具体等级、积分和权益规则由客户配置。
- 三语包括简体中文、繁体中文和英文，实际翻译由谁提供待确认。
- 烟草仅为首个行业配置包；任何商品、市场、广告、付款和配送能力须先经适用的法律与服务商规则审查。
