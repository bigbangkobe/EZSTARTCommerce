# 核心业务流程设计

本文把页面设计串成端到端业务旅程，供原型、接口、开发拆分和验收使用。所有流程都在单商家独立部署实例内完成。页面结构以 STOREFRONT.md、ADMIN_CONSOLE.md 为准；本文补充跨页面的数据流、状态转换、失败处理和审计要求。订单、付款、履约机器状态及允许转换以 [开发执行规格](../DEVELOPMENT_SPEC.md) 为准。

## 1. 流程总览

| 流程 | 参与者 | 起点 | 结果 |
|---|---|---|---|
| 实例开通 | 实施/运维、商家管理员 | 新客户部署 | 站点可访问、管理员可登录、基础配置完成 |
| 上架商品 | 商品管理员 | 后台商品列表或导入 | 商品校验通过并按渠道发布 |
| 顾客下单 | 访客、订单/支付服务 | 商品详情或购物车 | 订单创建，支付与履约状态明确 |
| 优惠核销 | 营销管理员、访客 | 优惠配置/结账 | 满足条件时优惠入单并留有核销记录 |
| 订单履约 | 订单/仓库人员 | 待处理订单 | 备货、发货、签收或异常关闭 |
| 库存管理 | 库存管理员 | 入库、订单、盘点 | 可售库存准确，低库存告警可处理 |
| 客户/会员 | 顾客、会员、客服/管理员 | 访客下单或会员 OTP | 安全关联资料，维护会员权益/积分及同意记录 |
| 经营分析 | 店主/运营 | 业务事件和订单数据 | 口径一致的看板、报表及导出 |
| 备份恢复/升级 | 运维 | 维护计划或故障 | 可追溯地恢复数据或完成版本升级 |
| 售后 | 顾客/客服/财务/仓库 | 客诉或售后申请 | 取消、退款、退货/换货及库存处置有记录 |

## 2. 新客户实例开通

### 操作步骤

1. 实施人员确认客户域名、部署环境、站点名称、品牌素材、默认语言/时区/币种和管理员联系方式。
2. 为该客户创建独立应用环境、数据库、文件存储、密钥与备份策略；每客户一个实例，不共享业务数据库。
3. 初始化数据库、管理员、默认角色、语言包、系统参数，并检查邮件/短信与文件存储连通性。
4. 商家管理员首次登录，修改临时凭证并完善店铺资料。
5. 配置支付、配送、税费、退款政策、隐私政策、通知渠道和库存预警阈值。
6. 在预览/测试环境检查定制前台，提交测试订单并核对后台状态、通知和报表。
7. 上线检查通过后切换域名与生产支付凭证，验证正式下单和退款流程。

### 验收与审计

- 客户数据、密钥、文件、域名和备份位置均登记，客户间相互隔离。
- 生产密钥不进入代码仓库；配置变更记录操作者、时间、字段和结果。
- 上线前检查 TLS、管理员安全策略、备份、错误告警、支付回调和恢复联系人。
- 商品和服务上线审核由商家/实施方按目标市场完成，平台提供配置能力，不替客户作合规判断。

## 3. 商品创建与批量导入

### 手工创建

1. 商品管理员新建商品，填写内部名称、状态、分类、品牌、SKU、价格、库存策略、主图及描述。
2. 维护简体中文、繁体中文、英文的标题、描述、图片替代文本和搜索元数据，并标记未完成语言。
3. 有规格时定义规格轴与选项，生成或编辑 SKU 变体；各变体单独设置 SKU、价格、库存和图片。
4. 设置配送/税费属性、可售区域、可见渠道、上架时间和促销展示信息。
5. 保存草稿，在前台预览三种语言和移动布局。
6. 校验通过后发布；下架保留历史订单快照，不删除被订单引用的商品。

### 批量导入

1. 管理员下载当前模板，查看字段说明、必填列、可选语言列和图片导入方式。
2. 上传 CSV/XLSX，选择语言、分隔符和更新策略；系统先解析预览，不立即写入商品。
3. 展示行级结果：新增、更新、跳过、错误、警告；以 SKU 匹配更新。未经确认不覆盖图片或库存。
4. 管理员下载错误明细或修正后重传；确认预览与策略后执行导入。
5. 导入任务记录发起人、文件摘要、策略、处理行数、失败行和结束状态，并可下载结果。
6. 导入商品默认保持草稿，或按客户确认的策略处理；导入不能绕过上架审核。

### 关键规则

- 商品采用停用/归档；存在订单引用时不做物理删除。
- 价格、SKU、库存变化记录操作者和时间；订单行保存商品名称、SKU、成交价及折扣快照。
- 币种、含税/未税展示和舍入规则属于实例配置，需求未确认前不写死。
- 大文件导入作为后台任务处理，具备进度、失败明细和幂等策略，不产生不可追踪的半批次数据。

## 4. 访客下单与付款

### 购物车到订单

1. 访客从商品详情选择规格与数量；系统校验商品已发布、销售区域有效、数量与库存可售。
2. 购物车展示商品、规格、数量、单价和小计；访客购物车跨会话保留 30 天无活动到期，顾客可主动清空。
3. 访客进入结账，填写邮箱/电话、收件人、地址、配送方式和备注，不创建或登录顾客账号。
4. 服务端重新计算价格、优惠、配送费、税费、库存和区域限制；前端传来的金额不作为最终金额依据。
5. 访客选择货到付款，或当前实例已启用且可用的线上付款方式。
6. 提交时使用幂等键，避免重复点击重复建单；服务端创建订单、商品快照、金额明细、优惠占位及库存预留。
7. 按付款方式分流：
   - 货到付款：订单机器状态为 `awaiting_confirmation`、付款状态为 `cod_due`；客服/店主确认后进入 `confirmed`，仅授权人员可登记已收款。
   - 线上付款：订单机器状态为 `pending_payment`；签名回调或服务端查询确认成功后进入 `confirmed`。
8. 订单创建成功后显示订单编号、金额、付款方式和后续说明，再发送订单通知。

### 在线支付回调与失败恢复

1. 支付适配器验证签名、商户号、币种、金额、订单关联和事件 ID。
2. 成功回调将付款状态更新为已支付；失败/取消更新为失败/取消；处理中则保持待支付。
3. 重复回调幂等处理；金额或订单不匹配的回调隔离并告警，不得覆盖订单金额。
4. 浏览器返回页仅展示结果，不能作为到账凭证；最终状态以验证通过的服务端回调或主动查询为准。
5. 回调延迟时由后台任务查询支付渠道并补偿；超时关闭前先确认渠道未收款，再释放库存和优惠占位。
6. 后台退款需记录渠道退款号、金额、原因、操作者和状态；部分退款另行确认规则。

### 状态分离

订单、付款、履约是三个独立状态维度，避免把已付款误当成已发货。

| 维度 | 状态建议 | 典型推进 |
|---|---|---|
| 订单 | 待确认、待处理、处理中、已发货、已完成、已取消、异常 | 创建后按付款方式和人工审核推进 |
| 付款 | 待支付、处理中、已支付、失败、已取消、部分退款、已退款 | 支付回调/查询或后台退款推进 |
| 履约 | 未分配、待拣货、已拣货、待发货、已发货、已签收、退回/异常 | 仓库与物流操作推进 |

页面中文/繁体/英文文案可由运营审校；机器状态和允许转换已按开发执行规格冻结。每次状态转换均需校验权限并记录操作者、时间、原因和审计事件。

## 5. 优惠券配置、发放与核销

1. 营销管理员配置优惠码或自动优惠、折扣类型、有效时间、适用商品/分类、最低消费、总领取/核销上限、每客上限和叠加规则。
2. 保存草稿并预览规则摘要；启用前检查日期、范围和规则冲突。
3. 通过后台或导入名单发放，记录批次和结果；邮件/短信发送取决于实例通知配置。
4. 访客在结账输入优惠码；服务端检查状态、有效期、适用范围、金额、次数、叠加规则和排除项。
5. 结账展示优惠明细和最终金额；提交订单时再次校验并创建核销占位。
6. 支付失败、订单取消或超时关闭时按规则释放占位；达到客户定义的消费节点后转为已核销。
7. 退款/取消后的优惠是否恢复由业务规则明确配置，不默认自动返还。

校验失败应提供可操作原因，例如已过期、未达门槛、不适用或已达上限，不暴露其他顾客的领取记录。

## 6. 订单审核与履约

1. 后台订单队列按订单状态、付款状态、时间、渠道和风险标记筛选；新单提醒不代表审核完成。
2. 订单人员查看地址、商品快照、金额、付款状态、客户历史和备注。
3. 需人工确认的订单进入待确认；拒绝时选择原因，并按付款状态启动退款或核实流程。
4. 通过后分配库存/仓库；拣货人员核对 SKU 与数量，缺货、替换或拆单走异常流程。
5. 出库时录入物流公司、追踪号和发货时间；发送发货通知并更新履约状态。
6. 根据物流回传或人工确认更新签收/异常；超过配置时限进入待跟进队列。
7. 订单完成后更新经营统计；取消、退货和退款以冲销/退款事件修正指标，保留原始记录。
8. 高风险动作如付款确认、取消、退款、地址变更和人工改价需权限控制并记录原因。

### 货到付款特有处理

- 下单标记货到付款及预计应收金额；收款确认由授权人员操作。
- 发货和签收不自动等于已收款；拒收、退回、未收款需有独立处理结果。
- 是否人工审核、地区限制、金额上限和运费规则由客户确认。

## 7. 库存流水与预警

### 库存台账

通过有方向、有原因的流水调整库存，而不是直接覆盖。至少区分现货、预留、可售、损坏/冻结数量。

建议可售数量 = 现货数量 - 有效预留数量 - 冻结数量。创建订单时按策略预留，付款成功/审核通过后分配；取消/超时按条件释放；发货时扣减现货。若客户要求下单即扣库存，需定义失败订单的返还规则。

### 预警闭环

1. 管理员按商品/SKU设置阈值，或使用系统默认值。
2. 后台任务发现可售数低于阈值时创建去重告警并通知授权人员。
3. 告警显示 SKU、现货、预留、可售、阈值、发生时间和处理状态。
4. 管理员确认、补货或调整阈值后关闭告警并记录说明；再次低于阈值时生成新一轮告警。
5. 导入、订单、退款、入库、盘点和人工调整均产生库存流水，可按 SKU 与时间追溯。

并发更新使用事务/原子条件防止超卖。多仓、批次、效期和采购单需作为额外范围确认。

## 8. 客户档案与营销同意

1. 顾客以访客结账；系统依据已确认的识别字段，将订单联系人匹配或创建客户档案。
2. 匹配规则、邮箱/电话标准化和重复档案合并需经隐私与运营要求确认，不可只按姓名匹配。
3. 客户详情展示订单摘要、消费汇总、标签、内部备注、优惠券发放和同意状态；敏感资料按角色限制。
4. 营销订阅与交易必要联系信息分开收集；完成交易不能默认为营销同意。
5. 退订后同步禁止营销发送；修改、导出、删除或匿名化请求走受控流程，并保留依法必须保存的交易记录。
6. 客户资料访问、导出、合并、删除和同意状态变化写入审计日志。

### 个人资料请求处理

1. 客服或隐私专员登记请求类型、收到时间、联系渠道和客户规定的处理时限，系统分配负责人并生成请求编号。
2. 处理访问/导出、更正或删除前，先用客户批准的方式核验请求人身份；未核验的请求只能补充资料或拒绝处理，不能显示敏感档案或生成导出。
3. 通过有效的一次性退订令牌或已登录偏好设置发起的营销退订立即写入统一同意状态并停止后续营销发送，其他请求继续按各自流程处理；无效令牌不改变资料且不透露账户是否存在。
4. 核验通过后，按角色复核数据范围和交易保留例外；批准、拒绝、要求补充信息或延期均记录理由及负责人。
5. 导出文件仅包含已批准范围、限时下载、到期失效；删除/匿名化只处置获准的会员/营销资料，不改写必须保留的订单、付款和售后事实。
6. 完成后记录处理范围、依据版本、结果、完成时间和对客通知状态；请求人查看、导出、审批、下载和关闭操作均留审计。

## 9. 报表与指标口径

### 数据形成

- 业务模块产生带时间、实例时区、币种、来源和关联 ID 的事件或审计事件。
- 订单和支付作为收入、付款状态事实来源；退款/取消以独立负向事件处理，不覆盖原订单。
- 看板支持时间范围与渠道筛选，注明时区、币种、订单状态范围和更新时间。
- 产品、订单、客户、营销、库存、支付和运营模块共用指标定义。
- 导出前校验操作者权限、筛选范围和数据量；任务记录发起人及下载状态。

### 首期指标定义建议

| 指标 | 建议口径 |
|---|---|
| 订单数 | 已创建且非测试订单；取消是否计入需单独说明 |
| 成交额 | 商品金额、优惠、配送、税费分别展示；退款独立扣减或分列 |
| 实收金额 | 已确认支付或已收 COD 金额减成功退款 |
| 客单价 | 选定范围内成交额 ÷ 有效订单数 |
| 转化率 | 需要访问/会话事件作分母；无埋点时不展示 |
| 热销商品 | 按售出件数或净销售额排序，并标注口径 |
| 库存预警数 | 未处理 SKU 告警数，按告警去重规则统计 |
| 优惠效果 | 分列领取、下单应用、完成核销和退款/取消 |

CSV/XLSX 导出须沿用页面筛选和指标定义，处理时区、币种精度及个人资料脱敏。

## 10. 内容与站点配置发布

1. 内容管理员编辑页面标题、正文、图片、SEO 元数据和三种语言版本。
2. 草稿预览使用当前主题与前台组件；未发布内容不应对普通访客可见。
3. 发布前检查缺失翻译、失效链接、图片、发布时间和政策页面。
4. 店铺配置维护品牌资料、联系方式、社交链接、语言、币种、时区、页脚和通知文字。
5. 关键配置变更写入审计；必要时支持回滚上一版本，发布事件保存版本号和操作者。
6. 定制前台后台仅编辑约定开放的数据字段/内容区块，不能把通用配置器变成任意代码编辑器。
7. 变更已发布 slug 前显示 301 目标和冲突检查；目标必须在本店已发布路由内，拒绝循环/重复来源。发布后立即更新 sitemap 与旧链接解析；撤下页面从 sitemap 移除。

## 10.1 前台陈列配置、预览与发布

1. 内容管理员选择首页、分类页或专题页；系统加载该页面当前已发布版本和客户前端主题注册的区块目录，并以当前版本创建草稿。
2. 管理员添加、隐藏或排序区块，编辑开放的标题、图片、链接和版式参数。每项修改限定在当前页面和当前区块，不改变商品主数据。
3. 商品区块可以手动选择商品并调整本区块优先级，也可以选新品、销量、价格等已开放规则；动态规则需设置展示上限和相同排序值的稳定次序。未发布、已下架或目标市场不可售的商品不得成为可购买项。
4. 缺货商品按店铺设置决定是否展示；展示时必须标记售罄并禁用购买。区块没有符合规则的商品时按主题配置隐藏区块或展示空状态，不自动回退到下架商品。
5. 管理员在桌面/手机及简体中文、繁体中文、英文下预览草稿。预览用隔离的草稿版本；普通访客继续读取已发布版本。
6. 即时发布前校验启用语言的翻译、图片、链接、商品状态与发布时间。缺少任一启用语言的必填内容时阻止发布并定位到字段；不静默用其他语言内容代替。校验通过后生成不可变发布版本并原子切换前台版本，刷新对应缓存并记录操作者、时间和版本号。
7. 定时发布按店铺时区执行；计划时间必须晚于当前时间。定时撤下时间必须晚于发布时间。计划状态显示待发布、已发布、已撤下或失败。计划执行失败时保留当前线上版本、提示管理员并允许重试。
8. 撤回时恢复一个明确的历史发布版本，生成新的发布记录；不能删除历史记录。并发草稿基于过期版本时提示冲突，要求管理员合并后再发布。
9. 首期同一页面只允许一个待执行的发布/撤下计划；新计划与已有计划时间冲突时，提示管理员编辑或取消旧计划。撤下任务绑定创建它的发布版本；如果线上版本已被后续发布替代，不得撤下新版本，应将旧任务标记为已跳过并通知管理员。
10. 商品在发布后变为下架、市场不可售或被归档时，前台立即隐藏该商品，不允许购买。手动区块保留该商品的后台配置并标记不可用，提醒运营替换；动态区块跳过该商品并按相同规则补足下一件合格商品。库存归零时按店铺设置隐藏商品或显示售罄，始终禁止加购。
11. 商品选择器显示商品状态、市场资格和库存；草稿、归档和当前市场不可售商品不可选，并显示不可选原因。无权发布/回滚的角色可以保存草稿和预览，但不能执行线上版本切换。
## 11. 通知发送与失败补偿

1. 订单、付款、发货、优惠券或库存事件按通知规则生成消息任务。
2. 发送前读取模板语言与收件人同意状态；交易通知和营销通知分开。
3. 发送服务返回成功、失败或未知；未知状态先查询发送结果再重试，避免重复发送。
4. 失败任务进入队列，有限次数退避重试，最终显示失败原因和人工重发入口。
5. 日志记录模板版本、渠道、收件人脱敏标识、时间、供应商消息号和状态。
6. 通知服务未配置或故障时订单仍应正常创建，后台提示通知未送达。

## 12. 备份、恢复与版本升级

- 备份范围覆盖数据库、商品媒体、客户上传内容、关键配置和密钥恢复指引。
- 备份任务记录时间、范围、结果、位置标识和校验信息；定期在隔离环境执行恢复演练。
- 升级前确认兼容性、备份、维护窗口和回滚方案；数据库迁移逐步记录。
- 升级失败时停止迁移并使用已验证的回滚/恢复方案，不在生产临时手改表。
- 客户实例可查询软件版本与扩展包版本；个性化前台通过稳定接口契约连接通用后台。
- 运维权限限授权角色，操作留审计；不建设跨客户 SaaS 管理控制台。

## 13. 横向验收要求

- 金额、库存和优惠由服务端最终计算；前端请求不能覆盖可信价格、折扣或支付结果。
- 为建单、支付回调、库存扣减、退款和批量导入定义幂等边界与重复请求结果。
- 关键状态变化记录操作者/系统来源、时间、前后状态、关联 ID 和原因。
- 页面覆盖加载、空结果、权限不足、校验错误、服务错误和成功反馈。
- 多语言页面明确处理缺译，不把某种语言静默伪装成另一种语言的完整内容。
- 后台高风险操作需要确认和可追溯原因；错误提示说明原因和下一步处理方式。
- 统计指标必须能从订单、支付、退款、库存流水或行为事件追溯。

## 14. 需求冻结时需定稿的流程参数

以下事项不能从参考网站推断，应在需求冻结时确认：

- 首发国家/地区、年龄/资质校验、可售范围及禁售商品处理。
- 默认币种、税费计算方式、金额精度、语言回退和时区。
- 配送方式、区域/重量/金额计价、免邮门槛、承运商和追踪集成。
- COD 审核、收款确认、拒收/退回、金额限制和运费规则。
- 线上支付服务商、结算币种、退款规则、回调超时。
- 库存预留时点、预留时长、取消返还和多仓需求。
- 优惠叠加、核销时点、按订单行分摊、取消/退款时恢复策略。
- 客户档案匹配字段、营销同意、保留期限和资料请求流程。
- 指标定义、有效订单范围、退款对收入的影响、访问埋点和归因方式。
- 通知渠道、模板审核、发送失败处理和退订同步方式。

## 15. 售后案件处理（M16）

1. 顾客通过客服渠道提出请求；若启用访客自助入口，必须先用短期安全链接或一次性验证码验证订单。后台客服也可从订单详情人工建立案件。
2. 系统关联订单行、付款、配送和顾客档案，显示订单状态、实收额、累计退款和各商品可申请数量。订单号本身不能证明申请人身份。
3. 客服选择取消、退款咨询、退货或换货，记录原因与顾客说明；按订单履约状态、商家政策和操作者权限通过、拒绝或要求补资料。
4. 需要退货时记录退件方式与追踪信息；收货人员登记数量和质检结果，逐件选择可重新入库、损坏/冻结、报废或待决定。
5. 财务发起退款前再次核验已收款、币种、金额和累计可退余额；使用幂等键提交渠道，未知状态先查询，失败进入人工处理队列。
6. COD 未收款取消只更新订单/案件并释放库存预留，不生成付款退款。COD 已收款后的退款使用客户确认的人工或服务商方式记录。
7. 退款或补发完成、退货处置完成、顾客通知结果已记录后，案件才可关闭；退款记录与原付款分开保存。
8. 取消/退款/退货事件分别更新库存流水、优惠券恢复规则、经营报表和售后通知；访问分析不接收顾客个人资料。

### 失败与补偿

- 外部退款请求超时：标记待查询，不盲目重发。
- 退款被拒：记录渠道原因、保持案件打开、分派财务。
- 通知失败：不回滚售后状态，进入通知重试队列。
- 退货与订单数量不匹配：暂停库存入账并由仓库主管处理。
- 重复售后请求：按订单/商品/数量检查冲突，不自动创建重复退款。

详细界面、权限及状态文案见 design/AFTERSALES.md。

## 14. 自愿会员验证码登录与权益

1. 顾客在会员入口输入邮箱并请求 OTP；消息任务检查发送限速、模板语言和账户枚举保护。
2. 验证码以摘要存储，设定有效期和最大尝试数；超时、重发、重复使用或服务故障均返回可理解提示。
3. 验证通过后，已有会员进入会员中心；首次加入时说明所需资料和用途，再创建会员档案。营销同意保持独立且默认未勾选。
4. 会员中心按身份读取等级、积分、优惠券、订单摘要和积分流水；权限只允许读取当前会员资料。
5. 订单完成后按店铺规则生成唯一积分流水；退款/取消/拒付按规则冲回或冻结，所有动作使用幂等键并保留规则版本。
6. 会员价、积分兑换券和普通优惠券在服务端统一计算，结账展示清楚的优惠明细；顾客始终可以退出登录后访客结账。
7. 会员更换邮箱/手机号必须重新验证；数据导出、删除/匿名化和营销退订按客户隐私策略处理。
8. OTP 服务不可用不阻断访客交易；客服可按受控流程协助会员身份核验，不提供绕过记录的人工改账。

### 会员验收状态
验证前、验证码已发送、验证码错误/过期、请求限流、通知服务失败、首次加入、已有会员、无积分、无优惠券、积分即将到期、规则调整、退款扣回均需有页面/操作说明和审计结果。
