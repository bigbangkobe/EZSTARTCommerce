# M03 商品、分类、规格与搜索

**优先级：**P0  
**初步开发估算：**10–14 人日

## 产品目标
让商家自行建立完整商品目录，并让顾客可按分类、品牌和关键词找到商品。

## 首期范围
商品 CRUD、草稿/上架/下架、分类、品牌、图片、SKU、规格、价格/促销价、库存引用、三语名称和描述、分类/品牌浏览、关键词搜索、排序与基础筛选。

## 主要数据对象
Product（状态、slug、品牌、分类、商品类型、SEO）；ProductTranslation；ProductVariant（SKU、属性、价格、库存策略）；Category/CategoryTranslation；Brand；MediaAsset；ProductAttribute。

## 关键业务规则
SKU 在店铺内唯一；价格采用货币最小单位存储；下架商品不可加入购物车；规格库存和商品可售状态必须一致。简体中文、繁体中文和英文按店铺已启用语言维护；商品发布时至少要求每种启用语言的名称、商品页必要信息和 SKU/规格展示文案齐全，缺失时阻止发布，不得静默展示错误语言或机器翻译。订单保留当时语言和商品翻译快照。首期搜索字段、筛选、排序和同值稳定规则见 [开发执行规格第 5.4 节](../DEVELOPMENT_SPEC.md#54-商品搜索与陈列动态排序)。

## 验收条件
管理员能新增/编辑三语商品和多个规格；按分类浏览及搜索；缺货/下架商品不能购买；图片上传、排序和替换可用。

## 依赖
M00/M01、媒体存储。M05 导入、M02 前台及 M12 库存消费商品目录契约，不作为商品目录核心模型的前置条件。

## 实施状态

2026-11-16：分类、品牌、商品（三语翻译、多规格、价格、图片引用、状态）后台 API 与 /admin/catalog 页面已实现；发布门禁强制每种启用语言齐全、至少一个可售规格，并要求目标市场已审核启用。媒体上传、前台陈列与搜索排序（M02）以及库存调整（M12）尚未实现，商品响应不含属性字段。详见 [实施记录](../IMPLEMENTATION_PROGRESS.md)。
