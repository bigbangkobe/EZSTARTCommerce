# M14 数据统计与分析

**优先级：**P0  
**初步开发估算：**10–16 人日（不含第三方分析平台授权费用）

## 产品目标
让店铺经营者同时看清交易经营结果和顾客在网站上的匿名访问/转化表现，帮助定位商品、流量和结账环节的问题。

## 首期范围

### A. 经营报表

- 销售额、订单数、平均订单金额、优惠金额、配送金额。
- 按付款状态、订单状态、付款方式统计；区分货到付款和线上支付。
- 商品/规格/分类销售排行和趋势。
- 取消订单、退款金额（启用退款流程后）。
- 库存、低库存和缺货汇总。
- 优惠券发放/核销量、折扣金额和使用率。
- 会员指标可汇总注册/活跃会员、积分发放/兑换及会员订单占比；仅做聚合统计，不将邮箱、电话或 OTP 放入分析事件。

### B. 网站访问与转化分析

- 匿名访问量/会话数、页面浏览量、商品详情浏览量。
- 商品加入购物车、开始结账、提交订单等关键事件。
- 访问来源、推荐来源、UTM 活动参数；按语言、设备类型、已批准市场区域切分。
- 漏斗：访问 → 商品浏览 → 加入购物车 → 开始结账 → 成功下单。
- 关键指标：商品加购率、结账完成率、访客下单转化率、来源渠道转化表现。
- 允许按日期范围、语言、设备、来源、分类/商品筛选，并导出 CSV/Excel；导出文件须包含筛选条件、店铺时区、币种、统计口径/归因规则版本、数据更新时间和采集覆盖状态，且继续遵守角色授权与小样本保护。
- 后台显示数据更新时间及统计口径说明。

### C. 数据采集与可选集成

- 首期使用轻量第一方事件采集，配合服务端订单事件；成交/支付以订单及支付记录为准，不信任浏览器的购买事件作为财务数据。
- 事件与订单关联使用随机会话/事件 ID，不在分析事件中写入姓名、电话、邮箱、地址或支付凭证。
- 外部分析平台（如商家选择的分析服务）作为可选连接器，不作为核心功能上线的前置条件。
- 依市场规则配置必要的告知/同意控制；未经批准的追踪行为不得默认启用。禁止设备指纹识别。

### D. 前台陈列效果分析（P1，首期经营报表后续增强）

- 按页面/区块查看可见曝光、区块点击、商品加购、已提交订单及归因净实收金额，支持日期、页面、区块、商品、语言、设备和市场筛选。
- 曝光定义为区块至少 50% 进入可视区域并持续 1 秒；每个匿名会话、页面和区块仅计一次，以减少滚动重复曝光。
- 点击记录 section_id、placement_id、product_id 和随机 interaction_id；加购仅在服务端成功写入购物袋后计数。
- 事件定义为 section_impression、section_click、placement_add_to_cart 和服务端 placement_order_attributed；每个事件带 schema_version，并定义幂等键。所有客户定制主题必须通过同一埋点 SDK/适配器发送事件，不允许各主题自行定义事件口径。
- 事件契约必填 publish_version_id、page_key、section_id、稳定的 section_key、placement_id（适用时）、product_id（适用时）、session_id、interaction_id（适用时）、environment、匿名 traffic_class、consent_state 和 schema_version。section_key 在同一逻辑区块跨发布版本保持稳定；section_id 标识该页面中的具体区块实例。事件保留发生时的发布版本，供版本筛选与比较。
- 预览链接/后台预览必须携带短时 preview token 并标记 environment=preview；预览、后台员工流量、沙箱订单、明确标记的测试订单不得进入正式经营指标或陈列转化指标。员工身份只由可信后台会话转成短时内部流量标志，分析事件不保存员工账号/身份 ID。已知爬虫按维护的规则排除；疑似机器人流量标记为可疑并可从分析视图过滤，过滤规则和数量可审计，不能静默删除原始事件。
- 加购和订单行使用匿名 interaction_id 关联，不通过邮箱/电话匹配。首期采用 24 小时内最后一次有效区块交互归因；每个订单行只归因给一个区块。
- 订单数以服务端订单行为准；页面分开展示已提交订单、已收款/已收 COD 订单和成功退款。归因净实收只统计商品行金额：订单级优惠按各商品行优惠前小计比例分摊，分币舍入余数按固定订单行顺序分配；排除配送费、税费及支付手续费；扣除成功退款中关联该商品行的金额。货到付款仅在订单明确标记已收款/已收货款后计入实收；待收 COD、取消订单及失败/待处理退款不计入净实收。订单级或无法关联商品行的退款单独列示为未分摊金额，不按比例伪造区块归因。
- 显示曝光到点击、点击到加购、加购到提交订单的阶段转化；分母为同一筛选范围内去重会话。单个区块少于 20 个曝光会话时显示“数据不足”，不展示误导性百分比。
- 报表提供发布版本筛选；区块按稳定 section_key 聚合，同时可下钻到发布版本及 section_id。定制主题未接入标准埋点、事件长期缺失或采集失败时显示相应状态，并显示最近事件时间和覆盖状态，不将未知数据当作 0 曝光；若该时段没有前台访问，显示“无访问/无法判定”，不直接判成埋点故障；“长期缺失”的判定阈值需按店铺流量/采集频率配置。P1 不含 A/B 实验或因果增量分析。
- 匿名归因不覆盖设备、跨店或跨客户；追踪告知/同意策略沿用 M01/M14 全局设置，分析停用或未获同意时不得采集受限事件。
- 此项不替代经营报表，不作为首期真实交易上线阻塞；原有 M14 估算不含该 P1 埋点、归因与区块报表。

## 指标口径初稿

- **时间归属：**访问/曝光/点击/加购按事件 UTC 时间；下单按订单创建时间；线上收款按服务端成功入账时间；COD 收款按授权人员登记时间；退款按渠道/人工确认成功时间。日期以店铺时区展示，数据库存 UTC。
- **下单量/下单额：**成功创建的订单按创建日期统计，包含之后取消的订单；取消数/取消额另列，测试和重复幂等请求不重复计数。页面按订单/付款/履约状态筛选，不隐式删掉某种状态。
- **已收金额：**线上成功支付金额 + COD 已登记收款金额；待收 COD、付款未知、失败/取消不计入。退款金额只计成功退款；待处理、失败、未知退款单独显示。现金口径净实收 = 已收金额 - 成功退款金额，按实际收退款日期统计。
- **净销售额：**已收商品金额（已分摊订单级优惠后）减去成功商品退款；配送费、税费、支付手续费分别展示或排除，不与商品净销售额混用。
- **平均订单金额：**分别提供下单平均金额（下单额/成功创建订单数）和已收平均金额（已收金额/至少有一笔成功收款的订单数），避免口径混用。
- **下单转化率：**创建订单的去重匿名会话数 / 符合条件的去重匿名会话数；付款转化率另算成功收款会话数 / 已创建订单会话数。服务端订单与支付记录是购买/收款权威来源。
- **漏斗转化：**按同一日期、语言、设备、来源和同意范围计算相邻步骤去重会话比例；会话重复事件按 event/session 去重。
- 报表页面和导出使用相同筛选、时间归属、币种、指标定义和数据覆盖状态；导出文件写明这些条件及更新时间。

本节作为模板统一指标口径；客户只需确认市场要求的分析告知/同意与留存政策，不得将订单额、实收、退款或净销售额合并改名为一个“销售额”。

## 主要数据对象

- **AnalyticsEvent：**event_id、session_id（随机）、event_name、occurred_at、locale、device_class、market_code、page_key、page/product/category/section/placement 引用、section_key、publish_version_id、environment、匿名 traffic_class、interaction_id、referrer_host、utm_source/medium/campaign、consent_state、schema_version。
- **AnalyticsSession：**随机 session_id、first_seen_at、last_seen_at、landing_page、referrer/UTM、locale、device_class；不保存直接身份信息。
- **DailyMetricRollup：**日期、时区、指标、维度和值，用于报表聚合。
- **EventDefinition：**事件名称、必需参数、版本和启用状态。
- **OrderAttribution：**订单与会话的可选关联、归因规则版本；不包含顾客 PII。
- **PlacementAttribution：**order_item_id、cart_item_id、section_id、section_key、placement_id、product_id、publish_version_id、interaction_id、归因规则版本；无 PII，单个订单行只保留一个有效归因。
- 经营报表继续使用 Order、OrderItem、Payment、Refund、CouponRedemption、InventoryMovement 等交易数据。

## 关键业务规则

- 浏览器事件可能丢失或重复；财务和订单报表以服务端订单/支付数据为权威。
- 购买事件使用订单 ID 做幂等去重；会话事件使用事件 ID 去重。
- 不在 URL、UTM 或分析事件中存个人资料；过滤 URL 查询参数中的敏感内容。
- 按市场配置追踪告知/同意行为和保留期限；最终配置由业主及专业顾问确认。
- 报表按角色授权；订单/顾客明细不得泄漏到仅可查看聚合指标的角色。
- 外部分析连接器故障不得阻塞商品浏览、结账或订单创建。
- 多币种数据不得直接相加；须按币种分别显示，换算报表规则另行确认。
- 定制主题发布前须通过事件契约验收；事件校验需检查必填字段、版本、幂等键、预览环境及匿名流量分类。报表提供埋点覆盖率/健康状态，并用页面访问事件辅助区分“确实无区块曝光”“无前台访问”和“埋点未采集”。
- 订单行净实收以该行最终应收商品金额（分摊订单级优惠后）为基数，扣除成功且关联该行的退款；配送费、税费、支付手续费及未分摊退款不计入区块净实收，单独显示。

## 验收条件

- 后台可查看交易、商品、库存、优惠券和访问转化分析。
- P1 陈列报表能分别查看区块曝光、点击、加购、服务端订单与净实收；会话/订单行按规则去重且可追溯到事件/订单数据。
- 客户定制主题使用统一事件契约；按稳定区块 key 和发布版本查询；预览/员工/沙箱/测试数据排除，并可检查采集覆盖状态。
- 订单行优惠分摊、成功退款、COD 收款状态及配送/税费排除符合口径说明；订单级未分摊退款单独显示。
- 日期、时区、语言、来源和设备筛选符合定义；导出结果与页面筛选一致，并携带可复核的筛选、口径和数据覆盖信息。
- 商品浏览、加购、结账开始事件可用于构建漏斗；成功订单由服务端数据去重并与订单后台核对一致。
- 对账报表可分别查看下单金额、支付金额及退款金额，口径有页面说明。
- 分析事件不包含姓名、电话、邮箱、地址、密码或支付凭证。
- 无报表权限的后台角色不能访问数据；数据更新时间和采集状态可见。
- 关闭可选外部分析服务后，核心商城和内部交易统计仍可用。

## 依赖

M00 权限、M01 地区/语言配置、M02 前台事件点、M03 商品目录、M06 购物车/结账、M07 订单、M08 付款、M11 优惠券、M12 库存，以及目标市场的数据告知/同意规则。

## 项目实施建议

先定义事件清单和指标词典，再与前台关键路径同时埋点；经营报表先做服务端数据聚合，访问漏斗随后接入。将分析事件采集与交易核心解耦，便于后续选择外部平台。估算 10–16 人日；完整归因、跨设备分析、广告平台转化 API 和高级 BI 另行估算。
