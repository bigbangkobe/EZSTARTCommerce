## 当前状态

项目包含产品/工程规格、17 个模块规格、页面设计与 HTML 原型、OpenAPI 草稿；尚无 `apps/` 应用、数据库迁移、业务实现或 CI，当前目录未初始化 Git。文档中的“基线冻结”表示工程规则已登记，不表示接口完成或系统可上线。

OpenAPI 当前包含 115 个路径、145 个操作和 123 个 schema。operationId 无重复；非认证后台操作均有 `x-permission` 标签；本轮检查的 README 与 docs Markdown 相对链接无失效。权限标签存在仅证明声明覆盖，不能证明运行时授权正确。

## 已处理问题

| 编号 | 问题及影响 | 本轮处理 | 回归用例 |
|---|---|---|---|
| CR-001 | `CheckoutQuote` 用 `allOf` 组合两个封闭对象；金额字段与报价字段互被视为额外字段，正常响应无法通过 schema | 改为单个封闭对象，保留金额整数约束及各报价字段 | CT-001 |
| CR-002 | 下单要求 `confirmedQuoteVersion`，报价却没有返回可提交的版本；规则版本在文字与 YAML 中形态不同 | 报价必返正整数 `version`；下单原样传回；文字统一使用 `ruleVersions`，税费关闭时 `tax:null`；配送、优惠摘要、警告字段明确必返 | CT-001 |
| CR-003 | OTP 申请使用通用响应，缺少 verify 必填的 `challengeId` 契约 | 增加专用 202 响应与封闭 DTO；已登记/未登记地址均使用统一字段，挑战 ID 不赋予身份权限 | CT-002 |
| CR-004 | `ContactInput` 只检查字段是否存在，`email:null`、`phone:null` 或空白电话可通过 | 至少一个通道为有效非空字符串，另一项可空；实例仍需按通知渠道检查可用性 | CT-003 |
| CR-005 | `ProductVariantResponse` 扩展封闭的输入 schema，导致响应的 `id` 和库存字段被拒绝 | 响应独立声明允许字段；输入仍拒绝客户端写入 ID/库存；响应拒绝未知字段 | CT-004 |

以上是对已有业务要求的契约补全，不引入新交易规则。消费者需重新生成类型：报价及 OTP 响应增加必填字段，报价规则版本统一采用 YAML 已有的嵌套字段。尚无数据库与运行服务，故本轮没有数据库迁移或客户实例升级操作。API 文字规格同步到 1.3；OpenAPI 继续作为未冻结的 1.0.0 草稿。

## 剩余开发缺口与顺序

1. **逐操作响应 DTO 尚不完整。** 126 个操作至少有一个 2xx 响应仍引用通用 `Success`、`Created` 或 `Accepted`，共 128 处。应优先补齐 R1 的登录/MFA/会话、员工/角色、店铺配置及运维响应，然后随模块逐步收紧。通用对象会让客户端失去字段约束，本轮不将它们批量替换为猜测字段。
2. **身份链路还需完整联调契约。** 管理员登录到 MFA、会员验证到本人摘要等成功响应仍需具体 DTO、安全 cookie/挑战绑定和异常用例；仅补齐 OTP 申请不能证明身份流程完成。
3. **工程骨架尚未落地。** 按开发执行规格建立 workspace、锁定依赖、API/Worker、数据库迁移和 CI；把本轮校验加入 CI。现有 Next.js/NestJS 等选型仍需在实施时核实可用版本并锁定，不能把规格版本号当作安装证据。
4. **发布证据为空。** 外部支付/通知 adapter、业务事件 schema、权限执行、幂等、迁移和恢复演练应随 R1–R4 逐批补齐；客户参数缺失只关闭对应的生产能力。

下一开发批次以 R1 身份、配置、实例基础的具体 API/数据契约为入口；首店交易及客户前台仍按已有参数表和独立验收范围推进。

## 第二批：R1 现有身份与配置接口响应

本批次补齐现有 AdminAuth/AdminAccess/StoreConfig 的 15 个操作，新增 17 个 schema 和 9 个专用响应：登录、MFA 验证、当前会话、密码重设、员工列表/邀请/详情/修改/会话撤销、角色列表/创建/详情/修改、店铺读取/修改。登出仍返回无响应体的 204。

- 登录 202 使用受限挑战 cookie 和挑战 ID；验证成功才产生正式后台会话。强制 MFA 员工未登记时不能用 200 绕过，转登记流程；邀请或停用账号不能构成有效会话。增加 MFA 未登记的 403 分支声明。
- 员工与角色分页返回具体 items；详情有版本，编辑响应声明 ETag、PATCH 带 If-Match。角色列表补齐分页参数。员工不返回密码摘要或 MFA 秘密。
- 店铺响应给出配置版本与市场审核状态；未批准市场不可 enabled，普通配置写入不能提交审核结论。有效期、语言归属、时区合法性等仍须服务端校验。
- 修正 API 文字规格中员工详情读取、店铺配置权限与已冻结权限码表的不一致，分别使用 staff.read 和 store.settings.manage；未改宽 YAML 权限。
- API 文字规格更新到 1.4，新增 cookie、MFA、响应、并发控制及生命周期缺口的说明。新增 DTO/响应均是开发草稿，没有数据库迁移或运行实例。

验证结果：13 项 unittest 全部通过，Markdown 相对链接无失效。OpenAPI 仍为 115 个路径、145 个操作，schema 增至 140 个；通用成功响应由第一批处理后的 128 处/126 个操作减少到 **112 处/111 个操作**。现有 R1 身份/权限/配置操作均不再使用通用成功 DTO。

**尚未闭环：**首次管理员初始化、邀请接受/设密、MFA 登记/确认/恢复/重新绑定、会话列表和市场审核动作还需补完整路由及防滥用约束；M15 运维响应仍有通用占位。客户端生成试编译、业务实现、授权/CSRF/会话执行、数据库和端到端测试尚未进行，当前不能将 R1 标记完成。

## 第三批：后台身份生命周期路由

新增 8 个路径/操作、16 个 schema、5 个具体响应，覆盖 bootstrap 首店主、邀请接受设密、MFA 登记授权/开始/确认、本人会话列表/单会话撤销、员工会话列表。登录 202 联合响应现在区分 verify_mfa 与 enroll_mfa，补齐第二批中强制 MFA 未登记时缺少登记入口的问题。恢复码沿用既有 MFA verify，重新绑定复用登记授权/确认路径。

新流程详见 [身份生命周期契约](ADMIN_IDENTITY_LIFECYCLE.md)，API 规格更新到 1.5，数据模型、模块和测试矩阵同步。首次开通需部署秘密、显式 setup 窗口和数据库唯一性门禁；邀请不能由客户端提权；MFA 待登记能力与普通后台会话分离；因子确认后才轮换并显示一次恢复码；原因子在替换完成前继续有效。双方因子均遗失时只允许受审计的离线恢复，不增加密码重设绕过 MFA 的公开接口。

本批新增 6 项静态测试，合计 **19 项通过**。当前 OpenAPI 为 123 个路径、153 个操作、156 个 schema；通用成功响应仍为 112 处/111 个操作，新操作未增加通用占位。

剩余门槛：有限挑战/邀请有效期等安全数值配置、邀请重发/撤销路由、离线恢复工具、数据库唯一约束和事务、会话/挑战实际授权、并发/重放/限流及通知联调、客户端生成试编译。M01 市场审核与 M15 运维响应亦待补齐。新增契约不代表这些运行行为已有实现；当前没有应用部署或数据迁移。

## 第四批：安全参数、邀请/审核契约与代码骨架

已登记 identity-v1 安全默认值和管理员全部因子遗失的核验/批准/执行流程，补齐邀请读取/重发/撤销、市场审核记录及健康探测的 6 个路径。市场审核使用现有 store.settings.manage 并追加店主/MFA/CSRF 门槛；审核通过不自动启用交易。恢复码响应明确每组 10 个、每个 20 字符。API 文字规格更新到 1.6。

工程新增 pnpm workspace、精确锁文件、TypeScript 6/NestJS 12 API、身份参数与领域守卫、OpenAPI 生成类型、类型化登录客户端、生成漂移检查和 GitHub Actions 文件。生成器使用隔离的 TypeScript 5.9，消除其 peer 要求与应用编译器之间的冲突。首次实际生成时发现并修正了本轮新增响应插入层级错误；最终 OpenAPI 与生成客户端均校验通过。

本地 `pnpm check` 全部通过：**21 项 Python 契约测试 + 10 项 Node 代码/HTTP 测试**，生成文件一致性及 TypeScript 检查通过。HTTP 集成实际监听随机 127.0.0.1 端口，测试后关闭。存活为 200，就绪为 503，未实现的身份路由为 404，不伪造管理员会话。

当前 OpenAPI 为 129 个路径、159 个操作、164 个 schema；通用成功响应仍为 112 处/111 个操作。GitHub Actions 尚未远端运行，当前目录仍未初始化 Git。

**下一步已收敛到实现：**PostgreSQL 18/Prisma 7 数据模型与迁移、条件更新/单次消费、Argon2id/TOTP、持久限流、事务后通知及清理 Worker，再接入身份控制器/后台页面。当前机器没有 Docker/PostgreSQL；本轮没有数据库、实际身份服务、生产部署或恢复工具，R1 不标记完成。安装、运行命令和具体边界见 [R1 工程说明](R1_ENGINEERING_PROGRESS.md)。

## 第五批：PostgreSQL 与首店主身份实装
