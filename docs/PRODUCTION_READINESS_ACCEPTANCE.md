# 生产就绪与端到端验收清单

> 目的：把已确认的交易、权限、隐私和运维要求落实为可演示、可签收的场景。模块文档定义详细功能；本清单定义首店生产上线前必须贯通的检查。每个独立部署实例分别验收。

## 范围基线

- 店铺由商家独立运营；商品、订单、顾客、密钥、媒体和备份按实例隔离。
- 顾客可访客结账；COD 可配置；线上支付仅接入该店已开通且获服务商批准的渠道。
- 首期配送按后台人工履约；支持一个订单分多个包裹/批次发货，不要求自动物流商 API。
- 运营人员可在后台编辑已注册主题区块、选品和排序；不提供任意代码或自由 CSS 页面搭建器。
- 未获得真实服务凭证时可用沙箱/模拟器验收流程；模拟验收不能代替生产支付服务商审批和真实密钥验证。

## 1. 售后、取消和退款（M16）

| 场景 | 验收结果 |
|---|---|
| 未付款线上订单或未收款 COD 取消 | 不生成虚假的付款退款；按规则释放库存/优惠占位；订单与案件状态均保留历史。 |
| 已付款订单全额/部分退款 | 服务端计算已收可退余额；累计退款不得超额；保存原支付、退款金额、币种、原因、外部退款号和操作者。 |
| 渠道退款超时或结果未知 | 进入待查询状态；先查询服务商，不盲目重复发起；安全重试有幂等保护。 |
| 退货收件和质检 | 质检前不恢复可售库存；按可售、损坏/冻结、报废分别产生库存流水。 |
| 通知发送失败 | 案件、退款和库存状态不回滚；通知进入失败/重试队列并可追踪。 |
| 越权或重复售后 | 未授权者不能审批/执行；同一订单行的累计数量和金额不超上限；所有拒绝、审批、执行和变更可审计。 |

详细状态机和权限见 [M16 售后模块](modules/M16_AFTERSALES.md)。

## 2. 付款、收款账户和结算对账（M08）

- 后台可设置已接入渠道的商户凭证引用、沙箱/正式模式、启停和连接状态。密钥保存后仅显示脱敏状态；未配置或未获批准的付款方式不会出现在结账页。
- 客户在服务商后台绑定结算银行账户；EZSTARTCommerce 不保存网银密码或完整银行账号，只展示必要的脱敏账户摘要/服务商连接状态。
- 后台交易台账能从订单追到支付、退款、服务商交易号、币种、金额、状态和事件记录；支付成功与资金结算是不同状态。
- 结算文件导入先预览再确认；支持识别重复文件/重复行，不能重复入账。每行可以匹配内部支付/退款，也可以进入差异队列。
- 差异至少标识：待结算、渠道侧缺失、内部侧缺失、金额不符、币种不符、重复行、未知/需人工确认。手续费与净结算额单独保存，不能改写原订单金额。
- 人工解决差异必须填写理由、操作者和时间；保留导入原始行及处理前后结果。对账数据可按期间筛选/导出并追溯来源。
- 服务商 API 自动对账仅在选定渠道提供能力且单独完成适配后纳入；MVP 不承诺所有支付商统一自动对账。

**关键演示：**一笔成功收款、一笔退款、一笔重复结算文件、一笔金额不符和一笔 COD 已收款记录，均能得到正确匹配/差异状态且不会重复改账。

## 3. 订单履约、地址变更和库存（M07/M09/M12）

- 下单和付款状态分开；服务端原子预留库存，不能因并发购买最后一件产生超卖。
- 未付款订单到预留期限时，先查询支付渠道最终状态：已付款则继续履约；明确未支付/已取消才释放；查询超时或状态未知则保持预留并告警/待处理。
- COD 订单明确显示“待收款”；只有授权人员可登记已收、拒收或退回，签收不自动等于收款。
- 未发货订单仅可由授权角色修改地址；重新校验市场、配送范围和运费。任何差额须按已配置规则处理并留审计，不能静默改应付金额。发货后禁止普通编辑地址，转人工联系承运商并记录结果。
- 一个订单可建立一个或多个包裹；每个包裹记录 SKU/数量、承运商、追踪号、发货时间和操作人。累计发货不得超过订购数量；只扣减已发包裹的数量；订单完成状态须等全部商品履约或按规则关闭。
- 已取消未发货订单按规则释放预留；已发货商品不得因普通取消自动入回库存。退货商品经 M16 收货质检后决定库存处置。
- 运费报价在结账服务端生成并保存订单快照；不可配送地址无法提交订单。发货/付款/取消通知失败不应重复扣库存或改变交易状态。

**关键演示：**最后一件并发下单、付款回调延迟、支付状态未知、COD 取消、分批发货、超量发货阻止、发货后地址修改阻止、退货质检前后库存差异。

## 4. 后台员工账号与权限安全（M00/M15）

- 员工账号唯一，不共用店主账号；支持邀请、密码重设、停用、会话查看/撤销。停用账号后现存会话立即失效。
- 店主和管理员必须启用 MFA，首选验证器 TOTP 并提供一次性恢复码；承担退款、支付配置或敏感导出的高权限账号也按店铺策略启用 MFA。MFA 未完成时不能执行受保护操作。
- 角色权限不仅控制导航菜单；服务端 API 对读、改、删除/归档、导出、退款、付款配置、库存调整、顾客敏感信息访问分别校验。
- 退款审批/执行、收款凭证配置、价格/库存批量更改、导出、权限变更、地址修改等高风险操作要求二次确认；达到配置阈值时要求另一授权员工审批。
- 审计记录操作者、时间、对象、动作、结果、前后状态/必要变更摘要和原因；密码、OTP、密钥、完整卡资料及完整银行资料不得进入日志。

**关键演示：**客服账号尝试访问支付设置/API、停用员工后复用旧会话、未启用 MFA 的店主操作、超限退款审批、审计查看和敏感字段脱敏。

## 5. 隐私、营销同意和市场/商品限制（M01/M10/M15）

- 每个店铺仅能启用经过业主审核并配置的销售市场；市场关闭时，前台目录/商品、购物车、结账及服务端 API 均执行一致限制，不能只隐藏按钮。
- 商品可配置适用市场、年龄/资格要求和提示；如该市场要求年龄/资格验证，前台完成交互后服务端仍须复核验证结果。仅保存实现业务所需的验证结果/时间/规则版本，不默认采集完整出生日期或证件影像。
- 隐私政策、退换/配送政策按店铺语言版本发布并记录版本；交易必要联系和营销订阅分开记录。营销同意含来源、时间、语言和政策/表单版本；退订后营销发送必须停止。
- 提供受权限控制的客户资料查询、导出、删除/匿名化处理工作流；依法/按客户批准需保留的交易资料可与营销资料分开处置，并留下操作审计。
- 每个访问/导出/更正/删除请求先核验身份并进入状态队列；营销退订立即生效。删除或匿名化不能破坏应保留的订单、支付、售后事实；受限字段按批准规则处置，需保留时记录例外依据。顾客导出短时可下载，过期后链接失效。
- 分析事件、应用日志和错误追踪不得包含顾客姓名、电话、邮箱、地址、支付密钥或完整付款资料；测试与生产访问权限隔离。
- 具体商品、市场、年龄要求、文案、保存期限和删除例外由客户提供并审核；产品负责按已批准配置执行，不替客户判断法律合规。

**关键演示：**关闭市场下无法从直接 API 下单；未同意营销的客户不进入营销名单；有效退订后立即停止营销，伪造/过期退订令牌不改变资料且不透露账户是否存在；未核验的资料请求不能导出/删除；已核验导出链接过期；超期请求显示责任人和处理说明；匿名化请求不改写交易事实且留处理审计；分析日志无个人资料。

## 6. 私有部署运维、备份、恢复和升级（M15）

- 每日备份覆盖数据库、商品/内容媒体及必要配置；备份加密、权限隔离、保留周期可配置，任务成功/失败可查询。
- 建议基线为 RPO ≤ 24 小时、RTO ≤ 8 小时；实际值需结合客户云资源、代运维合同和备份策略确认。验收时记录一次隔离环境恢复的实际数据范围和耗时。
- 健康监控覆盖应用/API、数据库、磁盘/对象存储、备份任务、异步任务队列及支付回调处理；失败告警发送到店铺指定的运维联系人，告警不得包含敏感信息。
- 发布升级前展示版本与迁移检查；先备份，在预发布/测试实例验证，再升级生产并做健康检查。升级失败按经验证的恢复/回滚步骤处理，不假设所有数据库迁移都能直接反向执行。
- 恢复/回滚后验证管理员登录、商品图片、订单、支付/售后记录和关键配置；恢复数据不得混入其他客户实例。
- 运维临时访问按授权、最小权限和期限控制；支持访问、备份下载、密钥轮换、恢复和升级均记入审计。

**关键演示：**新实例安装、备份失败告警、数据库与媒体恢复、健康检查、升级预检、升级后验证、恢复/回滚演练及授权运维日志。

## 7. 商品上架与前台陈列配置（M02/M03/M04）

- 商品运营可新增/编辑/导入商品，管理 SKU、价格、库存、图片及三语内容；草稿、预览、发布、下架状态清楚。
- 商家能在后台管理前台主题已注册的内容区块：选择显示/隐藏、排序、区块标题/图片/内容、关联商品/分类/专题。
- 商品区块支持手工选择及拖动排序/置顶；也支持主题已开放的动态规则（如新品、销量、价格）。商品优先级仅影响该陈列区，不覆盖全店商品字段或其他页面的排序。
- 商品与区块配置支持草稿、预览、即时发布、按店铺时区定时发布/撤下、撤回/恢复上一版本；桌面、手机、简体/繁体/英文都可预览。发布后前端读取新版本，缓存刷新行为可观察。定时任务失败时保留旧线上版本并提示管理员。
- 未发布、下架或目标市场不可售商品不得作为可购买商品发布；缺货商品可按配置展示，但不可加购并须显示售罄状态。
- 发布后商品若转为下架、归档或目标市场不可售，前台立即隐藏；手动陈列保留后台配置并提示运营处理，动态陈列跳过该商品并按规则补位。库存变为零时按店铺配置隐藏或显示售罄，始终不能加购。
- 动态排序有展示上限及稳定的并列排序规则，切换动态模式后手动排序控件不可用；商品选择器对草稿/归档/不可售项禁选并显示原因。
- 同一页面的发布时间计划冲突时必须先取消或修改旧计划；定时撤下绑定版本，不能误撤下更新后的线上版本。计划执行失败、过期草稿和版本冲突均有可读状态与恢复操作。
- 发布权限与回滚权限受账号角色控制；回滚前二次确认并创建新的发布版本，历史快照和操作记录保留。所有已启用语言的必填文案齐全后才可原子发布。
- 每个客户的特殊页面/组件需要先由前端主题注册，再开放给后台编辑；后台不允许录入任意脚本、HTML 或 CSS。

## 8. 访客结账与可选会员（M06/M10）

- 访客可从商品浏览到下单完整完成购买；会员 OTP 登录只用于自愿查看会员中心/使用会员权益，不成为购物袋或结账的前置条件。
- 已验证会员仅获得其规则允许的会员价、积分/优惠权益；无 OTP 服务、OTP 限流或会员系统故障不得阻断访客结账。
- 访客订单不能仅按姓名、未验证邮箱/手机号与会员档案自动合并；顾客主动验证后才可按规则关联。
- 结账页面逐项显示商品与变体、数量、折扣、配送费、税费（若启用）、应付总额、币种和政策同意；服务端重新计算且订单快照可复核。

**关键演示：**未登录顾客正常结账、会员主动验证后使用权益、OTP 故障仍可访客下单、同名访客订单不错误并入会员、价格/库存变化后服务端重新报价、重复提交返回原订单。

## 9. 优惠额度与通知事件一致性（M11/M13）

- 并发下单争用最后一张/最后一个额度时最多一个有效预占；订单取消、支付失败/明确超时和退款按商家配置处理额度，并且重复回调不会重复释放或核销。
- 线上支付状态未知时，优惠额度和库存按配置进入待处理/继续预占，不因前端关闭支付页而错误释放。
- 交易事件仅在业务提交后产生通知；重复队列消息/webhook 不重复发送。人工重发只重发通知，不重复执行订单、付款或退款动作，并记录操作者/原因。
- 营销发券消息受营销同意状态限制；交易通知与优惠营销消息可分别配置模板、语言和渠道。

**关键演示：**并发优惠额度预占、订单取消释放、退款返券策略、重复支付回调、通知发送失败后安全重试、营销退订后仍可发送必要交易通知但不能发送促销消息。

## 10. 数据交接与实例停用（M15）

- 客户可在受控权限下导出其业务数据和媒体清单；导出不含支付密钥、OTP、会话凭证或其他秘密，并带实例/生成时间/格式/校验信息。
- 停用实例前确认目标商家与实例、数据交付/留存责任和批准的删除计划；主数据删除与加密备份轮转分别记录，说明备份预计到期清除时间。
- 迁移/恢复/停用不能意外导出或混入其他实例数据；恢复后核对订单、客户、媒体、配置数量和清单校验。

**关键演示：**生成并核对业务导出、验证无密钥/OTP、另一个实例数据不可见、按保留策略执行停用并查看审计和备份轮转状态。

## 11. 商品资料、批量导入与多语言完整性（M03/M05/M12）

- 商品发布校验简体中文、繁体中文、英文所启用语言的名称、SKU/规格及商品页必需内容；缺译时明确阻止发布或按页面语言隐藏并告警，不静默错语种回退。
- 商品导入预览能列出新增/更新/跳过/错误和字段差异；重复 SKU 或冲突匹配不得自动选择目标商品；执行前明确选“仅应用有效行”或“整批原子”，无效行不得写入。
- 导入中断后可查看逐行状态并安全续跑；文件未包含商品不得被当作删除指令；价格/库存变更有清晰预览与授权。
- 库存盘点批量导入产生库存调整流水，不覆盖或绕过预留；图片 URL 导入拒绝内网/本机/元数据端点及不安全文件。
- 订单保存下单时的商品名称、规格、语言和价格快照，后续翻译/商品变更不篡改历史订单。

**关键演示：**正确商品批量新增、错误行部分应用与整批阻止、重复 SKU 拒绝、任务中断后重试、库存调整账目核对、三语缺译阻止发布、历史订单内容保持不变。

## 12. SEO 与发布 URL 管理（M02/M04）

- 已发布且允许索引的内容/商品页面有正确的语言版标题、描述、canonical、alternate/hreflang 与 sitemap 条目；草稿、预览、管理页、购物袋和结账页不得进入公开索引。
- 客户域名/语言路径对应正确；更改已发布 slug 创建 301 重定向；路径冲突及循环会被阻止；已撤下页面从 sitemap 移除且返回约定的未发布状态。
- 核心落地页的 SEO 元数据可在初始 HTML 或搜索引擎可读取的输出中获取；robots 与 sitemap 不会把测试/预览环境暴露为生产索引。

**关键演示：**三语商品页面索引信息核对、预览页 noindex、slug 变更后的旧 URL 跳转、循环重定向阻断、取消发布后 sitemap 清理。

## 上线责任与冻结项

平台级流程可先开发并用沙箱/模拟数据验收；生产验收前客户须提供/确认：目标市场与批准规则、支付服务商及商户账户/生产凭证、结算文件格式/币种、COD 收款规则、配送区域/费率、售后政策、隐私/营销文案和数据保留策略、运维联系人及备份/SLA 目标。缺少这些输入时对应生产开关保持关闭，不以模拟成功代替真实批准。
