# EZSTARTCommerce 首店输入与决策记录

平台基线和默认交付模式已在本文件末尾登记；下列事项用于补齐首店参数、合同边界和最终估算。后台售后、交易对账、员工权限安全、隐私请求和私有部署恢复均纳入产品基线；具体经营参数、市场规则和合同 SLA 仍需客户逐店确认。模板基础模块可按 [研发待办](PRODUCT_BACKLOG.md) 分批开工；生产交易和客户专属前台须满足对应冻结门槛。

## 首店交易开通前必须确认（模板研发可并行）

### 1. 谁负责运行每个私有实例？

已确认产品需支持多个商家分别私有部署。默认基线为客户持有云账号/域名，交付方获授权完成安装、初始化和交接；持续代托管是单独服务，不纳入模板核心固定报价。仍需在客户合同确认具体主机区域、备份目标和支持 SLA。

- 已确认默认商家云账号内独立部署：商家持有云资源/域名/服务账户，交付方授权安装、配置并交接。
- 可选代托管独立实例：仍每客户隔离，需另签托管、监控、备份、SLA 和退出迁移费用。
- 若客户要求同时提供自托管和代托管，按独立服务包评估兼容矩阵、监控与故障支持成本。
- 一位商家默认一站一实例；同一商家多站点分别部署。

### 2. 首发市场与合规责任

- 首期国家/地区、允许商品及配送地区是什么？
- 谁签署商品准入、网站展示/营销、年龄/资格验证和支付/配送合规审查？
- 未审市场保持关闭；已批准的禁售/资格规则需填写到上线参数表。

### 3. 顾客端与会员边界

模板规则已固定为：访客可无账号购物结账；会员自愿通过邮箱 OTP 登录，无密码；经验证后才创建或关联会员。客户填写邮箱/短信渠道、会员等级、积分、退款扣回和权益参数；短信须提供获批服务商。OTP 安全数值见 `DEVELOPMENT_SPEC.md`。

### 4. 支付服务

- 具体要信用卡、银行转账、电子钱包或其他哪些方式？
- 是否已有支付服务商及商户账户？
- 服务商分别支持哪些退款操作、结算文件/API 和结算币种？退款记录及基础结算对账属于模板基线，具体连接能力以客户选定服务商为准。
- 服务商是否接受拟经营的商品类别和目标市场？

### 5. 配送规则

- 模板首期支持配送区域、按地区固定费用、商品优惠后金额门槛、免运和人工分包裹履约；客户填写区域、费率、时效和 COD 适用范围。
- 重量/件数费率、承运商 API、运单打印和轨迹查询需要单独确认范围。

### 6. 语言与商品资料

模板支持简体中文、繁体中文、英文；启用语言的必填内容缺失时阻止发布，不静默回退。客户指定翻译/审校人、商品资料表格和图片提供人。

### 基础售后与退款

后台售后案件纳入 P0 基线：订单取消、全额/部分退款、退货/换货跟踪、收货质检、库存处置和审计；前台自助申请可按客户范围延后。客户仍需确认退货时限/商品资格、退款审批限额、COD 已收款退款渠道和优惠券返还规则。支付服务商退款 API 能力以商户账户和服务商规则为准；人工退款也须记录并可审计。
## 客户与合同参数（不改变模板默认规则）

### 7. 会员识别和数据字段

会员识别基线已固定为邮箱 OTP；访客订单不会按姓名或未验证联系方式自动合并。客户提供会员告知/同意文字、等级和积分规则；短信 OTP 若需要则单独配置服务商。

### 8. 优惠券

模板已包括批次发券、商品/分类、最低消费、使用次数和会员资格限制；默认每单一个优惠码，不叠加其他优惠码。客户填写使用限制与返券规则；若要求叠券/复杂促销，按变更单评估。

### 9. 通知渠道

订单通知需要邮件、短信还是 WhatsApp？由谁提供账号和模板审批？通知失败是否需要重试和人工告警？

### 10. 报表

订单额、实收、退款、净销售额、时区及导出字段口径已在 M14 冻结；客户提供基础币种、店铺时区及成本数据（无成本数据时不显示利润）。

### 11. 运营与运维

- 预计商品量、订单量和管理员人数。
- 主机部署地区、备份周期、恢复时间目标。
- 店铺实例由谁升级？升级窗口和支持响应时间如何约定？

### 12. 数据统计范围

- 首期包含站内匿名访问与转化漏斗；外部分析平台为可选变更。
- 客户/顾问确认事件告知/同意、保留时长和各市场策略；陈列分析按 M14 已冻结规则归因。
- 默认单店单币种、不换汇；多币种另行变更。

### 13. 交易、税务与售后范围

- 默认税费关闭，模板首期不含自动税务引擎/电子发票；如需启用，客户须提供已批准的地区计算规则和发票范围。
- 客户填写售后资格/时限、退款审批限额、COD 已收款退款、优惠券返还和退货库存处置规则；渠道退款 API 能力按服务商确认。
- 首期配送规则和手工履约已固定；物流 API/运单打印为单独范围。
- 安全订单查询为 P1；若客户需要，确认身份验证方式及通知费用。

### 14. 模板商业交付与版本支持

- 按商家、站点、部署实例还是一次性源码授权收费？
- 是否提供安装、域名/SSL、迁移、托管、备份和技术支持服务？
- 模板核心版本多久发布一次，旧版本支持多久，安全更新如何通知？
- 谁拥有商品、订单和内容数据；停止服务后如何导出、迁移或删除数据？

### 15. 客户专属前台交付约定

前台按客户单独设计开发已确认；还需约定页面清单的变更流程、源码/IP 归属、客户自改权限和定制前台的版本升级支持。

### 16. SEO 与个人资料请求

平台基线包含 SEO/索引/重定向管理，以及经身份核验的个人资料请求处理队列。每家客户仍需冻结公开索引范围、域名和旧链接映射、隐私联系人、资料保留期限、请求处理时限、身份核验方法和可保留的交易例外，详见 `CLIENT_LAUNCH_INPUTS.md`。

## 已登记的产品决策

已确认范围处理详见 REQUIREMENT_RESOLUTION.md；跨模块研发规则详见 DEVELOPMENT_SPEC.md；各商家需填写 CLIENT_LAUNCH_INPUTS.md。此清单未填的实例参数阻断对应的真实交易/上线功能，不阻断独立的模板基础开发。

- 项目名称：EZSTARTCommerce。
- 同一电商核心/管理后台可交付给多个商家分别私有部署；每家拥有独立站点、数据和密钥，前台按客户业务单独设计开发，不共享商家数据。
- 每家客户的前台页面与购物交互可以不同，按客户项目私有定制；模板参考前台不代表所有客户共用同一套页面。
- 本项目不做共享多租户 SaaS 控制台；默认一位商家一个独立站实例。
- 产品定位：通用电商独立站模板，不以烟草品类限定产品名称或核心模型。
- 烟草是首个行业场景/配置包。
- 前台支持简体中文、繁体中文和英文。
- 访客结账无需注册/登录；会员中心使用自愿邮箱 OTP 登录，不设置密码。
- 后台需支持商品自行配置、优惠券、会员/客户管理、库存预警、报表及商品导入。
- 支持后台配置货到付款，并规划信用卡或其他线上支付。
- 新站采用新设计。
- 原站仅作参考；无旧站后台、代码或数据，不承诺迁移。
